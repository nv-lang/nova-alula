# Модель профилей взаимодействия

Статус: проектная модель и исполняемые проверки совместимости; не новая норма языка и не описание уже реализованного общего runtime. Машина по-прежнему объявляет существующий `kind`; таблица ниже задаёт смысловое отображение для следующего этапа реализации. Ключевой артефакт и проверяемая матрица — [`../spec/alula-interaction-profiles.json`](../spec/alula-interaction-profiles.json), проверки — [`../tools/check-interaction-profiles.py`](../tools/check-interaction-profiles.py).

## Общий вид

Сторона — роль, типизированный контракт и профиль взаимодействия; хозяин связывает её с provider и реальными полномочиями. Профиль задаёт lifecycle и допустимые binding/policy, а не произвольный набор capabilities. Это общая модель, не универсальная шина: только `call` естественно использует request/result; `decision`, `managed-call` и `input-only` имеют самостоятельные lifecycle.

| Существующий kind | Профиль | Контракт | Binding, права и policy | Что уже исполняется |
|---|---|---|---|---|
| `agent` | `call` | Типизированные request/result; progress только если объявлен | Provider роли выбирает хозяин; может вызвать только разрешённое хозяином; policy не расширяет permissions | Runtime формирует request; старые retry/renewal и permissions не меняются |
| `human` | `decision` | Долговечные opening, subject, admissibility и versioned choice | Human principal; UI одного principal разделяют opening; может подать candidate, но endpoint не даёт права на effect; приоритет человека до commit | Существуют человеческие gate-сигналы, но новый durable decision lifecycle не реализован |
| `enhanced` | `decision` | Тот же типизированный decision contract | Candidate допускается только по прежнему enhanced-разрешению; это не «более сильный provider» | Существуют ограничения gate; нового арбитража нет |
| `gatekeeper` | `decision` | Долговечный opening и выбор по версии | Исполнитель разрешается именованной настройкой; имя настройки само не удостоверяет identity и не выдаёт полномочия | Существуют kind и проверка настройки; decision arbitration не реализован |
| `machine` | `managed-call` | Типизированные child input/result и стабильная child identity | Хозяин разрешает совместимую вложенную машину; родителю доступны только объявленные child controls, не эффекты host | Nested runner сохраняет identity, pause/recovery и результат; обычный `call` этого не обещает |
| `free_input` | `input-only` | Объявленный сигнал и типизированные поля, без request/result | Human input только в допустимом активном состоянии; только объявленные сигналы | Runtime принимает signal без запроса; вне активного допустимого состояния ввод не должен откладываться |
| `service` (локально принятый проект) | узкий `call` | Обязательные typed result и counter | Хозяин даёт provider; разрешён только объявленный узкий вызов; нет profile override, signals, progress/streaming/subscriptions | В свежем `origin/main` отсутствует; локальный проект не переносится в runtime этим этапом |

Идентификатор принятого локального проекта `ServiceParty`: `e7769b0599bd6bef85cf070be6ca2e043af123f9`. Он указан только как происхождение модели; его код не переносился. Проверенная база этого этапа — `4224563` (включая текстовое уточнение event protocol задачи 012; её файлы не менялись).

`profile` столбец старой таблицы, где он означает профиль модели/усилия, не является профилем взаимодействия и не переинтерпретируется.

Все профили зависят от единого общего контракта для типизированных значений, кодирования и канонизации запросов, ответов, сигналов и внешних функций. Планируемый первоисточник: `../spec/alula-value-codec.md`; специализированный протокол envelope событий и receipts: `../spec/alula-event-protocol.md`. На момент этой фиксации оба файла ещё не опубликованы: пути — плановые, не действующие ссылки; до интеграции надо сверить их с автором общего контракта. Эта зависимость не создаёт вторую копию codec и не требует конкретного JSON, сети или durable inbox у каждого binding. Event envelope и receipts сохраняют отдельный lifecycle; общий codec его не заменяет. Для профилей и codec отдельные версии не вводятся. Проектная модель целится в Алулу `0.29.0-alpha.1`; это не версия текущего runtime и не изменение package/tag/release.

## Инварианты lifecycle

- `call`: корреляция вызова не даёт полномочий. Progress не является terminal reply. Withdrawal ожидания не отменяет execution; cancel не доказывает rollback. Потерянный ответ после внешнего эффекта не даёт права повторить эффект без доказанной идемпотентности.
- `decision`: opening долговечен и включает subject, admissibility, версии и конкурирующие candidates. Выбор проверяется вместе с версией при атомарном commit. Человеческий приоритет арбитрируется до commit. После `applied/committed` замена запрещена; `superseded` возможно лишь для принятого, но ещё не применённого кандидата. Два UI одного principal — не два opening.
- `managed-call`: перезапуск родителя продолжает тот же child; pause child не становится timeout. Идентичность ребёнка и готовый результат сохраняются.
- `input-only`: сообщение допустимо только в явно разрешённом активном состоянии; rejection не означает отложенную доставку и не создаёт будущий input.
- Withdrawal, execution cancel и domain compensation — разные действия. Receipt подтверждает сообщение, не завершение операции. Управление и прогресс доступны только по соответствующему контракту.

Проверка деклараций/типов/совместимости относится к компилятору; lifecycle, correlation, pause и arbitration — к движку; реальные provider, полномочия, I/O, storage и эффекты — к хозяину. На текущем этапе исполняемая модель проверяет согласованность отображения и контрпримеры, а не заявляет новую runtime-функциональность.

Запуск: `python tools/check-interaction-profiles.py`. Reverse-probe проверяет, что намеренно испорченные варианты становятся красными: неверное отображение, отдельный opening на UI, потеря child identity, отложенный input, смешение cancel/compensation, расширение ServiceParty и замена committed decision.
