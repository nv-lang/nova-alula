# Задача 032: слова типов дерева — слова Новы `str`/`f64` (формат 0.32)

- Тип: ломающая правка провода `machine/2` пакета `nova-alula`.
- Статус: **реализуется**. Решение владельца 2026-11-19 (чат методики, после вопроса «выглядит как-то
  неконсистентно»: файл пишет `str`/`f64`, дерево — `text`/`float`): привести к консистентному
  состоянию, малый путь.
- Причина: дерево говорило историческими словами ядра (`text`, `float`), файл — словами Новы
  (`строка`/`str`, `вещественное`/`f64`); `int` и `bool` совпадали случайно, пара `str→text` выпадала.

## Что меняется

| Место | Было | Стало |
|---|---|---|
| Тип строки в дереве `machine/2` | `text` | `str` |
| Тип вещественного в дереве | `float` | `f64` |
| `int`, `bool`, `id`, `map`, `full_map` | — | без изменений |
| Текст файлов | `строка`/`str`, `вещественное`/`f64` | без изменений |
| Узлы и ключи провода | — | без изменений |
| Версия | 0.31 | 0.32 (файл/дерево 0.31 отвергается с подсказкой `tools/migrate-alula-232.py`) |

Шов 2.25: деревья шва читают прежние слова `text`/`float` (и оба словаря понимаются парсером
спецификации); рендер в файл для обоих — `str`/`f64`.

13 сигнатур инструментов и реестр — без изменений (сверка с реестром нормализует `str≡text`,
`f64≡float`).

## Объём

- Эмиттеры слов типов: `machine_text` (parse/elab/callee/library), `machine` (value/types),
  контрактные данные ядра (`[]str`), сообщения проверки.
- Читатели: `machine/spec.nv` принимает `str`/`f64` и прежние `text`/`float`; `base_type_names`.
- Рендер: оба словаря — в слова файла (`str`/`f64`).
- Версия 0.32 (язык/дерево/проверка/команды/программа/`nova.toml`) и цепочка подсказок 232 → 231 → 230.
- Мигратор `tools/migrate-alula-232.py`: шапка, хеши подключений, деревья `alula compile`;
  `--dry-run`, `--selftest`, идемпотентность.
- Примеры, библиотеки, векторы manifest, пробы и документы (спека 2.22/6/1а, AL-160, история 50, README).

Вне объёма: правки Oracle, схемы и ключи провода, формат текста, 13 сигнатур, релиз/тег (по слову владельца).

## Проверки (DoD)

1. `nova test src --jobs 4 --timeout 900` — без FAIL; `alula test examples` — 107/107; стражи — FAIL 0;
   exe печатает `alula 0.32.0 (Алула 0.32)`.
2. Деревья примеров пересобраны, типы в них — `str`/`f64`; старые деревья 0.31 отвергаются с подсказкой 232.
3. Сверка объявленного инструмента с реестром нормализует `str≡text`, `f64≡float` (AL-155 пробы зелёные).
4. Мигратор 232 `--selftest` зелёный, идемпотентен; хеши библиотек совпадают с пинами.
5. Шов 2.25: 2.25-тексты рендерятся в прежней форме (паритет хешей).
6. Саботаж-проба: дерево с `alula_version` 0.31 — проверка краснеет с подсказкой `migrate-alula-232.py`; слово `text` в дереве 0.32 читается (терпимость шва), но генератор пишет `str`.
