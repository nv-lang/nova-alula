# Задача 118/П-2а: точки монтирования (несколько корней) в хостах пакета

- Тип: отдельный ребёнок эпика «Тонкий хозяин в пакете» (задача 118 методики); сестра П-2, не его часть.
- Статус: **карточка; дизайн одобрен владельцем 2026-11-19; ждёт согласования с методикой и слова владельца
  на реализацию**. Слова владельца 2026-11-19: «Принимаю 118 как есть, заведи карточку на мультирут (П-2а)
  и согласуй её с методикой».
- Причина: корни проекта бывают независимыми (разные диски, шары, домашняя папка). Сегодня хост держит одну
  папку — `HostTree { root }`, `resolve` лексически внутри неё ([thin_host.nv:52](../../src/thin_host/thin_host.nv#L52)).
  Сценарий с независимыми корнями вынужден либо складывать их подпапками одного корня (владелец отверг:
  «руты это полностью независимые пути могут быть»), либо поднимать несколько хостов с раздельными
  журналами/правами/реестрами процессов (годится только для разных миров — см. «Отвергнутые варианты»).

## Цель

Несколько независимых точек монтирования (имя → абсолютный путь) у хостов пакета при неизменности сегодняшней
семантики для одной точки.

## Решения (предлагаемые)

1. **Аддитивность.** `new_tree(root)`, `new_scripted_host(root, producer)`, `new_battle_host(root, producer)`
   остаются и означают одну основную точку. Новые конструкторы принимают таблицу точек. Формат языка,
   сигнатуры 13 инструментов, образцы и fingerprints не меняются.
2. **Адресация.** При нескольких точках первый сегмент пути — имя точки (`"src/notes/a.txt"`); голый путь
   разрешается в основную точку (если она объявлена), иначе — сбой шага.
3. **Границы.** Абсолютный путь — отказ; `..` не выходит из своей точки (переход в чужую точку через `..` —
   отказ); неизвестное имя точки — сбой шага (`StepFailure`); имя точки — непустое, без `/`, `\`, `:`, `..`.
4. **Права и журнал.** Один хост — один outbox и свод прав, как сейчас; точки — пространство имён путей, не
   отдельные права. Права на точку — отдельный вопрос, в объём не входят.
5. **Процессы боевого хоста.** `dir` и `log` резолвятся теми же правилами и могут быть в разных точках;
   внутри — абсолютные пути для `Command`.
6. `parse_agent`, `sha256` — без изменений.

## Вопросы методике (согласование)

- Принцип аддитивных точек и текст host-spec 111: «каждый путь разрешается внутри дерева хозяина» →
  «дерева или леса точек; при одной точке — прежняя семантика».
- Грамматика адресации: первый сегмент как имя точки; голый путь — в основную точку.
- Куда отнести: уточнение REQ-4/REQ-5 или новый REQ эпика 118; и ребёнок эпика с их номером.
- Паритет: одномонтовые сценарии дают прежние исходы байт-в-байт; 595 машин методики, стражи и
  эквивалентность (AC-4) не меняются.

## Проверки (DoD)

1. **Сборка/набор:** `nova build src/alula.nv -o target/alula.exe`; `nova test src --jobs 4 --timeout 600` —
   без FAIL; `examples` 107/107; стражи `ок, FAIL 0`; профили 37/37.
2. **Позитивы:** два-три независимых корня (разные папки, по возможности разные диски); запись/чтение/
   перемещение/удаление/замок внутри своих точек; `start_process` с `dir` и `log` в разных точках,
   `process_running`/`stop_process`.
3. **Негативы:** абсолютный путь; `..` за границу точки; `..`-переход между точками; неизвестное имя точки;
   пустое/невалидное имя; голый путь без основной точки (если так решим).
4. **Одномонтовый паритет:** сегодняшние пробы `thin_host`/`battle_host` проходят без правок ожиданий;
   fingerprints образцов не меняются; 595 машин методики — зелёные (прогон методики).
5. **Саботаж-проба:** разрешить `..` через границу точки — многоточечный негатив краснеет, откат чистый.

## Отвергнутые варианты

- **Подпапки одного корня** — владелец отверг: корни полностью независимы.
- **Несколько хостов + роутер** — `ToolHost` получает только `(name, args)`: ни партии, ни корня, ни прогона;
  имя инструмента в прогоне одно (`Host @note_twice`), а каждый хост несёт свой outbox, права и реестр
  процессов — один боевой прогон теряет единый журнал. Остаётся приёмом для разных миров (разные
  производители/права/прогоны), не решением «несколько корней в одном прогоне».
