# Задача 118/П-2а: точки монтирования (несколько корней) в хостах пакета

- Тип: ребёнок эпика «Тонкий хозяин в пакете» (задача 118 методики), новый REQ-9/AC-8; сестра П-2, не его часть.
- Статус: **согласована с методикой 2026-11-19** (принцип принят; грамматика исправлена — при N≥2 имя точки
  обязательно у каждого пути); ждёт слова владельца на реализацию. Карточка методики — 122 (заводится методикой
  по слову владельца).
- Слова владельца 2026-11-19: «Принимаю 118 как есть, заведи карточку на мультирут (П-2а) и согласуй её
  с методикой».
- Причина: корни проекта бывают независимыми (разные диски, шары, домашняя папка). Сегодня хост держит одну
  папку — `HostTree { root }`, `resolve` лексически внутри неё ([thin_host.nv:52](../../src/thin_host/thin_host.nv#L52)).
  Сценарий с независимыми корнями вынужден либо складывать их подпапками одного корня (владелец отверг:
  «руты это полностью независимые пути могут быть»), либо поднимать несколько хостов с раздельными
  журналами/правами/реестрами процессов (годится только для разных миров — см. «Отвергнутые варианты»).

## Цель

Несколько независимых точек монтирования (имя → абсолютный путь) у хостов пакета при неизменности сегодняшней
семантики для одной точки.

## Решения (согласованы с методикой)

1. **Аддитивность.** `new_tree(root)`, `new_scripted_host(root, producer)`, `new_battle_host(root, producer)`
   остаются и означают одну основную точку. Новые конструкторы принимают таблицу точек. Язык, спецификация,
   реестр и 13 сигнатур инструментов не меняются: это host API, а не версия языка. Образцы и fingerprints —
   байт-в-байт прежние.
2. **Грамматика.**
   - **N=1** — ровно прежняя грамматика; префиксы точек не допускаются: первый сегмент, совпавший с именем
     точки, — обычная папка. Семантика и тексты ошибок — байт-в-байт (проба эквивалентности как AC-4).
   - **N≥2** — имя точки обязательно у каждого пути, включая основную (у неё объявленное фиксированное имя,
     напр. `root`). Голый путь (первый сегмент — не имя точки) — `StepFailure` со списком точек. Теневой
     маршрутизации нет.
   - `..` не выходит из своей точки; `..` в корне точки — `StepFailure`.
   - Абсолютные и особые формы — `StepFailure`: `/`, `\`, буква диска (`C:foo`, `C:/x`), `\\?\`, UNC
     (`\\server\share`), ADS (`a:b`), NUL-байт.
   - Разделитель — `/`; `\` не нормализуется, а отказывается. `.`, пустые сегменты и повторы `//`
     нормализуются.
   - Имена точек: непустые, без `/`, `\`, `:`, `.`, `..`; сравнение точное, регистрозависимое.
   - Symlink/junction: после разрешения проверяется `canonicalize` (std.fs, 0.1.6) — уход за точку —
     `StepFailure`; для ещё не созданной цели проверяется ближайший существующий предок. Это распространяется
     и на N=1: сегодняшнее лексическое правило «symlink не разрешается» закрывается; в сценариях AC-4 symlink
     не используется, паритет байт-в-байт сохраняется.
3. **Путевые аргументы (сверено по реестру).** read/write/delete/exists/list — `path`; move — `from`+`to`;
   start_process — `dir`+`log_path`; run_command — `dir`; acquire_lock — `path`. Перемещение между точками —
   `StepFailure` в П-2а (копирование+удаление — отдельное решение). Строка `command` непрозрачна:
   конфайнмент касается только объявленных путевых аргументов (записано явно).
4. **Идентичность и снапшот.** Dedup/replay acting-интентов — по каноническому абсолютному пути
   (корень точки + относительный), иначе одинаковые относительные пути двух точек дают коллизию
   dedup/replay. Таблица точек — часть host identity/снапшота; replay на другой конфигурации не
   поддерживается. Замки и процессы mount-qualified везде, где несут пути.
5. **Права и журнал.** Один хост — один outbox и свод прав, как сейчас; точки — пространство имён путей,
   не отдельные права. Права на точку — отдельный вопрос, в объём не входят.
6. **Отсутствующий корень.** В многомонтовых конструкторах: отсутствующий или несоздаваемый корень —
   ошибка запуска (боевой хост создаёт корни, как сегодня создаёт свой единственный); исчезнувший во время
   прогона корень — `StepFailure`. Легаси N=1 — без новых проверок на конструировании.
7. `parse_agent`, `sha256` — без изменений.

## Проверки (DoD)

1. **Сборка/набор:** `nova build src/alula.nv -o target/alula.exe`; `nova test src --jobs 4 --timeout 600` —
   без FAIL; `examples` 107/107; стражи `ок, FAIL 0`; профили 37/37.
2. **Позитивы (две точки):** чтение/запись/список/замок внутри своих корней; `start_process` с `dir` и
   `log_path` в разных точках; `process_running`/`stop_process`.
3. **Негативы:** абсолютный путь; `..`; `a/../../x`; неизвестная точка; пустое имя точки; имя с `/`, `\`,
   `:`, `..`; cross-mount move; symlink escape; `C:foo`; `\\?\`; `a:b`; голый путь в multi-root.
4. **Одномонтовый паритет:** байт-в-байт, включая тексты ошибок (проба эквивалентности как AC-4);
   fingerprints образцов не меняются; 595 машин методики — зелёные (прогон методики).
5. **Идентичность:** два монтирования с одинаковым относительным путём дают разные acting-идентичности
   (dedup не сталкивается).
6. **Саботаж-проба:** разрешить `..` через границу точки — многоточечный негатив краснеет, откат чистый.

## Отвергнутые варианты

- **Подпапки одного корня** — владелец отверг: корни полностью независимы.
- **Несколько хостов + роутер** — `ToolHost` получает только `(name, args)`: ни партии, ни корня, ни прогона;
  имя инструмента в прогоне одно (`Host @note_twice`), а каждый хост несёт свой outbox, права и реестр
  процессов — один боевой прогон теряет единый журнал. Остаётся приёмом для разных миров (разные
  производители/права/прогоны).

## Приёмка и публикация

## Оценка и риски

0.5–1 день пакета плюс согласование. Риски: Windows-формы путей и junction (проба `canonicalize` на 0.1.6 до
реализации); каноническая идентичность интентов в outbox; одномонтовый паритет (гарантирован конструкцией:
N=1 не проходит через новую грамматику, кроме symlink-проверки).
