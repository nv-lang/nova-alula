# Задача 129a: generic-ресивер боксит типизированные аргументы в `void*` (сторона пакета)

- Тип: задача пакета `nova-alula` по дефекту наблюдательного класса «решение 129a», отнесённому владельцем
  к стороне ПАКЕТА (не Oracle).
- Статус: **принята методикой 2026-11-20** (пин вершины `149c435` ветки `129a-audit`; публикуемая линия — `7411aba` ветки `129a-card`, дерево идентично принятому); публикация — по слову владельца. Код пакета не менялся (обходы оставлены с доказательством).
- Маршрут: из Oracle 0.1.7 (замороженный код `0f0b1bd6e`), решение владельца 2026-11-19 «На сторону
  пакета» (передано сессией методики; журнал методики 118, коммит `71a7570`).
- Следствие для Oracle: тег-блокер 0.1.7 по этой строке снят; блокеры 1994/1913 остаются, тег Oracle
  0.1.7 не ставится. Репозиторий `nv-lang/nova` этой задачей не трогается.

## Дефект и факты

Симптом (survey `spikes/env/README.md`, пункт 129, переоткрыт 2026-11-15): в слитом юните пакета прямой
вызов метода типа другого модуля **с конструктором в аргументе** выдаёт аргументы в C как `void*` — C не
собирается; тот же резолвер при равной арности может выбрать **не тот** метод (в пробе:
`h.submit_json(envelope)` резолвится в `describe_json`).

- Минимальный носитель на Nova — **зелёный**; на реальном коде Алулы — **воспроизводит** (слово владельца
  2026-11-19). Поэтому строка не ждёт фикса Oracle: решение о форме кода — на стороне пакета.
- Свидетельство: проба `host_contract` (результат F); форма-триггер — `@engine.submit_event(Incoming.incoming(...), …)`.
- Текущие обходы (класс 129a) в пакете:
  - `src/host_contract/contract.nv:174` — `ORACLE-WORKAROUND(129)`: событие в типизированную локальную,
    метод движка — через свободную функцию `submit_admission` (`src/engine/engine.nv`);
  - `src/host_contract/contract.nv:251`, `src/host_contract/contract_test.nv:29` — те же формы в текстах;
  - `src/engine/types.nv:87-95` — аксессор `Transition[S] @state_value()`: прямой разбор полезной нагрузки
    чужого перечисления сломал C слитого юнита на 0.1.4; живые вызовы снаружи — `thin_host_test.nv:371/399`;
  - `src/engine/engine.nv:611-618` — аксессоры `@open_count()` / `@first_open_id()`: итерация `Vec` открытых
    запросов через модули сломала C на 0.1.4; их читает `describe_json` (`contract.nv:249-253`);
  - `src/machine_run/state.nv:15-20` — пробы `AlulaState @name_probe()` / `@datum_json_probe(name)` для чужих
    модулей (прямое чтение поля связанной в `match` нагрузки — тот же класс 0.1.4);
  - `src/machine_typed/*`, `src/machine_manifest/manifest.nv:5` — структурный обход: типизированный контракт
    значений в отдельном модуле (один модуль — один юнит).

## Что решаем (объём — согласовать до кода)

1. Инвентаризация всех обходов класса 129a в пакете: место, форма вызова, причина, действует ли она на 0.1.6.
2. Решение по каждому: снять обход (если форма больше не ломает сборку — доказать красной пробой на
   0.1.6) либо оставить и зафиксировать правило формы вызова пакета:
   - операции над дескриптором — свободными функциями (`handle`-операции не методами);
   - конструктор в аргументе вызова метода — только через типизированную локальную.
3. Если правило остаётся — держать его пробой (минимальный носитель-красный на 0.1.6) и/или стражем,
   чтобы новый код не заводил запрещённую форму молча.
4. Поведение и публичные API пакета не меняются; формат языка, реестр и 13 сигнатур — вне объёма.

Вне объёма: правки `nv-lang/nova` (Oracle), формат/версия языка, машины и фикстуры методики, релиз и теги.

**Правило пакета (до фикса Oracle):** (1) операции над дескриптором — свободными функциями в модуле-владельце типа;
(2) результат конструктора в аргумент метода чужого типа прямо не передаётся — сначала в типизированную локальную;
(3) запретную форму не вводить. После выхода Oracle 0.1.7 с фиксом 129a обходы снимаются отдельной карточкой.

**Красная проба (0.1.6, 2026-11-20):** в `submit` временно заменено на
`admit = h.engine.submit_event(Incoming.incoming(ek, name, request, input), producer, effect_id, fingerprint)`:
`nova test src/host_contract` — красно: `CC-FAIL ... passing 'void *' to parameter of incompatible type 'nova_str'`
(`contract.c:170057`); откат обхода — зелёный. **Честная оговорка:** `src/alula.nv` НЕ импортирует
`alula.host_contract` (никто вне папки его не импортирует), поэтому `nova build src/alula.nv` этот модуль не
компилирует — зелёная сборка программы здесь ничего не доказывает и «юнит-зависимость» ею не подтверждается.
Наблюдаемое: та же форма компилируется в маленьком A-юните (`spikes/env/repro_129a`, зелёный, 8991a32) и падает
в тестовом юните модуля (B; минимальный состав описан ниже). Кэш сборки правкой импорта не инвалидируется:
для пробы — `NOVA_CACHE=0` или сброс `target/.nova-cache`.

**Минимальный CU (2026-11-20, бисекция по чартеру Оракула; отдельная линия, файлы не публикуются):** найден и
подтверждён A/B. Состав: модуль `alula.host_contract` из двух файлов — `InstanceHandle` с единственным полем
`engine Engine[AlulaMachine, AlulaState]` и `probe` с прямой формой
`h.engine.submit_event(Incoming.incoming(ek, name, request, input), "p", "id", "fp")`; тест — тривиальный; импорты
только `alula.machine_run` и `alula.engine`. A/B: обход (локальная + свободная `submit_admission`) — PASS; прямая
форма — CC-FAIL `passing 'void *' to parameter of incompatible type 'nova_str'` (contract.c:107601:141). Флаги:
`NOVA_MULTI_TU=0` — тот же `void*`; `NOVA_MULTI_TU=1` — другой сбой того же класса (`initializer element is not a
compile-time constant`). Команда: Oracle 0.1.6, `NOVA_CACHE=0`, `nova test src/host_contract`. Граница: дальше не
сводится без замены `AlulaMachine` на мини-машину (двигатель тянет machine/table); self-contained mini-machine CU —
работа линии фикса Оракула, не пакета.

**Что не сводилось ранее (2026-11-20, до бисекции):** трёхфайловый слитый юнит
(`spikes/env/repro_engine/src/repro_129a/{defs,engine,main}.nv`: generic-ресивер, конструктор чужого типа прямо
в метод, пара равной арности) на 0.1.6 **зелёный** — сторона A пары. Бисекция выполнена выше; в объём этой карточки
сведение не входит (отдельная линия по чартеру Оракула).

**Оракулу (сессия 0.1.7) отправлено:** симптом, обе формы (метод с конструктором в аргументе; ложный резолв при равной
арности), точечное 0.1.6-воспроизведение и критерий готовности — обе формы собираются в любом юните.

## Приёмка и публикация

Независимая приёмка чужой сессией по candidate SHA; публикация, пуш и теги — только по слову владельца.
Маршрут и слово владельца переданы методикой (журнал 118, коммит `71a7570`).

## Оценка и риски

0.5–1 день инвентаризации и проб плюс приёмка. Риски: обилие форм-триггеров (класс шире одной строки);
красная проба на 0.1.6 может зависеть от порядка файлов в юните — фиксировать форму носителя; снятие
обхода может вернуть `void*` только при следующей правке рядом (тогда правило и проба обязательны).
