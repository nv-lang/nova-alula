# Переименование: примитивы хозяина → инструменты (формат 0.30)

- Тип: ломающая языковая и API-правка пакета `nova-alula` + синхронная правка методики.
- Статус: **зарегистрирована, не начата**. Слово владельца 2026-11-18: «я бы хотел называть это инструментами»;
  на вопрос об объёме выбран вариант «полное переименование сразу».
- История: 2026-11-06 задачи 106–108 методики переименовали «внешние функции → инструменты» **только в прозе
  методики** (коммит `0c90ca2`); раздел 7 спецификации и пакет не участвовали. Слово владельца записано в журнале
  эпика 118 (`56a52d8`), объём тогда не был решён.

## Что меняется

| Место | Было | Стало |
|---|---|---|
| Раздел файла машины (ru) | `## Внешние функции` | `## Инструменты` |
| Раздел файла машины (en) | `## External functions` | `## Tools` |
| Термин спецификации, раздел 7 | «Внешние функции и допустимость классов», «внешняя функция» | «Инструменты и допустимость классов», «инструмент» |
| Реестр хозяина (пакет и методика) | `## Primitives` | `## Tools`; 13 строк — байт-в-байт без изменений |
| Страж 103 методики | ищет `^## Primitives`, сверяет с реестром пакета | ищет `^## Tools`, сверка та же |
| Протокол ядра | `PrimitiveHost`, `@call_primitive`, `PrimitiveFailed` | `ToolHost`, `@call_tool`, `ToolFailed` |
| Адаптер и функции пакета | `ThinPrimitiveHost`, `new_thin_primitive_host`, `run_thin_primitive`, `run_battle_primitive` | `ThinToolHost`, `new_thin_tool_host`, `run_thin_tool`, `run_battle_tool` |
| Документация пакета | «примитив», «primitive» | «инструмент», «tool» |

Не меняются: 13 имён функций (`read_file`, `start_process`, `sha256`, …), их сигнатуры и классы; 595 фикстур
методики; ключ дерева `primitives` (см. ниже); реестр-строки; поведение.

## Формат и совместимость

- Заголовок раздела — часть формата: выпуск **0.30**, метка AL-158 (следующая после AL-157), 0.29 и старше
  отвергаются с подсказкой мигратора.
- `tools/migrate-alula-230.py`: переименование заголовка раздела в машинах ru/en; идемпотентен; `--dry-run` и
  `--selftest` по образцу 229. Библиотеки не трогаются (в них `## Внешние функции` запрещены).
- Ключ дерева `primitives` в `machine/2` **в этой задаче не меняется**: это провод, его смена — отдельное решение
  о схеме дерева. В прозе и API — инструменты; в дереве — прежний ключ, с явной пометкой в спецификации.

## Порядок (два репозитория)

1. Пакет: парсер/рендер/проверки заголовка → идентификаторы (`ToolHost` и др.) → спецификация и доки → мигратор
   230 → примеры пакета.
2. Методика (её сторона): реестр `## Tools`, страж 103, миграция 5 машин, журнал/метки; строки реестра
   совпадают с пакетом байт-в-байт.
3. Совместно: прогон стража 103 с `--package-registry`, полный набор методики 595/595, примеры пакета 107/107.

## Проверки (DoD)

- `alula compile` всех машин ru/en: новый заголовок читается и рендерится; старый на 0.30 — отказ с подсказкой.
- Roundtrip compile→render→compile на примерах; `nova test src --jobs 4` — полный набор; `--strict-effects` на
  затронутых модулях.
- `alula test examples` — 107/107; стражи пакета FAIL 0; профили 37/37.
- Страж 103 методики с реестром пакета — зелёный; 595/595 на мигрированных машинах.
- Грепы: `PrimitiveHost`, `call_primitive`, `ThinPrimitiveHost`, `run_thin_primitive`, `run_battle_primitive`,
  `## Внешние функции`, `## External functions`, `## Primitives` — 0 в пакете (кроме исторических документов,
  где это цитата, и мигратора, который старый заголовок узнаёт).
- Саботаж-проба на приёмке: сломать узнавание нового заголовка — тесты парсера/рендера краснеют.

## Оценка и риски

2–4 рабочих дня (парсер/рендер, мигратор, спецификация, идентификаторы, два репозитория) плюс приёмка.
Риски: заголовок раздела — грамматика, ошибка ломает все машины; реестр и страж меняются одновременно в двух
репозиториях; рендер en/ru должен совпасть с деревом; 595 фикстур не правятся, но машины мигрируются.
Публикация, тег и выпуск 0.30 — только по слову владельца.
