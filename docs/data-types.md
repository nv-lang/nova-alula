## 1. Карта типов

Все типы перечислены в разделе 2; запись выражений над ними — раздел 3, функции каталога — раздел 12.

| Тип | Запись | Где живёт в машине |
|---|---|---|
| целое | `число`, `число>=n` | данные, поля, константы, параметры |
| дробное | `вещественное` | поля записей (стоимость), данные |
| текст | `строка` | поля, данные, параметры событий журнала |
| булево | `булево` | условия, результат функций |
| идентификатор | `ид` | данные машины: UUID сессий, прогонов |
| набор литералов | `"a" \| "b"` | тип данного, поля, аргумент типа, результат функции |
| необязательное | `?T` | данные «ещё нет значения», поля записей |
| список | `[]T` | данные, поля |
| словарь | `словарь[K, V]` | данные, параметры |
| полный словарь | `полный словарь[K, V]` | параметры, данные; ключ — перечисление |
| кортеж | `(T1, T2)` | ключ словаря, параметр события журнала |
| запись | `тип Имя { поле T, … }` | `## Типы`: вход, запрос, ответ, поля |
| перечисление | `тип Имя перечисление …` | `## Типы`: закрытые наборы, коды, формы ответа |
| встроенные | `Состояние`, `Сигнал`, `СобытиеЖурнала`, `ИсходВорот` | сама машина: состояния, сигналы, журнал, ответы ворот |

Перечисление объявляется словами `тип Имя перечисление` (раздел 2, AL-99). Одна его альтернатива — **форма**; форма без полей — **элемент**. Короткая запись — одной строкой из голых имён: `тип Имя перечисление А | Б`. Со значениями или полями — по строке на форму, начатой `|`: элемент со значением `| Эл = "значение"`, форма с полями `| Вар { поле T }`, форма без полей `| Вар`. Перечисление, у которого поля есть хотя бы у одной формы, — **перечисление с полями**. Значения у элементов и поля у форм в одном типе не смешиваются.

**Виды параметров фрагмента** (`сигнал`, `строка`, `[]машина`, `поведение`, `примечание`; группа `kind_param` таблицы слов) — не типы данных. Это слова подключения фрагмента (разделы 2, «Регистр», и 9).

## 2. Один шаг машины

![Типы в одном шаге машины: вход, данные, запрос стороне, сторона, ответ, строка перехода, журнал](alula-diagrams/alula-data-flow.svg)

Как это выглядит в «Шаге агента»:

1. **Вход** — поля `## Вход`, ровно поля записи `ЗапросАгента` (стр. 95–106).
2. **Данные** — `## Данные`: `начальное` собирает из входа запись `запрос_агента` (стр. 114).
3. **Запрос стороне** — таблица «Запрос» состояния ХОД_АГЕНТА: поля `запрос_агента`, `ход`, `число_повторов`, `ход_до_повтора`, `решение_разрешения`, `расход` (стр. 256–263).
4. **Сторона** — `агент`, вид `agent(итог ИтогХода)` (стр. 139).
5. **Ответ** — перечисление с полями `ИтогХода` (стр. 53–61). У ворот (`вратарь`) — `ИсходВорот` с сигналами `разрешить`, `отказать` (стр. 140).
6. **Строка перехода** — образец `ответ: Закончен { … }`, условие, действия `поле = выр` (стр. 267).
7. **Данные и журнал** — действия меняют данные; `журнал(…)` пишет `СобытиеЖурнала` (стр. 269, 362).

## 3. Как типы работают вместе

### Данные машины: тип, граница, владелец

Данное — строка таблицы `| имя | тип | начальное | не убывает | пишет |` (раздел 2, «Данные»).

```
| число_повторов | число>=0 | 0 | да, <= ЧИСЛО_ПОВТОРОВ | строки |
| попытка_агента | число>=0 | 0 | да | механика |
```
(«Шаг агента», стр. 116, 129.)

- `число>=0` — граница. Выход за неё — ошибка машины (раздел 2, 3.3).
- `не убывает` — `да` или `да, <= выр`. Исполнитель проверяет после перехода.
- `пишет` — кто меняет данное: строки таблиц, механика исполнителя, фрагмент. Запись строкой в данное механики — ошибка проверки.

### Запрос стороне и типизированный ответ

Запрос — **запись**: у неё всегда одни и те же поля.

```
тип ЗапросАгента { вид ВидВызывающего, профиль ПрофильАгента, сессия строка, вид_диалога строка, контекст строка,
                   пределы ПределыАгента, трасса строка, номер_шага число }
```
(«Шаг агента», стр. 45–46.)

Ответ — **перечисление с полями**: разные исходы — разные формы, и у каждой формы свои поля.

```
тип ИтогХода перечисление
  | Закончен { текст ?строка, артефакт ?строка, расход РасходТранспорта }
  | Обрезан { расход РасходТранспорта }
  ...
  | ВременнаяОшибка
  | НужноРазрешение { запрос_разрешения ЗапросРазрешения }
```
(«Шаг агента», стр. 53–61, часть строк.)

У `Закончен` есть текст, у `ВременнаяОшибка` нет ничего, у `НужноРазрешение` — запрос разрешения. Строка перехода выбирает форму образцом и привязывает её поля (раздел 4.3):

```
| 1 | ответ: Закончен { текст, артефакт, расход: полученный } | — | расход = сложить_расход(расход, полученный); текст_ответа = текст; артефакт_ответа = артефакт | ПРОВЕРКА_ОТВЕТА |
```
(«Шаг агента», стр. 267.)

**Колонка `читает` в таблице «Запрос».** Пример — ХОД_АГЕНТА:

```
| поле запроса | выражение | читает |
|---|---|---|
| запрос_агента | — | сторона |
...
| расход | — | исполнитель |
```
(«Шаг агента», стр. 256–263, часть строк.)

- `сторона` — поле уходит стороне в запросе; запрос собирает исполнитель до отправки (раздел 4.2; правило 11, правило 15).
- `исполнитель` — объявление зависимости, а не действие: состояние использует это данное в своих строках (здесь строки 1–5 прибавляют к `расход` полученный расход), стороне оно не передаётся (правило 11: «исполнитель» в запрос не входит).
- Состояние читает любое имя из своих чтений, каким бы ни было его `читает` (раздел 3.1, «Имена»). Проверка до запуска убеждается, что выражения состояния читают только объявленные имена (раздел 10; правило 11).
- При исполнении данное читается как в любом выражении — текущее значение; новое значение записывается при фиксации шага (правило 13).
- `—` в столбце «выражение» — то же имя, что поле запроса (AL-56).

**Параметры журнала: `имя: выражение`.** Пример — РАЗРЕШЕНИЕ, строка 1:

```
журнал(permission_human_allowed, action: строка(обязательно(запрос_разрешения).вид_действия))
```
(«Шаг агента», стр. 334, часть действий.)

`permission_human_allowed` — код события, `action` — имя параметра события, двоеточие отделяет имя от выражения. Значения параметров — `строка` (раздел 5, действие `журнал(код, имя: выр, …)`), поэтому значение перечисления `ВидДействия` обёрнуто в `строка(…)`: она даёт значение элемента, например `"delete"` (разделы 2, 3.3). Не путать с `расход: полученный` в образце события `ответ: Закончен { … }`: там двоеточие привязывает поле ответа к имени (раздел 4.3; раздел 3.1, «Привязка поля двоеточием»).

**Перечисление со значениями** — закрытый набор элементов; у элемента есть значение — текст для журнала и JSON:

```
тип ВидДействия перечисление
  | Чтение = "read"
  | Запись = "write"
```
(«Шаг агента», стр. 17–19.) `строка(ВидДействия.Чтение)` даёт `"read"` (раздел 2, 3.3).

### Необязательные значения

`?T` — значение или `пусто` (раздел 2; 3.1). Так данное говорит «ещё нет».

```
| ход_до_повтора | ?("first" \| "retry" \| "continue" \| "fix" \| "permission") | пусто | — | строки |
```
(«Шаг агента», стр. 120.)

- `есть(x)` — истина, если не `пусто`; `обязательно(x)` — значение, на `пусто` — дефект программы (раздел 12, 3.3).
- `x ?? y` — значение по умолчанию: `?T ?? T` даёт `T` (раздел 3.2).

```
  если есть(а) и есть(б) то { (а ?? 0) + (б ?? 0) } иначе { а ?? б }
```
(«Шаг агента», стр. 151.)

### Наборы литералов

Набор литералов — закрытый набор текстов, без объявления типа (раздел 2, Т-1).

```
| ПОЛИТИКА_РАЗРЕШЕНИЙ | полный словарь[ВидДействия, "allow" \| "deny" \| "ask"] | … | — |
```
(«Шаг агента», стр. 89, значение сокращено.)

Зачем: присвоить значение вне набора — ошибка проверки. `выбор` по набору исчерпан, если названы все значения или есть `иначе`. Строка `иначе` развилки обязательна, пока исчерпание не доказано типом (раздел 4.1, AL-57).

Принадлежность набору пишется `в […]` (английское `in`; раздел 3.1):

```
| 9 | сбой(причина в [КодСбоя.СоединениеОборвалось, КодСбоя.НетОтветаВСрок, КодСбоя.НетРезультата]) | — | остановка = строка(причина); журнал(turn_failed, reason: строка(причина)) | УЧЁТ |
```
(«Шаг агента», стр. 275.)

Когда набор, а когда перечисление (раздел 2, Т-1): набор — небольшой и локальный для одной машины; перечисление со значениями — общее для машин, пересекает границу вызова или нужно журналу.

### Списки и словари

`[]T` — список, `словарь[K, V]` — словарь. Индекс даёт `?V`: ключа нет — `пусто`, не ошибка (раздел 3.2).

```
| линзы | словарь[строка, Линза] | вход.порядок_линз.словарь(л => л, л => Линза { идентификатор: л, потери_подряд: 0, пробы: 0, попытка: 0 }) | — | строки |
```
(«Совещание», стр. 132.)

`полный словарь[K, V]` — ключ перечисление, ключи — все его значения. Индекс даёт `V`, а не `?V`: пропуска ключа быть не может. Неполный литерал — ошибка проверки (раздел 2). Пример — `ПОЛИТИКА_РАЗРЕШЕНИЙ` выше: значение называет все десять элементов `ВидДействия`, поэтому индекс сразу даёт решение:

```
  пусть по_таблице = если требует_повышенного_внимания(вид_действия) то { "ask" } иначе { ПОЛИТИКА_РАЗРЕШЕНИЙ[вид_действия] };
```
(«Шаг агента», стр. 196.)

### Кортежи

`(T1, T2)` — запись без имён полей; поля — `к.0`, `к.1` (раздел 2). Встроенный пример — параметр события журнала: `СобытиеЖурнала` — `{ код строка, параметры []Параметр }`, где `Параметр` — кортеж `(строка, строка)`: имя и значение. Кортеж может быть ключом словаря (раздел 2).

### `ид`

`ид` — текст формата UUID (раздел 2, Т-2). Проверяется при загрузке данных и разборе входа. Значение даёт примитив хозяина `новый_ид` (класс `reading`); звать его можно только в `пусть` «При входе» операции, значение фиксируется в событии `сразу` (раздел 7). `ид` присваивается `строка`, обратно — только литерал UUID. Идентификатор запроса стороны `<сторона>-<попытка>` — не `ид`, он остаётся прежним (раздел 2).

### Преобразования: где типы не смешиваются

- `число` и `вещественное` не смешиваются: `вещественное(x)`, `число(x)` пишутся явно (раздел 2, 12).
- `число>=n` и `число` совместимы в обе стороны; результат `+`, `-`, `*` — `число` без границы (раздел 3.2).
- `строка(x)` — текст значения: числа, `вещественное`, `строка`, набора литералов, `ид`, перечисления, `Состояние` и `?` от них; у `булево` и составных типов её нет (разделы 3.3, 12).
- Вставка `"…${x}…"` — тип `строка`, не набор; дерево — вызов `склеить` (раздел 3.1).
- Набор литералов присваивается `строка`, и набор при этом забывается (раздел 3.2).

```
| 3 | число_повторов >= ЧИСЛО_ПОВТОРОВ | остановка = "no_result"; журнал(agent_transient_error_exhausted, retries: строка(ЧИСЛО_ПОВТОРОВ)) | УЧЁТ |
```
(«Шаг агента», стр. 286: параметр журнала — текст, поэтому `строка(…)`.)

### Условия и `выбор`

Условие строки и развилки — выражение типа `булево`. `выбор` по перечислению пишет элементы; имя можно писать голым, если тип известен по месту (раздел 3.1, AL-88).

```
функция требует_повышенного_внимания(вид_действия ВидДействия) -> булево =>
  выбор вид_действия {
    ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима => истина
    иначе => ложь
  }
```
(«Шаг агента», стр. 189–193.)

### Встроенные типы машины

- `Состояние` — перечисление имён состояний; текст — JSON-имя состояния.
- `Сигнал` — сигнал машины: `стоп`, `продолжить`, `остановить`, `отмена`.
- `ИсходВорот` — встроенное перечисление с полями, ответ сторон `human`, `enhanced` и вратаря; его формы — сигналы столбца «сигналы» стороны (раздел 1).
- `СобытиеЖурнала` — событие журнала; `журнал(код, имя: выр)` требует значения-тексты (раздел 5).

Ответ ворот в строке перехода:

```
| 1 | сигнал(разрешить) | — | решение_разрешения = "allow"; ход = "permission"; журнал(permission_human_allowed, action: строка(обязательно(запрос_разрешения).вид_действия)) | БЮДЖЕТ |
```
(«Шаг агента», стр. 334.)

Событие журнала как значение:

```
функция событие_расхода(u Использование) -> СобытиеЖурнала =>
  событие_журнала("agent_usage", session: u.сессия, result: u.результат, model: u.модель.идентификатор,
```
(«Шаг агента», стр. 223–224, начало функции.)

### Сторона JSON

Тип становится узлом дерева `machine/2` (раздел 6). Перечисление всегда даёт узел типа в массиве `variants`: у форм поля есть или нет; значения элементов — ключ `values`. Отдельного узла `enum` нет. Набор литералов в JSON-схеме — перечень строк (раздел 2).

Имена в дереве — JSON-имена (раздел 1а): строятся автоматически (словарь методики, затем транслитерация) или задаются строкой `## Имена`. Ключевые слова русского и английского файла дают одни ключи, поэтому дерево от языка файла не зависит. Пример строки `## Имена`:

```
| расход | transport_usage |
```
(«Шаг агента», стр. 70.)

## 4. Зачем это всё

| Тип | Какую проблему решает |
|---|---|
| набор литералов, перечисление | закрытый набор: значение вне набора и неисчерпанный `выбор` ловит проверка |
| перечисление со значениями | устойчивые коды журнала и JSON (`"read"`, `"timeout"`) |
| перечисление с полями | у каждой формы ответа — свои поля, без пустых «лишних» |
| запись | запрос и вход с постоянным составом полей |
| `число>=n`, `не убывает` | инвариант, который исполнитель проверяет после перехода |
| `?T` | явное «нет значения» вместо магических значений |
| `полный словарь` | пропущенный ключ невозможен; индекс без `пусто` |
| `ид` | формат UUID проверяется на входе и при загрузке |
| `ИсходВорот` | ответ человека и агента на воротах — одного типа |
| `СобытиеЖурнала` | журнал — код и тексты, его можно сверить со сценарием |
| раздельные `число` и `вещественное` | нет тихих преобразований чисел |
