# Алула: причины, цели и история создания

Алула (`Alula`) — язык записи стейт-машин таблицами с формальными столбцами; описание — [state-machine-alula-spec.md](../state-machines/state-machine-alula-spec.md). С 2026-10-19 по 2026-10-21 (версии 2.7–2.13) язык назывался «Портолан» (`Portolan`); в разделах 1–9 он назван так, как назывался тогда, и имена файлов там тогдашние (`*.portolan.md`, `state-machine-portolan-spec.md`, `check-portolan-*.py`); с версии 2.14 (2026-10-21, метка AL-50) — `*.alula.md`, `state-machine-alula-spec.md`, `check-alula-*.py`. Почему имя сменили — раздел 10. Этот файл — не норма и не журнал правок, а запись о том, зачем язык появился, что от него требовалось и как решали; построчный журнал меток AL-NN — раздел 0 спецификации и `completeness-check.md`. Путь начался с алгоритма прозой 2026-10-06…07 (раздел 2); сам формат вырос за один день, 2026-10-19, из таблиц состояний и кода автоматов; даты без года-месяца — 2026-10-19. Слова владельца записаны с датой и источником (правило методики о слове владельца, `task-sessions.md`, «Правила»). Пути к прежним файлам машин — по нынешнему положению (в `state-machines/archive/`).

## 1. Что это и чего хотели

**Портолан** записывает машину — процесс с состояниями, событиями, условиями, действиями и вложенными вызовами других машин — таблицами в markdown. Файл машины читает и пишет человек по-русски; из него программа получает проверки, JSON-дерево и исполнение.

**Цели**

1. **Описывать машины без программирования на Нове.** Владелец, 2026-10-19: «как можно строить стейт машины внутри продукта … на человеческом языке миную стадию перепрограммирования на Нова, есть идеи?»
2. **С теми же возможностями, что у машин на Нове:** детерминированный повтор шага (правила 12–13 спецификации), вложенные вызовы (правило 35), структурный журнал (правило 31), счётчики, таблицы маршрутов, списки структур.
3. **С соблюдением правил методики.** Язык не вводит новых норм поведения: всё, что в нём записано, выводится из правил `state-machine-spec.md` (шаг как фиксация, шаг читает только свой Вход, один запрос — один ответ).
4. **Одна запись — один источник правды.** Код на Нове по таблицам не генерируется: третьего источника нет.
5. **Читаемость и проверяемость вместе.** Человек видит таблицы; программа проверяет достижимость состояний, полноту развилок, чтения и записи данных, соответствие журнала шаблонам.
6. **Проверка равенства с рукописным кодом по журналу.** Интерпретатор и автомат на Нове на одной последовательности событий дают одну последовательность (состояние, событие журнала, данные машины).

## 3. Причины появления

Проект-потребитель методики строит продукт, в котором пользователь должен описывать собственные машины, не программируя на Нове. Ему нужен был общий интерпретатор, читающий описание машины как данные. Первый ответ методики (владелец принял его «по рекомендации») был осторожным: источник правды оставить в коде автоматов на Нове, потому что в таблицах нет условий и действий, а универсальный язык по описанию — это второй язык программирования. Решающим стало слово владельца: «Мы не знаем заранее, достаточно ли такого языка для ваших реальных машин — реальные машины есть в этой методике» (владелец, 2026-10-19). Это превратило вопрос из «нужно ли» в «проверим выразимость на настоящих машинах».

**Почему не готовый язык.** Рассмотрены SCXML, XState, Amazon States Language, CNCF Serverless Workflow, BPMN/DMN, Temporal, а для условий — CEL, FEEL, JSONata. Целиком ни один не подошёл: у наших машин особая семантика (сохраняемая очередь событий, шаг как атомарная фиксация, «один запрос — один ответ», необратимое после фиксации, пауза цепочки вложенных машин), а исполнитель должен быть на Нове. Взята семантика CEL как образец (не Тьюринг-полный, детерминированный, без побочных эффектов), структура — в духе XState и Serverless Workflow.

## 4. Ключевые решения и их причины

| Решение | Причина |
|---|---|
| Таблицы с формальными столбцами вместо отдельного языка | строка таблицы уже единица проверки (метки `ИМЯ #n`); человек и программа читают один файл |
| Файл машины — единственный источник; код не генерируется | без третьего источника правды нет расхождений между прозой, таблицами и кодом |
| Закрытый чистый язык выражений без циклов (фильтр, отобразить, свёртка, диапазон), условия `если … то … иначе` | детерминизм (правила 12–13); простота интерпретатора; тотальность вычислений |
| Эффекты — только именованные примитивы с классами `pure`/`reading`/`writing`/`irreversible` | видно, что чисто, что читает, что пишет; необратимое только после фиксации шага |
| Структурный журнал: событие (код, параметры), шаблоны текста — отдельно | машина не собирает текст; журнал читается программой и показывается по-русски |
| Правило «функция без тела в источнике — примитив хозяина» | не изобретать тела, которых нет в источнике |
| Нотация как в Нове: объявления `имя тип` через пробел, `->` для результата, `...` для спреда, поля кортежа с нуля | одна нотация в таблице машины и в Нове (владелец, 2026-10-19, через проект-потребитель: «в Нова нет двоеточия перед типом, почему тут решил добавить?»); расширения помечены в разделе 14 формата |
| Закрытый набор значений `"a" \| "b"` вместо `текст из {…}` | единообразие с вариантами и перечислениями; правило, когда набор, а когда перечисление |
| Строки-ключи состояния — элементы списка | предпросмотр markdown склеивал соседние строки в один абзац (замечание владельца, 2026-10-19, по снимку экрана) |
| Проза в файле — комментарий; раскрытие фрагмента — отдельный справочный раздел | замечания переводчика проекта-потребителя при разборе образца |
| `ид` — тип UUID; `новый_ид` — reading-примитив, значение фиксируется в событии `сразу` | недетерминированность снимается как у времени; конверт запроса и трассы не меняются |

## 5. Хроника: от первого вопроса до версии 2.22

Записи 17–29 говорят, что решили, почему и что сказал владелец; метки AL-NN построчно, с перечнем затронутых разделов, — в разделе 0 [спецификации](../state-machines/state-machine-alula-spec.md).

1. **Вопрос и оценка.** Владелец спросил, можно ли строить машины в продукте на человеческом языке без Новы. Оценка методики: формата-данных нет; машины остаются кодом; можно взять идеи из готовых языков. Владелец: машины для проверки есть в методике.
2. **Формат v0.** Проект-потребитель написал черновик формата: файл машины — markdown с разделами Типы, Данные, Стороны, Состояния, Концы, Примитивы; выражения по семантике CEL; JSON-дерево; сценарии. Методика назвала недостающее: протокол `Автомат` движка требует около 30 методов, а в таблицах «строка перехода» — только `step`; нужны вход обращений, действия при приёме, работа операций, концы, данные.
3. **Подсчёт конструкций** по пяти автоматам (414 строк переходов; около 48% только простые конструкции; 82 вызываемые функции).
4. **Пилот «Шаг агента» на v0:** 22 из 37 строк переходов легли (59,5%), единиц 90 из 139 (64,7%).
5. **Формат v1** (19 правок пилота). **Пилоты на v1:** «Шаг агента» 32 из 37 строк (86,5%), единиц 129 из 138 (93,5%); «Совещание» 54 из 67 строк (80,6%), единиц 190 из 270 (70,4%).
6. **Исправления источников** по находкам пилотов: расхождение копии предложения и её отпечатка в «Совещании» (дефект логики), имена состояний в шаблонах журнала, очистка данных аннулированного захода, слово кода сбоя в журнале, текст отказа ОШИБКИ, фрагмент «Пауза».
7. **Формат v2 → 2.1 → 2.2** (коммиты 2334f77, 33d2104, 56ea7f6). Пилоты на v2: «Шаг агента» 123 из 138 Л (89,1%), «Совещание» 222 из 271 (81,9%). На 2.1: 135 из 138 (97,8%) и 262 из 271 (96,7%). На 2.2 (выборочная проверка): 138 из 138 и 266 из 271 (98,2%) — критерии приёма достигнуты.
8. **Формат 2.3** (55490e6, 28339a7, fc230fb). Три уточнения (состав `все_данные`, возврат сторон в `к_отправке`, объём правила для функций без тела) и нотация Новы; сводка записей формата, которых нет в Нове (раздел 14 формата).
9. **Формат 2.4** (c51e901). Проект-потребитель реализовал интерпретатор по версии 2.2 и подтвердил равенство с автоматом по журналу на 39 сценариях небольшой машины (машина чата). Из реализации пришли: код журнала `input_rejected`, кодирование `журнал(все_данные)`, формулировка про дефект программы как «выпуск для интерпретатора».
10. **Формат 2.5** (2a611b4; словарь 9 — ffc75ff). Набор литералов, тип `ид` и примитив `новый_ид` (латинское имя `new_id`, словарь версии 9).
11. **Формат 2.6** (57218fd, d189da8). Строки-ключи списком (предпросмотр склеивал строки); образец «Шаг агента» целиком (461 строка) в формате.
12. **Формат 2.7** (66baf66). Прогон образца через переводчик «таблица → JSON» не разобрал его (25 ошибок первой волны): проза вне таблиц, раскрытие фрагмента внутри подключения, повтор состояния ПАУЗА, имена вне словаря. ## 9. Схемы `machine/2` и `scenario/0`: что это и для чего

Эти два вида JSON-файлов ведёт проект-потребитель Портолана; описания схем лежат у него в виде JSON Schema. Раздел записан по ним на 2026-10-19; нормативного статуса в методике он не имеет.

**Цепочка.** `agent_step.portolan.md` (пишет человек, по-русски или по-английски) → переводчик → `agent_step.portolan.json` (схема `machine/2`) → интерпретатор; `*.scenario.test.json` (схема `scenario/0`) проверяют поведение. Имя дерева — `<имя>.portolan.json` (решение владельца, 2026-10-19, версия языка 2.10): JSON — исполняемая форма самого языка, а не отдельный формат; прежнее имя `*.machine.json` без переходного периода (версия 2.11). Обратное преобразование — канонический вид, раздел 1б спецификации.

### 9.1. `machine/2` — машина как данные

Дерево, которое исполняет интерпретатор; `format: "machine/2"` обязательно, неизвестный ключ — отказ загрузки; одно и то же дерево получается из русского и английского файла. Схема проверяет форму, правила между разделами — программа проверки. Обязательны `format`, `machine`, `initial`, `states`, `ends`. Строка таблицы — элемент `rows` с номером `n`; условие — дерево выражения (`op`, `left`, `right`, `name`, `lit`, `call`); действия — объекты с `do` (`assign`, `journal`, …); «Куда» — `to`; `иначе` — `else: true`; вид состояния — `kind`; «Концы» — в `ends`. Пример:

```text
| 1 | count >= LIMIT | journal(reached_limit, count: text(count)); stop = "done" | Finish |
{ "n": 1, "event": { "kind": "now" }, "cond": { "op": ">=", … }, "actions": [ { "do": "journal", "code": "reached_limit", … }, { "do": "assign", "target": "stop", … } ], "to": "Finish" }
```

### 9.2. `scenario/0` — тест поведения машины

Сценарий подаёт машине события и после каждого шага сверяет названное: состояние, строки структурного журнала, подмножество данных, открытые, отправленные и отменённые запросы, итог. Шаг: `do` (`feed`), `event`, `host` (ответы примитивов хозяина), `expect`. Для «Шага агента» у потребителя 75 сценариев, для машины чата — 39; сравнение с автоматом идёт по структурному журналу (код события и параметры), а не по тексту.

## 10. Как выбирали имя (второй раз): Портолан → Алула

Имя «Портолан» продержалось с 2026-10-19 по 2026-10-21 (версии 2.7–2.13). Поиск нового имени шёл 2026-10-19…21 в несколько кругов; решение — слово владельца, 2026-10-21: «Alula - ОК». Переходного периода нет (слово владельца, 2026-10-20: «нету переходного периода»): с версии 2.14 (метка AL-50) язык, расширения файлов, таблица слов `alula-keywords.tsv`, скрипты `check-alula-*.py`, спецификация и образцы переименованы одной волной; `machine/2`, `scenario/0` и `*.scenario.test.json` не менялись.

**Почему отказались от «Портолана»:** в 2026 году появилась открытая геопространственная спецификация Portolan для ИИ-агентов — та же ниша; владельцу не нравится русское звучание: «порча», «портной».

**Проверенные кандидаты** — около 130 имён:

**Что значит имя.** Два независимых значения:

- звезда Алула в лапе Большой Медведицы (имя в каталоге IAU): арабское *al-qafza al-ūlā*, «первый прыжок»; звёзды «трёх прыжков газели» — Alula, Tania, Talitha. Прыжок — переход машины из состояния в состояние;
