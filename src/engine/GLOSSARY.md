# Словарь: термин методики -> идентификатор -> где в методике

Код движка и демонстрационной машины написан английскими идентификаторами: Нова в Oracle 0.1.0 не принимает
русские (слово владельца, 2026-10-18). Методика описывает движок русскими именами; этот файл сопоставляет их.
**Словарь методики — версия 6** (`state-machines/state-machine-glossary.md`, репозиторий `unitcraft/ai-dev-methodology`, коммит
`744e0af`, 2026-10-19; журнал событием со структурой — `state-machines/state-machine-journal.md`). Код продукта выровнен по нему
задачей 102 (`doc/tasks/102-align-glossary/`); полная таблица решений «имя продукта -> имя словаря, переименовать или
оставить и почему» — `doc/tasks/102-align-glossary/mapping.md`. До задачи 102 словарь продукта шёл за методикой на коммите
`03b93a2` (задание 091): старые имена — в `rename-map.json` той же папки. Файлы методики: `state-machine-engine-automaton.md`
(движок), `state-machine-spec.md` («Спец. N» — правило N), `state-machine-journal.md` (журнал). Столбец «Где» называет файл и
раздел, в скобках — русское имя в методике.

## Типы

| Термин | Идентификатор | Где |
|---|---|---|
| Запрос (конверт обращения) | `PartyRequest[T]` | Спец. 15; движок, «Типы» (`Запрос`) |
| Ответ с результатом | `Reply[R]` | там же (`ОтветСРезультатом`) |
| Ответ с отказом | `Rejection` | там же (`ОтветОтказ`) |
| Ответ: результат или отказ | `PartyResponse[R]` (`Answer`, `Refusal`) | там же (`Исход`). `Outcome[T]` занят прелюдией Нова, свой тип с этим именем ломает C (spikes/env, `repro_engine`, п. 9), поэтому — `Response`, как в блоке «Типы на Нове» методики |
| Код сбоя | `FailCode` | Спец. 16; движок, «Типы» (`КодСбоя`); те же десять кодов |
| Конверт события (приходящее) | `Incoming` | движок, «Типы» (`Входящее[Событие]`); словарь, п. 10: в 091 назывался `Event`. В продукте поля `kind`, `name`, `input`, `trace`, `step`, `at` вместо `party` и `body` (событие машины кодируется парой `name` + `input`) |
| Событие машины | `ChatEvent` (у машины чата) | словарь: `Event` модуля машины; у демонстрационной машины приставка `Chat` |
| Вид события (класс, по которому ветвится движок) | `EventKind`, поле `Incoming.kind` | Спец. 6, 14, 16; в методике отдельного типа нет: движок ветвится по виду `Received` (`ResponseReceived`, `WordReceived`, `RequestExpired`); у `Progress` соответствия нет |
| Имя события машины | `Incoming.name` | Спец. 31 («вид» события в идентификаторе `<вид>-<номер>`) |
| Куда ведёт шаг | `Transition[S]` (`Go(S)`, `Stay`) | движок, «Типы» (`Переход`); `Rerun` и `NotAwaited` в MVP нет |
| Среда машины | `Environment` (протокол) | движок, «Протоколы и хранилище» (`Среда`): операция `write_journal`; приказы продукта `order_send`, `order_cancel`, `order_save`, `order_finish` — соответствия нет (в методике запрос рождается из описания обращения состояния, отмена — правилом 18, конец — видом `Final`) |
| Приказы шага | `SendOrder`, `CancelOrder`, `Conclusion` | соответствия нет (словарь, п. 18); это аргументы операций среды продукта |
| Запись приказов шага | `Order`, `StepEnvironment` | внутренняя реализация среды в движке: записывает приказы по порядку; не часть контракта машины |
| Машина | `Machine[S]` (протокол) | движок, «Протоколы и хранилище» (`Автомат`); `S` — состояние, типизированное |
| Параметр журнала, событие журнала | `JournalParam`, `JournalEvent`; помощники `param`, `journal_event` | журнал (версия 6): код и именованные параметры вместо готового русского текста |
| Строка журнала | `JournalEntry` (`trace`, `step`, `cause`, `state`, `request`, `at`, `event`) | Спец. 31; движок, «Типы» (`ЗаписьЖурнала`); без `kind` и `text`, `model_tally` не вводится |
| Журнал | `Journal` (эффект) | Спец. 31; движок, эффект `Журнал` |
| Снимок | `Snapshot` | Спец. 22; движок, «Протоколы и хранилище» (`Снимок`); в продукте один JSON-объект: `step`, `data` вместо `engine_data`, `machine_data` |
| Хранилище | `Store` (эффект) | движок, эффект `Хранилище` |
| Связь со стороной | `Link` (эффект: `send`, `receive`, `cancel`, `ack`) | движок, эффект `Связь` (здесь сторона одна — агент; в 091 назывался `Agent`); `ack` — подтверждение входящего события после фиксации (задание 095), в методике нет; `signal`, `reply` не вводятся |
| Время | `Time` (стандартный эффект Нова) | движок, «Протоколы и хранилище»; `Time.now()` |
| Данные движка | `EngineState[S]` | движок, «Данные» (`СостояниеДвижка`) |
| Открытый запрос | `OpenRequest` | Спец. 14, 16 (`открытые_запросы`); срок — `Waiting` |
| Ожидание ответа | `Waiting` (`sent`, `term`) | движок, «Типы» (`Ожидание`); вместо `deadline` |
| Счётчик попыток стороны | `PartyCounter` | Спец. 15; в методике счётчики — поля данных машины, соответствия нет |
| Исполнитель | `Engine[M, S]` | движок, «Цикл исполнителя» (`Исполнитель`) |

## Коды сбоя (`FailCode`)

| Код методики | Идентификатор | Слово в журнале (`fail_code_word`) | Примечание |
|---|---|---|---|
| нет результата | `NoResult` | `no_result` | сбой вне списка исполнитель пишет этим кодом (Спец. 16) |
| отказ модели | `ModelRefused` | `model_refused` | |
| соединение оборвалось | `ConnectionLost` | `connection_lost` | |
| форма не исправлена | `FormNotFixed` | `form_not_fixed` | |
| нет ответа в срок | `Timeout` | `timeout` | порождает исполнитель, не сторона |
| отменено родителем | `Cancelled` | `cancelled` | в MVP не порождается (вложенных машин нет) |
| остановлено человеком | `StoppedByHuman` | `stopped_by_human` | |
| потолок заходов с открытыми находками | `CeilingReached` | `ceiling_reached` | в MVP не порождается |
| `MaxTokens`, `MaxTurnRequests` | `MaxTokens`, `MaxTurnRequests` | `max_tokens`, `max_turn_requests` | в методике добавлены вслед за заданием 091; в MVP не порождаются |

Имя `FailCode.name()` (`NoResult`, …) остаётся форматом провода продукта: так код записан в снимке, во входе события отказа и в итоге сессии.

## Журнал: коды событий продукта

Код события — латинский `snake_case`, один смысл — один код, без приставки машины (журнал, раздел 1). Параметры — именованные строки.
Русских шаблонов у этих кодов пока нет (таблица шаблонов методики — для машин методики): показ текста — отдельная задача, а код читается и так.

| Код | Параметры | Когда |
|---|---|---|
| `machine_started` | `machine` | первый шаг (`start-1`) |
| `event_accepted` | `kind`, `name`, `source` (если у события есть ключ источника) | событие принято |
| `reply_discarded` | `reason`: `no_request_id`, `closed_request`, `unknown_request` | чужой или поздний ответ отброшен (Спец. 17) |
| `request_ordered` | `party`, `attempt` | запрос заказан машиной |
| `request_sent` | `attempt` | запрос отправлен (отметка диспетчера) |
| `request_closed` | `how`: `answered`, `refused` (и `code`), `expired`, `cancelled`, `machine_ended` | запрос закрыт |
| `cancel_ordered` | `reason`: `machine`, `idle_term`, `machine_ended` | отмена заказана |
| `cancel_sent` | — | отмена отправлена |
| `cancel_without_request` | `party` | отмена стороны без открытого запроса |
| `snapshot_ordered` | `step` | машина заказала снимок (`order_save`) |
| `machine_finished` | `outcome`: `answer`, `refusal`; `code` | конец машины |
| `engine_resumed` | `snapshot_step`, `open`, `not_sent`, `ignored_lines` | повторный вход (`restart-<n>`) |

## Демонстрационная машина (сессия чата)

В словаре методики её нет (словарь, п. 22), приставка `Chat` держит имена машины отдельно от имён движка.

| Термин | Идентификатор | Где |
|---|---|---|
| сессия чата с агентом | `ChatSession` | `task-runner-session-states.md` (обращение СЕССИЯ) — сильно упрощена |
| состояние | `ChatState`: `Idle`, `Awaiting`, `Done`, `Failed` | |
| события | `ChatEvent`: `UserMessage(text)`, `AgentChunk(text)`, `AgentDone`, `AgentRefused(code)`, `Cancel`, `Timeout` | |
| типизированное ядро шага | `chat_step(session, state, event, mut environment) -> Transition[ChatState]` | |
| шаг для движка (протокол `Machine[ChatState]`) | `ChatSession.step(state, incoming, mut environment)` | |
| граница снимка | `ChatSession.encode_state`, `decode_state` (`encode_chat_state`, `decode_chat_state`) | |
| события журнала машины | `user_message` (`text`), `cancelled_before_request`, `agent_chunk` (`text`), `agent_done`, `agent_refused` (`code`), `cancelled_while_waiting`, `no_answer_in_time`, `event_ignored` (`event`, `state`), `event_unknown` (`name`) | |

В задании 099 (сервер сессий) типы `Request[T]` и `Response[R]` движка переименованы в `PartyRequest[T]` и `PartyResponse[R]`: в одной программе с Polaris пакет `http` приносит свои `Request` и `Response`, а таблица имён типов в Oracle 0.1.0 одна на всю программу, зависимости включены (`spikes/env/repro_server/`, `user_request_vs_http`). Слова методики остаются прежними. Событие `event_accepted` журнала получило параметр `input` (вход события), `Engine` — методы `take_events` и `history`.
