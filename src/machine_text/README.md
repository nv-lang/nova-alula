# machine_text: the translator of Alula (tables in Russian or English) into the machine as data, and the reverse generator

Task 108 (`doc/tasks/108-table-translator/`), task 109 (format 2.6), task 110 (format 2.7), task 113 (two languages, formats 2.8 - 2.11, the reverse generator), task 125 (format 2.12), task 149 (the rules AL-38 ... AL-49 of the format 2.13, the language 2.14), task 151 (the semantics AL-51 ... AL-64 of the formats 2.15 - 2.17), task 152 (the syntax AL-65 ... AL-102 of the formats 2.18 - 2.22: blocks, `=>`, functions, ranges, methods, insertions, enumerations, the lexer). A machine is a Markdown file of tables in Russian or in English in Alula, the language of the methodology (a file `*.alula.md`; the translator does not look at the extension; the former `*.table.md` is not a name of the product), **version 2.17 only**
(`spec/alula-spec.md` of the package; until version 0.3.2 the text lived in `unitcraft/ai-dev-methodology`); the translator turns it into the JSON `machine/2` that the interpreter of
`src/machine_table` + `src/machine_run` runs. Since task 148 a file of any other version than the current one (2.14, 2.12 too) is refused with "версия не известна": there is no transition period (the owner, 2026-10-20). The user writes no Nova. The names of a machine are written as the author likes; a name that leaves the machine gets its Latin JSON name by itself (the row of `## Имена`, the Latin name, the dictionary of the methodology, the transliteration, AL-53) - the brackets after a name of 2.14 are an error (AL-60), see "Format 2.17" below.

As a library (module `alula.machine_text`):

| Function | What it does |
|---|---|
| `translate(file_text) -> Result[str, []TranslateError]` | the JSON of a machine, or every error |
| `translate_report(file_text) -> TranslateReport` | the JSON (of what could be translated) with every note, the WARNINGS (`warnings`, a list of their own, format 2.7), and the counts of the rows (`rows_total`, `rows_noted`) |
| `translate_checked(file_text, registry) -> TranslateReport` | the same, then the checks of the table `check_machine` against the registry of the primitives of the host; an issue is put at the line of its row |
| `translate_report_with`, `translate_checked_with` | with the registry of the files of definitions of the caller (`[]NamedText`: the name of the include line, the text) |
| `translate_definitions(text) -> DefsReport` | a file of definitions (format section 8) alone: version, hash, JSON of types, constants, definitions |
| `definitions_hash(text)`, `normalize_definitions(text)` | the hash of a file of definitions: 12 hex letters of SHA-256 after the normalization of the format (BOM, LF, no blanks at the end of a line, one LF at the end) |
| `translate_type(text)`, `translate_types(text)`, `translate_expression(text, data)`, `translate_actions(text, data, parties, empty_lists)` | pieces of a table alone: a type, the declarations of the section `## Типы`, an expression, a list of actions |
| `render_summary(machine_json) -> str` | the summary of a machine: the header, one line per state with the number of rows and actions, the common events, the ends |
| `error_text(error, file) -> str` | `file:line:column: kind: message` and the quoted line (the same for a warning, its `kind` is `warning`) |

The output is deterministic: two translations of one text give the same bytes (a test compares them, and a test on the chat machine compares the tree with the hand-written one).

**Format 2.6 (task 109).** The key lines of a state (`Сторона`, `Срок тишины`, `Правит`, `Возвратов формы`, `Вход`, `При входе`, `При приёме`, `Кроме`, and `Предел запросов`, `Результат` in their sections) are items of a bullet list: `- Сторона: агент`.
The marker `- ` is OPTIONAL when reading (a file of format 2.5, such as `chat.alula.md`, has none), with and without it the JSON is the same; the columns of the errors stay the columns of the file (`TxEntry.shift` is the width of the marker).
The body of `При входе` of several actions may be a nested list, one action to an item (`  - пусть номер = новый_ид();`), the `;` at the end of an item is kept; an item of a nested list is read as a continuation line without its marker.
A table after a list item stands at the level of the block after an empty line. `format: 2.6` is read like `format: 2.5`; the key `alula_version` of the tree is the format of the file (`2.5` or `2.6`). The hash of the sample file of definitions is `1628bec298d9` (the line `format: 2.6` is a part of the hash).

**Format 2.7 (task 110).** Every mark of the version is run (the marks P-1...P-9 of section 0 of the changelog of the format); the sample of the methodology (`spec/samples/agent-step.alula.md`, 2.7, copied as it is into `src/machine_agent/cases/`) is translated whole, with no error.

| Mark | What the translator does |
|---|---|
| P-1 prose | A paragraph is a comment: a line at the first column after an empty line, outside the tables, the blocks of code (between lines of three backticks) and the key lines, with the lines that follow it up to an empty line, gives no entry (`tx_classify_full`); the signs `` ` `` and `« »` in it are free. A line that begins a declaration (`тип`, `функция`), a call `Имя(`, the sign `—` and any line of the section `Подключения` is not a paragraph (a file of 2.5 or 2.6 reads as before). A line right after a heading or a table (no empty line) is not a paragraph: it is "лишняя строка". A line of a paragraph that begins with a word of the closed list (`Сторона`, `Срок тишины`, `Вход`, `Правит`, `Возвратов формы`, `При входе`, `При приёме`, `Результат`, `Кроме`, `Предел запросов`, `Куда` - the format 4.1 names the last one too; `Начальное состояние` is not in it), after the marks `-`, a dash, `•`, `*` and spaces, followed by a space, a colon or the end, gives a WARNING `kind: warning` with the line and the column; the warnings are `TranslateReport.warnings`, not `errors`, the command prints them after the errors and does not change the exit code. |
| P-2 fragment | `## Подключения` holds the lines of connection only (`Имя(…)`, `функции: …`); prose, a list, a table, a heading or a key there is the error "только строки подключения". `## Раскрытие фрагмента «Имя»` (a heading that begins with these words, any name) is skipped whole up to the next heading `#`/`##` outside a block of code. A heading `### ПАУЗА — …` of the fragment in `## Состояния` is the error "состояние `ПАУЗА` объявлено дважды" (the fragment registers its states first). |
| P-5 sets | A set of literals `"a" \| "b"` is a type everywhere a type stands: the argument of `словарь[K, V]` and `полный словарь[K, V]`, the result and the parameter of a definition, a cell "type"; the brackets only under `?` and `[]` (the message says so). |
| P-6 tables | A separator row (a line of `-`, `:`, spaces and bars `|`) is skipped; `\|` in a cell is a bar of the text (also in a string literal), the escape is taken off. |
| P-7 words | The enum with words `перечисление Имя = Зн "слово" \| …` has the key `words` in the JSON: the list of the pairs `["Name", "word"]` in the order of the declaration (only of the values that have a word); an enum without words has no key. A word is a Latin word of a code (`[a-z][a-z0-9_]*`), not empty, once in the enum; the words of the built-in `КодСбоя` are the words of the engine (another word is `unsupported`) and do not go to the tree. |
| names | The field of a signal `идентификатор_запроса` is `id` (the dictionary) instead of `request_id`; `alula_version` of the tree is `2.5`, `2.6` or `2.7`. The hash of the sample file of definitions is `446ddf8041c0` (the line `- format: 2.7` is a part of the hash; `1628bec298d9` was the hash of 2.6). |

The files of definitions and the fragments say `format: 2.14`; the hashes of the sample file of definitions are `e7df8843f017` (Russian) and `8f309d17b896` (English), the method is the old one (the line `format` is a part of the hash; the Russian file changed with the ASCII signs of 2.14: for `format: 2.11` the hash of the changed file is `fef51ed19cf1`, the English file gives the old `afe05e9a1e4d`). |

| AL-24 | The body of `для каждого` is one action up to the `;` or a list in brackets `(а; б)`; an action after the `;` outside the brackets is not in the body. |

Since 2.14 the translator tells a binding from a datum by the name as it is written too. |
| AL-27, AL-28 | The column `читает` stays obligatory (the rule of AL-27 is for the author who carries a table over: write `сторона` when the source does not say). | AL-29, AL-123 | An external function that the machine declares in `## Внешние функции` is called as a function `имя(арг)`, in an expression and as an action `имя(арг);` (the node `primitive_call` / the action `call`); since 2.24 this is the only form (`вызвать(…)` and the heading `## Примитивы` are errors with the hint, there is no transition period). ## Format 2.14: the rules AL-38 ... AL-49 (task 149)

The marks of the format 2.13 (the language 2.14), what the translator (`machine_text`), the reverse generator, the model and the checks (`machine_table`), the interpreter (`machine_run`) and the schemas do with each. The table of the analysis (label -> what changes -> where -> how it is checked) is `doc/tasks/149-alula-rules-213/analysis.md` of the product.

| Mark | What is done |
|---|---|
| AL-38 | `слово` is a signal of the party: the column `слова ворот`/`gate_words` is `сигналы`/`signals` (`имя (json)(поле (json) тип, …)`), the event `слово(…)` is `сигнал(…)`, the JSON has `signals` of a party and the event kind `signal`; the argument of the fragment is `сигнал_остановки`/`halt_signal`; the formers are errors with the form to write. |
| AL-39 | The key `Вход:` is `Запрос:` (an appeal: the table of the fields of the request) and `Читает:` (an operation, a fork, an end: the names the state reads); the section `## Вход` of the machine stays. |
| AL-40 | A key with no value is not written (`Срок тишины: —`, `Вход: нет`, an empty `При входе`); `Запрос: нет` or an empty value is an error; the generator writes no such key. |
| AL-41 | The values of an enum are `values` (`words` before); the schema and the decoder refuse `words`. |
| AL-42 | ASCII signs of the operators only (above). |
| AL-43 | No synonym of a type: `HashMap[K, V]` is refused with the form to write (`словарь[K, V]`, `map[K, V]`). |
| AL-44 | The section `## Раскрытие фрагмента «Имя»` is gone: one error "раздел … убран" at the heading, its content is skipped (no error from it). |
| AL-45 | The canon 1b is a recommendation; the norm is the circle "file -> tree -> file -> tree" (`alula_eq`, `machine_text_render`). The table of the keywords is the table of the methodology (216 rows); the names of the host are the registry `names_host.tsv`. |
| AL-46 | Names as written, JSON names in brackets (above); `$id` of the schemas is the package `nova-alula`. |
| AL-47 | `int` and `int>=n` fit each other in a call of a nested machine (the field of the input and of the result), at any depth; two bounds fit only when equal (`machine_table/check.nv`, `specs_fit`). |
| AL-48 | A field of the input of the type `?T` that the request does not give is `none` (the check does not ask for it). |
| AL-49 | The readable words (`причина` -> `reason`) are the table kind `readable`; a binding named by such a word has the JSON name of the table. |


**The key `fragments` of the tree** (a key of the product, not of the format: the methodology answered on 2026-10-20 that the form is the product's and the circle md -> JSON -> md needs only equal trees). `"fragments": [{ "name": "Pause", "args": { "halt_signal": lit, "halt_code": lit, "nested": list of lit, "cancel_requests": lit, "reenter": lit, "write_right": lit } }]`, the arguments in the order of the table `## Параметры` of the fragment, the values are expressions of the tree: the Latin name of the signal of the party that halts (`halt`), the text of the code, the names of the nested machines (`agent_step`), the Latin keys of the behavior words (`mechanics`, `without_return_to_send`, `stop_transport_turn`; `nothing`, `requests_from_to_send`), the note. It stands after `includes`, before `initial`. The fragment stays substituted in the ordinary keys (`data`, `common_events`, `states`, `signals`), so the interpreter needs no change. The generator (`render_frag.nv`) knows by the name what a fragment brings (`fragment_shape`: the data `previous`, `call_request_id`, `open_requests`, 6 common events, the state `Pause`, the 5 signals of the protocol; a test pins it to the file of the fragment) and leaves it out of the sections; a hand-written tree with no `fragments` is written as before. The text of a fragment says the states and the parties of the machine by words (`ОСТАНОВЛЕНО`, `усиленный`): a state whose heading is its Latin name is also called by its word of the dictionary, and the party of the fragment is named by the id of the column `идентификатор` (`enhanced`).

## Two languages (task 113)

A file is written in ONE language, `ru` or `en`, declared by the header line `- language: ru|en` (none means `ru`; spec 1a). The translator does not guess: an English header (`# Machine:`, `# Definitions:`, `# Fragment:`) with no `- language: en` is the error "язык шапки английский, а language не объявлен" (a Russian header with `language: en` too; any value but `ru`, `en` is an error); the file is then translated in the language of its header so that one wrong line does not
give a hundred errors. A keyword of the other language is the error of the kind `language` at the line and the column of the first foreign word (a section, a column, a key line, the kind of a state, an event, a destination, an action, a type, an expression word - `if` in a Russian file, `если` in an English one). The names of the author may be of any language: a Latin name that the table of names does not have is the name of the JSON as it is, in both languages; in an English file a Russian word of the dictionary is read too (the words of the kinds `catalog` and `executor` are keywords of the language and not names). The tree `machine/2` is the same for both
files but for the strings of the author (the title, the texts of refusals) and the names of the local variables that the author wrote himself.

**The table of words** is data: `alula-keywords.tsv` is a copy of `spec/alula-keywords.tsv` of the package as it is (the table of the notation of 2.14, the methodology commit `7b59336`: 216 rows, `kind, ru, en`, the closed list of spec 1a; the kinds `readable` and `enum_value` are new), `keywords_product.tsv` is the layer of the product (the sections `Сигналы`/`Signals` and `Части ответа`/`Response parts`, the events `срок`/`deadline` and `часть`/`part`, the key `сторона`/`party` of `cancel_open`, the fragment `Пауза`/`Pause` and its six parameters). The code never writes a word of the structure: it asks `kw(words, kind, key)` for a kind and the English word (the key) and gets the word of the language of the file, or asks which key a word is (`kw_key`) or whether it belongs to the other language only (`kw_foreign`). The test `wt no cyrillic words` reads the sources of the unit and finds no Cyrillic literal outside the texts of the error messages and the letters of the alphabet of the transliteration; the test `wt asked words exist` finds every pair kind-key that the code asks for in the table. `names_host.tsv` is the registry of the host (below), not a dictionary. Fragments and files of definitions come in both languages (`fragments/pause.fragment.md` and `.en.md`, `defs/cycle-arithmetic.alula.md` and `.en.alula.md`; the hashes of the samples of 2.14 are `e7df8843f017` and `8f309d17b896`).

**The news of 2.9 - 2.11 in the reading.** `для каждого`/`for each`; the heading of a state `### ИМЯ — вид (JsonИмя)` with the brackets needed only when the names differ (a Russian name without them is an error); an event field binding `поле: имя`; a declaration outside a block of code in a machine of 2.9 and later is a comment with a warning (the files of definitions and the fragments are read as before: the sample of the methodology holds its definition outside a block); a paragraph pressed against a table, a heading or a list item is a warning and an extra line (2.9 and later); `Куда` is no key of the list of the prose warning; an empty section `Вход` (one dash) is no input; `сбой(_ in {…})` binds nothing. The signs of the operators are ASCII only since 2.13 (AL-42): `>=`, `<=`, `!=`, `->`, `...`, `in`; a Unicode sign of 2.12 (`≥ ≤ ≠ → … ∈`) is the error "знак … в формате 2.14 не бывает" with the ASCII sign to write; in English the word `in` is the membership before `{` and ends the value of a `let`. Not run (the interpreter has no such thing; the line stays an `unsupported` note or is read as a name): the built-in enum `Сигнал` as a type (its words are the arguments of `передать`), `Состояние` as the enum of the names of the states (it is `text`), `допустимые значения` and `Обязывает` of the file of a fragment (the product's fragment is compiled in, its text is read as before), a nested machine, `Правит`, a profile of a party.

## Format 2.17: the semantics AL-51 ... AL-64 (task 151)

The marks of the formats 2.15 (AL-51 ... AL-55), 2.16 (AL-56 ... AL-62) and 2.17 (AL-63, AL-64); the analysis with the table "mark -> what changes -> where -> how we check" is `doc/tasks/151-alula-semantics-215-217/analysis.md` of the product.

| Mark | What the translator, the checks and the generator do |
|---|---|
| AL-53 the name by itself | A name that leaves the machine (a state, a datum, a field of the input, a type, a field, a form of an enumeration, an element of an enum, a signal of a party and its field, a primitive, the setting of a keeper) gets its Latin JSON name in this order: the row of `## Имена` (the qualified name `Тип.Форма.поле` is stronger than the simple one; a simple row renames every declaration of the name), the Latin name as it is, the English name of the dictionary for the WHOLE name (`glossary_names.tsv`, version 13 for 2.24, `glossary_names_v11.tsv` for 2.23, a name with two English names such as `расход` is not in it), the transliteration word by word (`jname.nv`; a state, a type, a form, an element - `PascalCase`, the others - `snake_case`). The code is `jname.nv` (`jn_auto`, `jn_declare`, `jn_finish`); `translate_names(text)` lists the names with their JSON names. |
| AL-59 mixed words | A word of a name (between `_` and spaces) of two alphabets (`ЗапросAgent`) is an error; `запрос_Agent` is fine. |
| AL-60 `## Имена` | `\| имя \| JSON-имя \|` (`Names`, `name \| json_name`) after `## Типы` in a file of a machine and of definitions: the only way to set a JSON name. Errors: an extra row (it changes nothing), a row for a name that is not declared (an internal or a readable name too), a repeated row, a JSON name that is not Latin, a collision. The brackets after a name (`число_ходов (turn_count)`) are an error with the way to write it now. The reverse generator writes no brackets and no section: the names lie in the tree as they are. |
| AL-58 ten spaces | A collision of JSON names inside one space is an error: the states (with the states of a connected fragment), the data (with the data of the fragments and of the contract), the fields of the input, the types, the fields of one record or form, the forms of one enumeration, the elements of one enum, the signals of one party and, apart, the fields of one signal, the signals of the machine, the primitives, the constants, the parameters and the settings of the keepers. |
| AL-61, AL-62 the dictionary | `glossary_names.tsv` is the normative part of the dictionary of the methodology (version 13, 1270 pairs in the order of the glossary; `parse_agent_reply` is replaced by the three parse functions by role, AL-131) pinned by the format 2.24 (the dictionary of the version 11 that 2.23 pinned, 1268 pairs and the hash `60383c370415`, went with the format 2.23: task 181 dropped its file); the translator recomputes the hash of the lines of the file (`35c571ccda17`, 12 letters of SHA-256 of `русское -> английское` joined by LF) at every translation and says "словарь изменён без смены формата" when it differs; the format and the hash change only together (`glossary_pinned_hash`). `scripts/glossary-names.py <glossary.md>` makes the file and prints the hash. |
| AL-56 `—` in `Запрос` | The cell of the expression `—` is "the same name as the field" (the name must be readable like any expression of the request); the same name written out is a warning; the reverse generator writes `—`. |
| AL-51, AL-52 free input | A party of the kind `human` with `—` in the column `счётчик` is a party of a free input: no key `counter` in the tree; `—` at another kind is an error. The checks of the tree refuse for an appeal to such a party a table `Запрос`, a set, an idle term, `Правит`, returns of the form, `При приёме` and the events `ответ`, `сбой`. The word is taken by the name of the signal in the current state, no gate is recorded and no counter grows. |

**The lexer (`lexer.nv`).** A lossless lexer by the model of the lexer of Nova: every token has the trivia before it, `lx_reserialize(lx_lex(src)) == src` for any text (checked on all files of the package and on mutations), a bad character, a bad number, a bad escape and an unclosed literal are `Error` tokens with a message and the lexer goes on. The numbers follow D44 (`1..п` is `1`, `..`, `п`; `0.5..2` is `0.5`, `..`, `2`; `...` is one token), a text literal with `${…}` is scanned to the matching brace (nested literals and braces inside are fine). `lex.nv` adapts the tokens to the parser (`tx_lex`, `tx_lex_in`): in a cell `\|` is a bar, a comment is an error, the numbers lose their `_`, the strings are decoded.

**The expected type (`elab.nv`).** The translator is untyped: it builds the tree and then `el_root` walks it once with the types that the tree itself holds (the declarations, the signatures of the functions, the types of the input) and turns the mark `[]` into `list` or `dict`. A piece translated alone (`translate_expression`) uses `el_piece` with the names of the context.

**The former forms (`former.tsv`).** One row per word that 2.24 does not have (the words of 2.23 and 2.22 that were replaced are here too, the column `was` says the last format that had the word): the language, the kind, the word, what to write, the mark, how it was shown. The code never writes such a word itself; `former_find` asks the table.

**The classes of the primitives (AL-116, task 170).** The class cell of `## Примитивы` is read by the table of words (the kind `enum_value`): `pure`, `изменчивая`/`volatile`, `действующая`/`acting`. The words `reading`, `writing`, `irreversible` stand in `former.tsv` under the kind `class` (6 rows, both languages): the error says "`reading` в формате 2.22 не бывает (AL-116): пишется `изменчивая`; переходного периода нет"; the table of words has 217 rows (it had 218 with the three old words). The same refusal is in the loader of `registry.md` (`alula.machine`, `host.nv`). The generator writes the class in the word of the language of the file.

**The marks of 2.23 (task 170).** AL-115: the code of an entry of the journal is a string literal, `журнал("код", имя: выр)` / `journal("code", name: e)`; a single literal without pairs is a code too; a bare name that is no binding, datum or word of the executor (`журнал(код)`) is refused with the new writing (`ac_journal` in `action.nv`); the reverse generator writes the code in quotes. The macros of the catalog are called list functions in the messages and the texts since 2.23 (the internal functions keep the word `macro`, the kind of the table of words stays `catalog`).

## The reverse generator (task 113)

`render_machine(machine_json, language) -> RenderReport { text, notes }` (and `render`, `render_machine_with(json, language, copy_includes)`) writes a tree `machine/2` as a file of Alula in `ru` or `en` in the canonical form of section 1b of the specification: the header `# Машина: <Имя>` with the four items, the eleven sections in order and an empty one as `—` under its heading, the keys of a state as list items in the order Party, Idle term, Edits, Form returns, Request, Reads, On accept, On entry, Except (a key with no value is not written), the tables with one space round the bar and `\|` in a cell, the declarations in blocks of code, one on a line, ASCII signs of the operators in both languages (`>=`, `->`, `...`, `in`), the name of a state in its heading with no brackets, UTF-8, LF, one line feed at the end. The words are the table of words; every name is written as it lies in the tree (a Latin JSON name, or the internal name as written, AL-46), but a readable word of the table (`причина`, `остановка`) is written by the word of the language and the registry of the host gives the Russian name of a machine, a signal of the call protocol and its field. An included file of definitions is written as its line of connection (its types, constants and definitions are left out), `copy_includes` writes the copies instead; an included fragment is written as ONE line of connection with every argument (format 2.12, 1b (m)) and its states, data, common events and signals are left out (a section `Common events`, `Signals`, `Response parts` are the product's extensions and are written when there is something to write); a tree with no `fragments` writes them as the machine's own. What the tree has and the file cannot say (a nested machine, an unknown node) is a note with the place in the JSON. Nothing of the prose is written, and the title is not: the header holds the Latin name of the machine, so a circle gives the same tree but for `title` and `alula_version`. The pieces are exported for tests (`render_type_in`, `render_expression_in`, `render_actions_in`).

The command: `alula render <file.alula.json> [--language ru|en]` (the program `alula`, `src/alula_cli/`, task 116; it replaced `machine-translate --render`) writes the file to the standard output (on Windows the standard output turns a line feed into CR LF; the function returns LF). The circles are tests: tree -> file -> tree on the seven machines of `src/machine/machines/` and on the machines written as files (the chat, the table of the agent step, both samples of the methodology, the pilot, the examples of the format) in both languages, "ru -> en -> ru", and the file of the second pass is the file of the first (the canonical form is a fixed point). `check-alula-samples.py` of the methodology, run on the generated pair of the agent step (Russian and English), finds one difference, and it is the product's section `Signals` that the table of words of the methodology has not got.

## Names in any alphabet, byte offsets (task 117)

The names of the author may be written in any alphabet: Greek, German with umlauts, Chinese, letters of four bytes. The reader of the lines (`lex.nv`) works on **byte offsets** and on `std.unicode`:

| What | How |
|---|---|
| a place in a line | a byte offset; the reader walks a line by the chars (`tx_at` decodes the char at an offset, `len_utf8` is its width) and cuts it with `s[from..to]` (a zero-copy view; every cut point is an offset of the walk, so a border of a char). There is no list of one-letter strings (`tx_chars`, `tx_slice` are gone). |
| a column of an error | still a column in LETTERS (`file:line:column` of the Cyrillic files is unchanged): the reader keeps the column step by step with the offset (`tx_cols` = `s[from..to].chars().count()`); never a byte count. `TxEntry.indent` and `shift` are in letters, `TxEntry.colon` and `TxKvHit.colon` are byte offsets in the text of the entry. |
| a letter of a name | `tx_is_letter`: `a-z`, `A-Z`, `_`, and for a char above U+007F `char.is_alphabetic()`; after the first letter also a digit `0-9` and a combining mark (`Mn`, `Mc`: a decomposed `ö` is one name). A number is ASCII digits only. |
| the case | `tx_is_upper`, `tx_is_lower`: `A-Z`, `a-z`, and `char.is_uppercase()`, `is_lowercase()` above U+007F. A type is told from a constant by `looks_like_type`: the first letter is upper case and a lower case letter follows (`Größe`, `Δείγμα`, `Использование` are types; `ÄRGER`, `ΔΕΙΓΜΑ`, `ПРЕДЕЛ` are constants or data); an alphabet without a case (Chinese, Hebrew) is neither upper nor lower, so such a name is never a type. |
| a space | a space, a tab, or `is_whitespace()` above U+007F (a no-break space, an ideographic space): indent, cells, between words. |
| a JSON name | a name that stays inside the machine (a binding, a constant, a parameter, a definition, a party) is written to the tree as it is, in any alphabet and in any case (`Größe` stays `Größe`, `ΔΕΙΓΜΑ` stays); a name that leaves the machine has a Latin JSON name in brackets after the name (AL-46), else the error. The transliteration is gone. |
| the circle | `md -> JSON -> md -> JSON` gives the same JSON on a lambda parameter, a `пусть` name and a datum of the author in any of these alphabets (`src/machine_text_unicode`), and on a machine whose states have Greek, German or Chinese names. |

What did not change: the keywords of the structure are the table of words; the name of a state takes its JSON name from the brackets of the heading (`### ЖДАТЬ — обращение (Wait)`, section 1a). The time of the translation of the sample of the agent step (30 KB) fell from about 1.2 s to about 0.45 s (the one-letter strings were the cost).

## The names

Since 2.16 (AL-53, AL-60) the JSON name of a name that leaves the machine is built by itself and set only by a row of `## Имена` (see "Format 2.17" above); the brackets of 2.9 - 2.15 are an error. A name that stays inside the machine (a constant, a parameter, a definition, a party, a binding) is written to the tree as it is. The readable words of the table (kind `readable`: `причина` -> `reason`, `остановка` -> `stop_reason`, `предыдущее` -> `previous`, `запись_перехода`, `все_данные`, ...) have the JSON name of the table. The same word of a field may have two JSON names in two declarations (a qualified row `Тип.поле` sets one of them); a literal `Тип { поле: … }`, a pattern `Случай(поле)` and a signal `сигнал(поле: …)` find the field by its owner, a reference without an owner (`x.поле`, a row of the request) to a field with two names is the error "объявлено в машине с разными JSON-именами" (the translator does not know the types of the expressions; a question to the methodology).

`names_host.tsv` (`kind<TAB>Russian<TAB>English`) is the registry of the host, not the dictionary of the names (that is `glossary_names.tsv`): `machine` (the names of the nested machines of the registry of the caller: `шаг_агента` -> `agent_step`), `signal` and `signal_field` (the signals of the call protocol that the fragment Pause reads: `стоп человека` -> `human_stop`, `продолжить` -> `continue`, their fields `автор`, `источник`, `слово_человека`), `field` (the fields of the built-in records). A name that a table introduces itself (a parameter of a definition, a `пусть`, a variable of a lambda, a name of an event) is written as it is; the fields of the signals of the protocol have the names of the registry also as bindings, so that a fragment of either language gives one tree. `piece_names.tsv` is test data (the names of the pieces of the tests of the expressions, the actions and the types), the translator does not read it.

## The file

Markdown, the sections of format section 1 (`## Типы`, `## Константы`, `## Параметры`, `## Вход`, `## Данные`, `## Стороны`, `## Определения`, `## Подключения`, `## Общие события`,
`## Состояния`, `## Концы`, `## Примитивы`). The rules of the reader: a line that starts with `>` is a comment, three backticks are nothing, `//` ends a line, a line that starts with `|` at the
first column is a row (`\|` is a bar of the text, a bar in a string literal is not a cell border), an indented line continues the line before it, any other line outside a construction is "лишняя
строка". Expressions, actions and types are those of sections 2, 3 and 5 (`?T`, `[]T`, `словарь[K, V]`, `полный словарь[K, V]`, tuples, `число≥n`, sets of literals `"a" | "b"`, `ид`; `если`, `пусть`,
`выбор`, lambdas, `{ ...x, поле: выр }`, `Тип.Форма { … }`, `вызвать(примитив, …)`; `поле = выр`, `+=`, `поле[ключ] = выр`, `журнал(…)`, `ошибка_машины(…)`, `для каждого`, `если … то (…) иначе (…)`).

Extensions of the product (they are the proposals of section 14 of the changelog of the format, И-4, that the interpreter has): the section `## Части ответа` (`| сторона | имя | поля |`) and the event
`часть(имя(поле: имя))` for a part of an answer that keeps the request open; the event `срок` (the term made by the executor); the section `## Сигналы` (`| имя | поля |`) and `сигнал(имя)` in the
rows of any appeal; `отменить_открытые(сторона: имя)` cancels the open requests of one party. The chat machine (`src/machine/machines/chat.alula.md`) uses all four.

**Fragments and definitions.** `## Подключения` holds `Пауза(сигнал_остановки: …, код_остановки: "…", вложенные: [], отмена_запросов: …, вход_заново: …, право_записи: "…")` (all six parameters; the
text of the fragment, `fragments/pause.fragment.md`, is compiled in, `<параметр>` is put in before it is read; its data come before the data of the machine, its common events before the
machine's own, its state `ПАУЗА` after the machine's states) and `функции: <имя> версия <N> хеш <hex12>` (the file is found in the registry by the name, the version and the hash are
checked, a copy of its types, constants and definitions is put in the tree, `includes` gets the line). `вложенные: []` makes `передать(вложенные, …)` and `отменить_открытые(кроме: вложенные)` plain.

## Alula 2.26, stream 3: the libraries and the built-in library `контракт` (task 197, spec sections 9 and 7а)

- The connection (`library.nv`). - The files. The translator takes the files of the caller (`translate_report_with`, `translate_checked_with`: `[]NamedText`, the name is the path as written; a path is also found at the end of a longer name). The errors in the text of a library stand at the subheading of its connection, with the line in the file: "в библиотеке Пауза (libs/pause.alula.md:51): …".
- The parameters are the local constants of the library: the value of the table is put in the text of the library where the name of the parameter stands (outside the strings, the header and `## Параметры`) before the text is read (`lib_substitute`).
