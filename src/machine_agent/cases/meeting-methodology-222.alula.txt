**Как устроена запись.** Разделы идут в порядке раздела 1 формата. Номер `№` строки состояния равен метке `ИМЯ #n` в таблицах и в коде автомата (метка умолчания развилки — следующий номер). Строки-ключи состояний — элементы списка, таблицы стоят на уровне блока. Текстовые значения закрытых наборов (`остановка`, `сбойное_обращение`) — слова кода автомата (латиница). Имена, которые выходят из машины (состояния, данные, поля входа, типы, их поля, формы и элементы, сигналы сторон и их поля, примитивы, имя настройки вратаря), получают латинское JSON-имя автоматически (спецификация, раздел 1а, «JSON-имя»: словарь методики, затем транслитерация); раздел `## Имена` (после `## Типы`) задаёт JSON-имя только там, где автоматическое имя неверно, — 14 строк: сигналы `оставить правку`, `вернуть копию`, `ответил`, `подтвердил` и имя настройки вратаря (их в словаре нет), `Утверждение`, формы `Ответил`, `ИтогПравки.Вопрос`, формы `КонтекстРоли` и поля `ОтветСвидетеля.Ответил.утверждение`, `КонтекстРоли.Свидетель.находки` (код автомата расходится со словарём; имя, объявленное в нескольких местах, уточнено путём); остальные сигналы ворот (`повторить`, `остановить совещание`, `засчитан` и др.) называет словарь (раздел 2.16); JSON-имена — имена кода автомата (по словарю), у типов вызова «Шага агента» — те же, что в его образце; данные контракта (`остановка`, `к_отправке`) в `## Имена` не пишутся: их JSON-имя — слово таблицы слов. В таблицах «Запрос» поле, чьё выражение — то же имя, несёт `—` в столбце «выражение» (`| трасса | — | сторона |`). Коды журнала — по таблице [журнала](state-machine-journal.md). Тела функций без тела в источнике (`has_critical`, `merge_unique`, `build_summary`, `remove_unsound` и другие) записаны примитивами хозяина (раздел «Примитивы», спецификация, раздел 7).

| вратарь | gatekeeper | human или agent по настройке исполнитель_повышенного_внимания(итог ИсходВорот) | — | повторить, остановить совещание, оставить правку, вернуть копию, остановить, не засчитан, засчитан { находки_В3 []Находка }, ещё заход { решение_человека строка }, остановиться, ответил { ответ_человека строка }, подтвердил { подтверждение строка } | попытка_вратаря |
| усиленный | enhanced | enhanced(итог ИсходВорот) | — | продолжить { слово_человека строка, автор строка, источник строка }, остановить совещание | попытка_усиленного |

- Предел запросов: ПРЕДЕЛ_ЗАПРОСОВ

Стороны вложенных вызовов — три: свидетель, автор, линза (набор по `порядок_линз`); все три — вложенная машина «Шаг агента». Профиль стороны — настройка проекта «Профили ролей», его читает примитив `профиль_стороны`. Вратарь — человек по умолчанию, агент по настройке проекта `исполнитель_повышенного_внимания` (ворота СБОЙ, ИЗМЕНЁН, ПОВТОР, В3, В9, В7, ПРИНЯТИЕ); усиленный — сторона состояния ПАУЗА (решение 12 первоисточника).

```
  если б то { "yes" } иначе { "no" }
```

Соответствие коду автомата: `role_limits` — `пределы_роли`. `слово_да_нет` — для значений параметров журнала `repeat` и `question` (раздел 4.7 формата). `call_kind` кода записан значениями во «Входах» сторон: у линзы `ВидВызывающего.Линза`, у свидетеля и автора `ВидВызывающего.ХодЧата` (решение 2 первоисточника). `ceiling_reached` слоя методики — `потолок_исчерпан` из подключённого файла `арифметика_цикла`; `reset_origin` и `no_probes_step` слоя методики — строки таблиц (`заход_отсчёта = номер_захода`; условия БЕЗ_ПРОБ), функциями не служат.

### ОСТАНОВЛЕНО — конец
- Читает: остановка, открытые, находки_В3

В ОШИБКУ входят из «иначе» развилок (`ошибка_машины("fork_no_match", …)`), из ОБЩ 6 (`ошибка_машины("cancel_parse_no_match")`) и по ошибке машины исполнителя; на всех путях определено `запись_перехода`.
