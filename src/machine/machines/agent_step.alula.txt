# Машина: Шаг агента

- machine: agent_step
- machine_version: alula-2.14
- format: 2.14

Это **иллюстрация**: машина «Шаг агента» целиком, записанная в формате «Портолан», версия формата 2.14 ([state-machine-portolan-spec.md](state-machine-portolan-spec.md); он единственное определение языка записи). Файл нужен, чтобы человек мог открыть и увидеть настоящую машину: типы, данные, стороны, определения, все 37 строк переходов, концы с таблицей «конец → ответ», подключённый фрагмент «Пауза»; его раскрытие (параметры, общие события ОБЩ 1–6, состояние ПАУЗА с событиями ПАУЗА 1–4) вынесено в справочный раздел в конце файла.

**Статус.** Эквивалентность этой записи автомату по журналу не проверялась: интерпретатор «Шага агента» не гонялся, сценарии не сравнивались. **Источник правды остаётся прежним:** таблицы состояний [archive/state-machine-agent-step-states.md](archive/state-machine-agent-step-states.md) и код автомата [archive/state-machine-agent-step-automaton.md](archive/state-machine-agent-step-automaton.md); при расхождении верны они, а этот файл правится вслед за ними. Фрагмент «Пауза» — [state-machine-pause-states.md](state-machine-pause-states.md), коды журнала — [state-machine-journal.md](state-machine-journal.md), имена — [state-machine-glossary.md](state-machine-glossary.md).

**Как устроена запись.** Разделы идут в порядке раздела 1 формата. Номер `№` строки состояния равен метке `ИМЯ #n` в таблицах и в коде автомата (метка умолчания развилки — следующий номер; строки `иначе` записаны явно и равны умолчанию). Строки-ключи состояний — элементы списка (`- Сторона: …`), таблицы стоят на уровне блока; абзацы прозы вне таблиц и блоков кода — комментарии для читателя, разбор их пропускает. Текстовые значения (`ход`, `остановка`, решения) — слова кода автомата (латиница). Строк переходов 37: СТАРТ 1, ХОД_АГЕНТА 9, ПОВТОР 4, ПРОДОЛЖЕНИЕ 3, ПРОВЕРКА_ОТВЕТА 5, ПОЛИТИКА 4, РАЗРЕШЕНИЕ 2, БЮДЖЕТ 5, УЧЁТ 1, ИТОГ_ШАГА 3; строки ПАУЗА 1–4 и ОБЩ 1–6 приходят из фрагмента. Строк «Концов» 13: КОНЕЦ 1, ОШИБКА 1, ОСТАНОВЛЕНО 11.

## Типы

```
перечисление ВидВызывающего = Линза | СессияЦикла | ХодЧата | Вратарь
перечисление ВидДействия = Чтение "read" | Запись "write" | Удаление "delete" | Перенос "move" | Поиск "search"
                         | Исполнение "execute" | Сеть "network" | Мышление "think" | СменаРежима "switch_mode" | Другое "other"
перечисление ПроверкаОтвета = Верна | Нарушена | Пуста
перечисление КодСбоя = НетРезультата "no_result" | ОтказМодели "model_refused" | СоединениеОборвалось "connection_lost"
                     | ФормаНеИсправлена "form_not_fixed" | НетОтветаВСрок "timeout" | ОстановленоЧеловеком "stopped_by_human"
                     | ПотолокЗаходов "ceiling_reached" | ОтмененоРодителем "cancelled" | ПредельТокенов "max_tokens"
                     | ПредельЗапросовХода "max_turn_requests"

тип МодельАгента { идентификатор текст, поставщик текст, вариант ?текст }
тип Токены { вход ?число, выход ?число, рассуждение ?число, кэш_чтение ?число, кэш_запись ?число }
тип ПрофильАгента { семья текст, модель текст, усилие ?текст }
тип ПределыАгента { срок_тишины ?число, бюджет_токенов ?число, бюджет_стоимости ?дробное, предел_ходов ?число }
тип ЗапросАгента { вид ВидВызывающего, профиль ПрофильАгента, сессия текст, вид_диалога текст, контекст текст,
                   пределы ПределыАгента, трасса текст, номер_шага число }
тип РасходТранспорта { модель МодельАгента, токены Токены, стоимость ?дробное, занято_контекста ?число, начало_запроса число }
тип Использование { сессия текст, результат текст, семья текст, модель МодельАгента, токены Токены, стоимость ?дробное,
                    создано число, обновлено число, занято_контекста ?число, трасса текст, номер_шага число }
тип ОтветАгента { текст ?текст, артефакт ?текст, использование Использование, начало_запроса ?число }
тип ЗапросРазрешения { вид_действия ВидДействия, описание текст }

вариант ИтогХода {
  Закончен { текст ?текст, артефакт ?текст, расход РасходТранспорта }
  Обрезан { расход РасходТранспорта }
  ПределЗапросов { расход РасходТранспорта }
  МодельОтказалась { расход РасходТранспорта }
  Отменён { расход РасходТранспорта }
  ВременнаяОшибка
  ПостояннаяОшибка
  НужноРазрешение { запрос_разрешения ЗапросРазрешения }
}
```

Типы конверта (запрос, ответ, отказ) не объявляются: их собирает исполнитель; машина пишет только `Ответ(значение)` и `Отказ(код, текст)` (раздел «Концы»). Источник называет «дробное» неотрицательным; формат границу у дробного не выражает, поэтому поля `?дробное` — без границы, как в коде. Слова значений `ВидДействия` и `КодСбоя` — слова журнала и провода; у `ВидВызывающего` и `ПроверкаОтвета` слов в источнике нет, в записи данных они идут именем значения.

## Параметры

| имя | тип | по умолчанию | переопределение проектом |
|---|---|---|---|
| ПАУЗА_ПОВТОРА | число≥0 | 2000 | проект.пауза_повтора |
| ПОЛИТИКА_РАЗРЕШЕНИЙ | полный словарь[ВидДействия, "allow" \| "deny" \| "ask"] | {ВидДействия.Чтение: "ask", ВидДействия.Запись: "ask", ВидДействия.Удаление: "ask", ВидДействия.Перенос: "ask", ВидДействия.Поиск: "ask", ВидДействия.Исполнение: "ask", ВидДействия.Сеть: "ask", ВидДействия.Мышление: "ask", ВидДействия.СменаРежима: "ask", ВидДействия.Другое: "ask"} | проект.политика_разрешений |

Источники называют оба значения параметром проекта, но ключа проекта не дают: в столбце `—`. Значение `ПАУЗА_ПОВТОРА` принято владельцем в источнике, заглушкой не является. Значения `ПОЛИТИКА_РАЗРЕШЕНИЙ` — `"allow"`, `"deny"`, `"ask"`: набор литералов стоит в аргументе типа словаря.

## Вход

| имя | тип | примечание |
|---|---|---|
| вид | ВидВызывающего | вид вызывающего |
| профиль | ПрофильАгента | профиль агента; у вызывающего — столбец `профиль` его «Сторон» |
| сессия | текст | сессия агента |
| вид_диалога | текст | вид диалога |
| контекст | текст | контекст хода |
| пределы | ПределыАгента | пределы шага |
| трасса | текст | трасса вызывающего |
| номер_шага | число | номер шага вызывающего |

Поля входа — ровно поля `ЗапросАгента`: вызывающие называют сторону `machine шаг_агента(вход ЗапросАгента, итог ОтветАгента)`, и поля их запроса — поля этого типа (формат, раздел 1, «Вход вызываемой машины»). Запись `запрос_агента` целиком собирает `начальное` в «Данных». Инварианта входа нет. Идентификатор запроса вызова (`запрос_вызова`) во входе не лежит: его даёт исполнитель.

## Данные

Данные фрагмента «Пауза» (`предыдущее`, `запрос_вызова`, `открытые_запросы`) входят из фрагмента и здесь не повторяются (раздел «Подключения»); в `все_данные` они идут первыми. Данные исполнителя (`состояние`, `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `принятые_запросы`, журнал) и хранилища (`слова_человека`, `тексты_сбоев`) в таблицу не вносятся.

| имя | тип | начальное | не убывает | пишет |
|---|---|---|---|---|
| запрос_агента | ЗапросАгента | ЗапросАгента { вид: вход.вид, профиль: вход.профиль, сессия: вход.сессия, вид_диалога: вход.вид_диалога, контекст: вход.контекст, пределы: вход.пределы, трасса: вход.трасса, номер_шага: вход.номер_шага } | — | строки |
| ход | "first" \| "retry" \| "continue" \| "fix" \| "permission" | "first" | — | строки |
| число_повторов | число≥0 | 0 | да, ≤ ЧИСЛО_ПОВТОРОВ | строки |
| число_продолжений | число≥0 | 0 | да, ≤ ЧИСЛО_ПРОДОЛЖЕНИЙ | строки |
| число_возвратов | число≥0 | 0 | да, ≤ ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | строки |
| число_ходов | число≥0 | 0 | да | строки |
| ход_до_повтора | ?("first" \| "retry" \| "continue" \| "fix" \| "permission") | пусто | — | строки |
| расход | ?РасходТранспорта | пусто | — | строки |

| начато | ?число | пусто | — | строки |

Границу `число_ходов ≤ предел ходов` не пишем: при пределе меньше 1 СТАРТ ставит 1, и граница в источнике неверна для части значений. Значение `ход` машина не читает для ветвления (по нему ветвится транспорт); `ход_до_повтора` хранит ход, который повторяется после временной ошибки. `остановка` пишут строки машины и фрагмент «Пауза» (`pause_halt`, `cancel_request`).

## Стороны

| имя | идентификатор | вид | профиль | слова ворот | счётчик |
|---|---|---|---|---|---|
| агент | agent | agent(итог ИтогХода) | — | — | попытка_агента |
| вратарь | gatekeeper | human или agent по настройке исполнитель_повышенного_внимания(итог ИсходВорот) | — | разрешить, отказать | попытка_вратаря |
| усиленный | enhanced | enhanced(итог ИсходВорот) | — | продолжить(слово_человека текст, автор текст, источник текст), остановить | попытка_усиленного |

- Предел запросов: 1

Профиль агента лежит внутри `запрос_агента.профиль` и уходит стороне как часть этого поля; отдельного поля `профиль` в запросе кода нет, поэтому столбец — `—`. Вратарь — человек по умолчанию, агент по настройке проекта `исполнитель_повышенного_внимания`; усиленный — сторона состояния ПАУЗА (человек по умолчанию, усиленный вратарь по разрешению владельца).

## Определения

```
определение сумма_целых(а ?число, б ?число) -> ?число =
  если есть(а) и есть(б) то (а ?? 0) + (б ?? 0) иначе а ?? б

определение сумма_дробных(а ?дробное, б ?дробное) -> ?дробное =
  если есть(а) и есть(б) то (а ?? 0.0) + (б ?? 0.0) иначе а ?? б

определение сложить_токены(а Токены, б Токены) -> Токены =
  Токены { вход: сумма_целых(а.вход, б.вход), выход: сумма_целых(а.выход, б.выход),
           рассуждение: сумма_целых(а.рассуждение, б.рассуждение),
           кэш_чтение: сумма_целых(а.кэш_чтение, б.кэш_чтение), кэш_запись: сумма_целых(а.кэш_запись, б.кэш_запись) }

определение сложить_расход(прежний ?РасходТранспорта, новый РасходТранспорта) -> РасходТранспорта =
  если есть(прежний)
  то (пусть п = обязательно(прежний) в
        РасходТранспорта { модель: новый.модель, токены: сложить_токены(п.токены, новый.токены),
                           стоимость: сумма_дробных(п.стоимость, новый.стоимость),
                           занято_контекста: новый.занято_контекста, начало_запроса: новый.начало_запроса })
  иначе новый

определение израсходовано_токенов(р ?РасходТранспорта) -> число =
  если есть(р)
  то (пусть п = обязательно(р) в (п.токены.вход ?? 0) + (п.токены.выход ?? 0) + (п.токены.рассуждение ?? 0))
  иначе 0

определение израсходовано_стоимости(р ?РасходТранспорта) -> дробное =
  если есть(р) то (обязательно(р).стоимость ?? 0.0) иначе 0.0

определение предел_токенов_исчерпан(з ЗапросАгента, р ?РасходТранспорта) -> да/нет =
  есть(з.пределы.бюджет_токенов) и израсходовано_токенов(р) >= (з.пределы.бюджет_токенов ?? 0)

определение предел_стоимости_исчерпан(з ЗапросАгента, р ?РасходТранспорта) -> да/нет =
  есть(з.пределы.бюджет_стоимости) и израсходовано_стоимости(р) >= (з.пределы.бюджет_стоимости ?? 0.0)

определение предел_ходов_исчерпан(з ЗапросАгента, ходов число≥0) -> да/нет =
  ходов >= (з.пределы.предел_ходов ?? ПРЕДЕЛ_ХОДОВ)

определение интерактивный(вид_вызова ВидВызывающего) -> да/нет =
  вид_вызова == ВидВызывающего.СессияЦикла или вид_вызова == ВидВызывающего.ХодЧата

определение требует_повышенного_внимания(вид_действия ВидДействия) -> да/нет =
  выбор вид_действия { ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима → истина;
                       иначе → ложь }

определение решение_по_политике(вид_действия ВидДействия, вид_вызова ВидВызывающего) -> "allow" | "deny" | "ask" =
  пусть по_таблице = (если требует_повышенного_внимания(вид_действия) то "ask" иначе ПОЛИТИКА_РАЗРЕШЕНИЙ[вид_действия]) в
  если по_таблице == "ask" и не интерактивный(вид_вызова) то "deny" иначе по_таблице

определение пауза_повтора(п число≥0) -> число =
  свёртка(диапазон(1, п), ПАУЗА_ПОВТОРА, (н, _) → н * 2)

определение срок_хода(з ЗапросАгента, ход_запроса текст, повторов число≥0) -> число =
  пусть добавка = (если ход_запроса == "retry" то пауза_повтора(повторов) иначе 0) в
  пусть срок = з.пределы.срок_тишины в
  если есть(срок) то (срок ?? 0) + добавка иначе 0

определение собрать_использование(з ЗапросАгента, ост текст, р ?РасходТранспорта, нач ?число, обн число) -> Использование =
  пусть результат_шага = (если ост == "" то "reply" иначе ост) в
  Использование {
    сессия: з.сессия, результат: результат_шага, семья: з.профиль.семья,
    модель: (если есть(р) то обязательно(р).модель
             иначе МодельАгента { идентификатор: з.профиль.модель, поставщик: "", вариант: з.профиль.усилие }),
    токены: (если есть(р) то обязательно(р).токены
             иначе Токены { вход: пусто, выход: пусто, рассуждение: пусто, кэш_чтение: пусто, кэш_запись: пусто }),
    стоимость: (если есть(р) то обязательно(р).стоимость иначе пусто),
    создано: нач ?? обн, обновлено: обн,
    занято_контекста: (если есть(р) то обязательно(р).занято_контекста иначе пусто),
    трасса: з.трасса, номер_шага: з.номер_шага }

определение событие_расхода(u Использование) -> СобытиеЖурнала =
  событие_журнала("agent_usage", session: u.сессия, result: u.результат, model: u.модель.идентификатор,
                  input: текст(u.токены.вход), output: текст(u.токены.выход), reasoning: текст(u.токены.рассуждение),
                  cache_read: текст(u.токены.кэш_чтение), cache_write: текст(u.токены.кэш_запись), cost: текст(u.стоимость))
```

Соответствие коду автомата: `sum_ints` — `сумма_целых`, `sum_floats` — `сумма_дробных`, `add_tokens` — `сложить_токены`, `add_usage` — `сложить_расход`, `tokens_spent` — `израсходовано_токенов`, `cost_spent` — `израсходовано_стоимости`, `token_limit_reached` — `предел_токенов_исчерпан`, `cost_limit_reached` — `предел_стоимости_исчерпан`, `turn_limit_reached` — `предел_ходов_исчерпан`, `interactive` — `интерактивный`, `needs_elevated_attention` — `требует_повышенного_внимания`, `project_policy` — параметр `ПОЛИТИКА_РАЗРЕШЕНИЙ`, `decision_by_policy` — `решение_по_политике`, `retry_pause` — `пауза_повтора`, `turn_term` — `срок_хода`, `action_kind_word` — `текст(ВидДействия)` (слова в перечислении), `number_word` и `float_word` — `текст(x)` (пусто — `none`), `usage_event` — `событие_расхода`, `collect_usage` — `собрать_использование`. `record_end_usage` и `journal_machine_data` — не функции, а действия в «При входе» концов; `reply_validation`, `close_agent_turn`, `time_now` — примитивы (раздел «Примитивы»).

## Раскрытие фрагмента «Пауза»

Справка читателю; разбор раздел пропускает. Фрагмент подставлен в машину: `<слово_остановки>` = `остановить`, `<код_остановки>` = `"pause_halt"`; параметр `вложенные` остаётся в строках именем со значением `[]`. Состояния, события и данные фрагмента — состояния, события и данные машины; объявлять их в разделах машины не нужно и нельзя.

### Параметры подключения

Все шесть параметров названы, виды и значения подходят. Значения параметров:

| параметр | вид | значение здесь | что значит |
|---|---|---|---|
| слово_остановки | слово | остановить | слово ворот стороны «усиленный», останавливающее машину |
| код_остановки | текст | "pause_halt" | значение `остановка` при остановке паузой |
| вложенные | []машина | [] | вложенных машин у шага нет: транспорт агента и человек — стороны запросов |
| отмена_запросов | поведение | прекратить_ход_транспорта | отмена открытых запросов без принятого ответа; ход у транспорта прекращается; удержанный до решения о разрешении ход закрывает `вызвать(close_agent_turn)` в концах машины |
| вход_заново | поведение | ничего | повторный вход в сохранённое состояние — только по правилу 12 спецификации |
| право_записи | примечание | текст | исполнитель не вычисляет |

### Обязывает

`остановка` содержит `"pause_halt"` и `"cancel_request"`; в «Концах» — строки для обоих значений (коды `ОстановленоЧеловеком` и `ОтмененоРодителем`: ОСТАНОВЛЕНО № 10 и № 11); концы ОСТАНОВЛЕНО и ОШИБКА; в «Сторонах» — сторона `усиленный` вида `enhanced` со словами `продолжить(слово_человека текст, автор текст, источник текст)` и `остановить`. Значение `предыдущее` — всегда обращение (ХОД_АГЕНТА или РАЗРЕШЕНИЕ): машина стоит только в обращениях и концах, а в концах и в ПАУЗЕ ОБЩ 1 и ОБЩ 2 условием отброшены.

### Данные фрагмента

| имя | тип | начальное | не убывает | пишет |
|---|---|---|---|---|
| предыдущее | ?Состояние | пусто | — | фрагмент |
| запрос_вызова | текст | "" | — | механика |
| открытые_запросы | []текст | [] | — | механика |

`слова_человека` — хранилище исполнителя (правило 31 спецификации), в таблицу не вносится и в `все_данные` не входит.

### Общие события

Разбираются до строк состояний (правило 23 спецификации). «Продолжить» и «остановить» (и от родителя) вне ПАУЗЫ — лишние сигналы: исполнитель отбрасывает их с записью в журнал.

| № | Событие | Условие | Действия | Куда |
|---|---|---|---|---|
| ОБЩ 1 | сигнал(стоп человека(слово_человека, автор, источник)) | не конец(состояние) и состояние != ПАУЗА | журнал(human_stop, author: автор, source: источник, event: событие.идентификатор); предыдущее = состояние; передать(вложенные, стоп); отменить_открытые(кроме: вложенные) | ПАУЗА |
| ОБЩ 2 | сигнал(стоп от родителя(идентификатор_запроса)) | не конец(состояние) и состояние != ПАУЗА и идентификатор_запроса == запрос_вызова | журнал(pause_by_parent_stop, request: идентификатор_запроса, event: событие.идентификатор); предыдущее = состояние; передать(вложенные, стоп); отменить_открытые(кроме: вложенные) | ПАУЗА |
| ОБЩ 3 | сигнал(отмена_запроса(идентификатор_запроса)) | идентификатор_запроса != запрос_вызова | журнал(cancel_discarded_foreign_request, request: идентификатор_запроса, event: событие.идентификатор) | то же |
| ОБЩ 4 | сигнал(отмена_запроса(идентификатор_запроса)) | идентификатор_запроса == запрос_вызова и конец(состояние) | журнал(cancel_discarded_already_replied, request: идентификатор_запроса, event: событие.идентификатор) | то же |
| ОБЩ 5 | сигнал(отмена_запроса(идентификатор_запроса)) | идентификатор_запроса == запрос_вызова и не конец(состояние) | журнал(request_cancelled, request: идентификатор_запроса, event: событие.идентификатор); остановка = "cancel_request"; передать(вложенные, отмена); отменить_открытые | ОСТАНОВЛЕНО |
| ОБЩ 6 | сигнал(отмена_запроса(идентификатор_запроса)) | иначе | ошибка_машины("cancel_parse_no_match") | — |

### Состояние ПАУЗА

Обращение (`Pause`). Заголовком `### ПАУЗА — …` в `## Состояния` оно не объявляется: состояние приносит подключение.

- Сторона: усиленный
- Срок тишины: —
- Вход:

| поле запроса | выражение | читает |
|---|---|---|
| предыдущее | обязательно(предыдущее) | сторона |
| запрос_вызова | запрос_вызова | сторона |

| № | Событие | Условие | Действия | Куда |
|---|---|---|---|---|
| ПАУЗА 1 | слово(продолжить(автор, источник)) | — | журнал(human_continue, previous: текст(обязательно(предыдущее)), author: автор, source: источник, event: событие.идентификатор); передать(вложенные, продолжить) | предыдущее |
| ПАУЗА 2 | слово(остановить) | — | остановка = "pause_halt"; передать(вложенные, остановить) | ОСТАНОВЛЕНО |
| ПАУЗА 3 | сигнал(продолжить от родителя(идентификатор_запроса)) | идентификатор_запроса == запрос_вызова | журнал(parent_continue, previous: текст(обязательно(предыдущее)), request: идентификатор_запроса, event: событие.идентификатор); передать(вложенные, продолжить) | предыдущее |
| ПАУЗА 4 | сигнал(остановить от родителя(идентификатор_запроса)) | идентификатор_запроса == запрос_вызова | остановка = "pause_halt"; передать(вложенные, остановить) | ОСТАНОВЛЕНО |

- `Куда: предыдущее` ведёт повторным входом в сохранённое состояние (правило 12; параметр `вход_заново: ничего`); `предыдущее` при этом не пишется. Сохранённое состояние — только ХОД_АГЕНТА или РАЗРЕШЕНИЕ: остальные состояния не ждут, и прервать их ОБЩ 1 и ОБЩ 2 не могут.
- Слова «продолжить» и «остановить» вне ПАУЗЫ и их варианты от родителя — лишние сигналы; исполнитель отбрасывает их с записью в журнал (правило 17).
