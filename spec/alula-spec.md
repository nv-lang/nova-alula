# Алула (`Alula`): спецификация языка записи стейт-машины таблицами, версия 2.25

Английская версия: [spec/alula-spec.en.md](alula-spec.en.md) (перевод; нормативен русский текст).

История изменений — [spec/alula-changelog.md](alula-changelog.md): что изменилось в каждой версии, открытые вопросы, соответствие правилам методики. Здесь — только действующие правила языка.

Имя языка записи — **«Алула»** (`Alula`; слово владельца, 2026-10-21: «Alula - ОК»). Читается «Алу́ла», ударение на «у»; женского рода, склоняется как «Луна»: Алулы, Алуле, Алулу, Алулой, на Алуле. Алула — звезда в лапе Большой Медведицы (имя в каталоге IAU), от арабского *al-qafza al-ūlā*, «первый прыжок» (звёзды «трёх прыжков газели»: Alula, Tania, Talitha); прыжок — переход машины из состояния в состояние. Второе, независимое значение — английское *alula*, «крылышко» (лат. *ala*, «крыло», и уменьшительный суффикс *-ula*): пучок перьев на первом пальце птичьего крыла, которым птица управляет полётом на малой скорости. Файл машины — «таблица машины» на Алуле. Занятость имени проверена 2026-10-21: знаков ALULA на языки и средства разработки не найдено (знаки ALULA в классах 9/42 — у нескольких узких компаний: охранные системы, страхование, онкология; в России в классах 9/42 их нет, TMview); пространства имён `alula-lang` (GitHub, домены, пакеты) свободны; ручная проверка реестра Роспатента — открытый пункт. Прежнее имя языка (версии 2.7–2.13) и почему от него отказались — в истории [doc/alula-history.md](../docs/history.md), раздел 10; там же причины, цели и история языка.

Версия формата: 2.25, 2026-10-26. Статус: **опытный формат; версия 2.2 реализована интерпретатором на другом языке; равенство с автоматом по журналу подтверждено на 39 сценариях одной небольшой машины (машина чата); выразимость «Шага агента» и «Совещания» проверена пилотами; не реализовано: вложенные машины, `Правит`, профиль стороны, `Предел запросов`, `Возвратов формы`, `передать`.** Правила записи машин — [state-machine-spec.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-spec.md); этот файл задаёт формальную запись тех же таблиц: типы, выражения, действия, стороны, фрагменты. Журнал — [state-machine-journal.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-journal.md); словарь английских имён — [state-machine-glossary.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-glossary.md) (словарь автоматических JSON-имён, раздел 1а). При расхождении с правилами спецификации верна спецификация, а этот файл правится вслед за ней.

Цель: машина описывается одним файлом без кода на Нова; исполнитель по описанию даёт то же поведение, что автомат на Нове: те же переходы, тот же структурный журнал, те же данные и очередь. Проверено выразимостью строк автоматов (какие строки записываются без обходов) и прогоном одной небольшой машины интерпретатором (сравнение с автоматом по журналу, шапка).

Примеры взяты из пилотов (выписки «Шага агента» и «Совещания»). Конструкция, использованная в примере, определена в разделах 2–5, 7–9 или в каталоге (раздел 12). Примеры — выдержки: раздел `## Имена` (1а) в них не показан, кроме примера в разделе 1а; где имя примера получило бы в файле машины не автоматическое JSON-имя, строка `## Имена` названа под примером (образцы несут раздел целиком).

## 1. Файл машины

Ключевые слова этого раздела (заголовки разделов, имена столбцов, строки-ключи, виды сторон) — слова русской формы; в английской форме файла их пишут по [таблице слов](alula-keywords.tsv), правила — раздел 1а.

**Расширение.** Файл машины на Алуле называется `*.alula.md` (имя машины — латинское, как в `- machine:`; например `agent_step.alula.md`); прежние имена `*.table.md` и `*.table.txt` не употребляются, переходного периода нет (слово владельца, 2026-10-19: «нету переходного периода»; версия 2.11). Расширение разбор не проверяет: проверку расширения выполняет только скрипт проверки форматирования. Файл функций и файл фрагмента — тоже `*.alula.md` с шапкой своего вида. **Скомпилированное дерево** (JSON `machine/2`, раздел 6) называется `<имя>.alula.json`: `agent_step.alula.md` ↔ `agent_step.alula.json`; это не отдельный формат, а исполняемая форма самого языка — рукописное дерево тоже Алула, записанная в JSON-виде; `format: "machine/2"` внутри дерева не меняется. Прежнее `*.machine.json` не употребляется, переходного периода нет. Версию машины (`- machine_version:`) задаёт автор файла; рекомендуется строка вида `alula-<версия формата>` (например `alula-2.25`) — она отвечает на вопрос «на каком языке и какой версии записана машина»; вызывающий сверяет её только на равенство с записью реестра (протокол вызова, раздел B, пункт 6).

Markdown, разделы по порядку:

| Раздел | Содержимое |
|---|---|
| шапка | `# Машина: <Имя>`; элементы списка `- machine: <латинское_имя>`, `- machine_version: <строка>`, `- format: 2.25`, необязательно `- language: ru` или `- language: en` (1а; маркер `- ` необязателен при разборе; в записи обязателен: markdown склеивает идущие подряд строки) |
| `## Типы` | записи и перечисления, в том числе с полями у форм (раздел 2) |
| `## Имена` | необязательно: таблица `\| имя \| JSON-имя \|` — JSON-имена, отличные от автоматических (1а); нет таких имён — раздела нет |
| `## Константы` | `имя`, `тип`, `значение` |
| `## Параметры` | `имя`, `тип`, `по умолчанию`, `переопределение проектом` (`проект.<ключ>`); значение по умолчанию обязательно: если источник даёт заглушку, пишется она с пометкой «заглушка источника»; ключ проекта, которого источник не называет, — `—`; передача значений извне — ниже |
| `## Вход` | поля входа вызова: `имя`, `тип`, примечание; строки `Инвариант: <булево выражение над полями>`; значение входа — имя `вход` |
| `## Данные` | `имя`, `тип`, `начальное`, `не убывает`, `пишет` (раздел 2) |
| `## Стороны` | см. ниже |
| `## Функции` | чистые функции автора, объявление `функция` (раздел 8) |
| `## Подключения` | **только** строки подключения: фрагменты (раздел 9) и файлы функций `функции: <имя> версия <N> хеш <hex12>` (раздел 8); без прозы и списков |
| `## Состояния` | первая строка `Начальное состояние: ИМЯ`, затем состояния (раздел 4) |
| `## Концы` | таблица «конец → ответ» (4.7) |
| `## Внешние функции` | объявления внешних функций хозяина, которые зовёт машина: `внешняя функция имя(арг тип, …) [<класс>] [-> тип]` без тела (раздел 7) |

**Таблицы**. Строка-разделитель под заголовком таблицы (`|---|---|`, `|:---|---:|`) — строка из знаков `-`, `:`, пробелов и `|`; разбор её пропускает. Знак `|` внутри ячейки пишется `\|` (набор литералов `"a" \| "b"`, альтернативы `выбор`); разбор снимает экранирование. В примерах формата разделитель опущен.

**Комментарий `//`** (как голое `//` Новы, D104). В блоке кода (между ограждениями ```) и в строке заголовка `##` или `###` — после текста заголовка (`## Общие события     // разбираются до строк состояний`) — знак `//` вне текстового литерала начинает комментарий до конца строки: разбор и проверки его не читают, в дерево он не входит, генератор его не пишет (1б). `//` внутри литерала — текст (`"http://x"`): комментарий ищется после разбора литералов строки. В ячейке кода таблицы (столбцы кода: действия, выражение, условие, «когда», «ответ», «значение», «начальное», «по умолчанию», «профиль», «не убывает»; ячейка события) и в строке-ключе (`- Кроме: …`) комментария нет: `//` вне литерала там — ошибка проверки; в столбцах прозы («примечание») `//` — обычный текст, ссылки `https://…` допустимы; пояснение к строке таблицы — столбец «примечание» или абзац прозы (4.1). Оператора `//` в языке нет (деление — `/`, 3.1). Doc-комментарии Новы `///` и `//!` не вводятся: `///` — тоже обычный комментарий.

**`## Параметры`: передача значений извне**. Исполнитель принимает переопределения параметров таблицей «ключ → значение»: ключ — `проект.<ключ>` из столбца «переопределение проектом»; значение проверяется по типу параметра (полный словарь — по правилам раздела 2), ключ, которого нет в столбце, — отказ загрузки. Это механизм передачи; откуда исполнитель берёт таблицу (настройки проекта, `params` сценария, раздел 11), формат не задаёт. Ключи `проект.<ключ>` называет продукт, они не часть языка; столбец «переопределение проектом» образца остаётся `—`, потому что источник ключей не называет. Значение по умолчанию, зависящее от внешнего ключа, действует только при наличии ключа в таблице переопределений, иначе работает значение по умолчанию.

**`## Вход`.** Тип входа — запись из полей этого раздела (правило 35, пункт 1); `начальное: вход.<поле>` берёт значение из входа. Необязательное поле (тип `?T`), которого во входе нет, равно `пусто`. Инвариант проверяет исполнитель при приёме запроса; нарушение — отказ вызова: исполнитель пишет событие журнала `input_rejected` и завершает вызов отказом `NoResult` с текстом `input rejected: <reason>`; состояние машины не меняется. Тот же отказ — при разборе входа. Параметры события (журнал, подраздел «События формата таблиц»): `reason` — закрытый перечень `json` (вход не JSON), `missing` (нет обязательного поля входа; у необязательного отказа нет), `type` (поле другого типа, вне границы типа, вне набора литералов или не `ид` формата UUID, например `число>=0` при −1), `invariant` (нарушен инвариант входа); `field` — имя поля входа (для `missing` и `type`); `index` — номер инварианта с нуля (для `invariant`). `field` и `index` необязательные: при `json` их нет, и шаблон их пропускает. Примеры: `input_rejected(reason=json)`, `input_rejected(reason=missing; field=label)`, `input_rejected(reason=type; field=start)`, `input_rejected(reason=invariant; index=0)`. Идентификатор запроса вызова (`запрос_вызова`) в входе не лежит: его даёт исполнитель (раздел 9).

**Вход вызываемой машины и `вход Тип` вызывающей**. Сторона `machine <имя>(вход Тип, …)` называет тип записи, поля которой — ровно поля `## Вход` вызываемой машины: те же имена и типы, порядок не значим; поля запроса — поля этого типа, кроме `профиль` (4.2). Поэтому вход, который вызывающие передают полями (`вид`, `сессия`, `контекст`, …), вызываемая объявляет теми же полями, а не одним полем-записью; запись целиком, если она нужна в данных, собирает `начальное` конструктором записи (`ЗапросАгента { вид: вход.вид, … }`, образец «Шага агента»). Типы полей сравниваются по совместимости раздела 2: `число` и `число>=n` совместимы в обе стороны — поле `число` у вызывающей и `число>=0` у вызываемой (или наоборот) — одно поле, границу проверяет вызываемая при приёме входа (`input_rejected`, `reason=type`). Сверка типов двух файлов — продукт (см. [журнал изменений](alula-changelog.md), «Открытое»).

**`## Стороны`.** Таблица `| имя | идентификатор | вид | профиль | сигналы | счётчик |`.

| Вид | Что это |
|---|---|
| `agent(итог Тип)` | агент; `итог` — тип результата стороны |
| `human(итог ИсходВорот)` | человек: на воротах (со счётчиком) или со свободным вводом (`—` в столбце `счётчик`) |
| `enhanced(итог ИсходВорот)` | усиленный вратарь |
| `human или agent по настройке <имя>(итог ИсходВорот)` | вратарь: человек, агент — по настройке проекта (правило 19); `<имя>` — ключ настройки проекта, он выходит из машины: его JSON-имя строится по 1а, а где оно неверно, задаётся строкой `## Имена` (`\| исполнитель_повышенного_внимания \| elevated_attention_executor \|`: транслитерация дала бы `ispolnitel_povyshennogo_vnimaniya`); английская запись — `human or agent by setting <имя>(result GateOutcome)`; в дереве JSON этот вид называется `gatekeeper` |
| `machine <имя>(вход Тип, итог Тип)[; разбор: <внешняя функция> -> Тип]` | вложенная машина (правило 35): имя из реестра вызывающего (правило 35, [протокол вызова](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-call-protocol.md), раздел J, пункт 6), тип входа запроса, тип результата ответа; необязательный разбор результата (см. ниже) |

- `идентификатор` — латинское слово стороны: у сторон машин методики — значение «сторона запроса» словаря ([state-machine-glossary.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-glossary.md), раздел 2.14: `agent`, `gatekeeper`, `enhanced`, `witness`, `author`, `session_launch`, `review`, `meeting`, `agent_step`), сторона, которой там нет, берёт своё латинское слово (пример стороны со свободным вводом ниже — `human`); входит в конверт запроса и ответа и в идентификатор запроса (`<идентификатор>-<номер>`), поэтому попадает в журнал. У стороны с набором (4.2) — `—`: идентификатором служит элемент набора. Идентификаторы сторон машины различны.
- **`итог`** — тип результата стороны: у `agent` — тип из `## Типы` или встроенный тип (слово типа раздела 2: `строка`, `число`, `булево`, …; английское `str`, `int`, `bool`), у `machine` — так же; у `human`, `enhanced` и вратаря — встроенное перечисление с полями `ИсходВорот`, формами которого служат сигналы столбца «сигналы» (сигнал без данных — форма без полей, `сигнал { поле тип }` — форма с полями, запись та же; правило 19), событие `сигнал(…)` стороны — форма `ИсходВорот`. `ответ: Форма` разрешается по `итог` стороны (у `machine` с `разбор` — по результату разбора); допустима квалифицированная форма `ответ: ИтогХода.Закончен { … }`, тип в ней — тип результата стороны; неквалифицированное имя формы ищется только в этом типе.
- `профиль` — выражение либо `—`; **единственный источник профиля**: поле запроса `профиль` исполнитель берёт отсюда, строка `профиль` в «Запросе» — ошибка проверки. Столбец читает данные машины, константы, параметры, `вход` и (у набора) `сторона`; допустим вызов изменчивой внешней функции `имя(арг)` (раздел 7), её скрытые чтения (по реестру хозяина) — данные машины; имена `Запрос` состояния столбец не читает: таблица «Сторон» одна на машину, правило 11 к ней не применяется. Если профиль лежит внутри запроса (у стороны `агент` — `запрос_агента.профиль`), отдельного поля у стороны нет и пишется `—`.
- `счётчик` (правило 15) — **обязателен у каждой стороны, кроме стороны со свободным вводом**: данное, где лежит счётчик попыток стороны, — имя данного (`попытка_агента`) либо, у стороны с набором, путь поля записи элемента (`линзы[*].попытка`). Данное — `число>=0`, начальное `0`, `не убывает: да`, `пишет: механика`; у пути поля начальное `0` задаёт строка данного с записью элемента (`попытка: 0` в `линзы`, раздел 2), а у пути в таблице «Данных» `начальное` — `—`; номер попытки запроса равен значению счётчика после увеличения (механика, до отправки; у ворот человека — до показа ворот, правило 19), идентификатор запроса — `<идентификатор>-<номер>` (у набора — `<элемент набора>-<номер>`). Проверка раздела 10 сверяет данное.
- **Сторона со свободным вводом** (правило 19) — сторона вида `human` со `—` в столбце `счётчик` (`—` — знак «нет значения», 1б): ворот у неё нет; человек отвечает ей **словом свободного ввода** — сигналом стороны без ворот: идентификатора ворот оно не несёт, принимается по имени сигнала строкой текущего состояния и ведёт переход (что такое слово — ниже, `сигналы`); записи ворот нет, счётчика нет; вратарь-агент ей не отвечает, поэтому `—` допустим только у вида `human`. Сторона `human` со счётчиком — ворота (правило 19). Пример: `| собеседник | human | human(итог ИсходВорот) | — | сообщение { содержание строка, автор строка, источник строка } | — |`.
- `сигналы` — у видов `human`, `enhanced`, вратаря: **сигналы стороны** — то, что сторона говорит машине на воротах: сигнал или `сигнал { поле тип, … }` — сигнал с данными (поля в фигурных скобках, как у формы перечисления; прежняя запись `сигнал(поле тип)` — ошибка); сигналы пишутся как в таблицах машины (в том числе из нескольких слов: `остановить совещание`); JSON-имя сигнала и его полей строится по 1а, а где оно неверно, задаётся строкой `## Имена`: у `засчитан { находки []Находка }` словарь даёт сигналу `counted`, полю `находки` — `findings`, строк не нужно; поле сигнала объявляется в фигурных скобках через пробел, а в строке перехода привязывается `сигнал(засчитан { находки: новые })` (3.1). Объявление и называет, какая сторона может подать сигнал: это **все сигналы стороны**; сигналы состояния — сигналы его строк (4.3). Сигнал стороны — событие стороны из её объявленного набора (у `human`, `enhanced` и вратаря — форма `ИсходВорот`); он относится к открытому запросу этой стороны, а когда отвечает человек — к её открытым воротам и несёт их идентификатор, так, как говорят правила 15–19 спецификации (счётчик попыток, приём ответа, слова человека); идентификатор ворот `<идентификатор>-<номер>` называет сторону, и сигнал сверяется с сигналами этой стороны: не объявленный ею или пришедший от другой стороны отбрасывается («слово чужой стороны», правила 17, 19); сигнал стороны со свободным вводом идентификатора ворот не несёт и принимается по имени в текущем состоянии (правило 19). От сигнала машины (общие события, раздел 9) он отличается объявлением у стороны и тем, кто может его подать. **Слово** — текст, который пишет человек, чтобы ответить; слово несёт один из сигналов стороны: на воротах слово — один из сигналов стороны, несёт идентификатор ворот и принимается один раз; у стороны со свободным вводом слово принимается по имени сигнала строкой текущего состояния, идентификатора ворот нет. У остальных видов — `—`.
- **`разбор`** — только у вида `machine`: изменчивая внешняя функция (раздел 7) с единственным параметром типа `итог` и результатом указанного типа; пишется именем без скобок и аргументов (`разобрать_ответ_автора`): у каждой роли своя функция, второго аргумента-роли нет. Исполнитель вызывает её при приёме ответа (правило 14), после проверки «Правит» (4.2) и до «При приёме», и **значением ответа** для `ответ(имя)`, `ответ: Форма { … }` и «При приёме» становится результат разбора; без `разбор` — сам `итог`. Событие `ответ: Форма` требует, чтобы значение ответа было значением перечисления. Скрытые чтения функции (`читает` в реестре хозяина) входят в чтения состояния (`Запрос`, правило 11); разбор вызывается один раз за ответ, результат хранится с принятым событием. Разбор по роли — отдельная функция на роль (раздел 7).
- **Сбой разбора**. Разбор либо даёт значение указанного типа, либо отказывает: ответ не по форме (артефакт не читается, нет выдержек, сверка не сошлась); замечания отказа — служебная запись, которую читает возврат стороны. Отказ разбора — ответ не по форме (правило 18): событие не возникает, «При приёме» не выполняется, в `принятые_запросы` ответ не пишется; пока возвратов меньше «Возвратов формы» (4.2), исполнитель возвращает ответ стороне (у `machine` — новым запросом той же стороны с замечанием); после исчерпания, а при `Возвратов формы: 0` сразу, запрос закрывается событием `сбой` с кодом `КодСбоя.ФормаНеИсправлена` (код вне списка состояния исполнитель приводит к `НетРезультата`, 4.3). Возврат и его запись в журнал — механика исполнителя (коды журнала продукта — раздел 5). Значение не того типа, что назван после `->`, — дефект хозяина, то есть дефект программы (3.3), а не ответ не по форме.
- Под таблицей — элемент списка `- Предел запросов: <выражение типа число>=1>` (одна на машину, правило 21; не написана — 1).

Пример (пилоты; `human или agent по настройке` и сигналы — «Шаг агента», `machine`, разбор и сигналы с данными — «Совещание»). Сигналы сторон — столбец «сигналы», поля сигнала — в фигурных скобках; сигналы усиленного — по фрагменту «Пауза» (раздел 9); профиль агента — внутри `запрос_агента`, поэтому `—`.

```
| имя | идентификатор | вид | профиль | сигналы | счётчик |
| агент | agent | agent(итог ИтогХода) | — | — | попытка_агента |
| вратарь | gatekeeper | human или agent по настройке исполнитель_повышенного_внимания(итог ИсходВорот) | — | разрешить, отказать | попытка_вратаря |
| усиленный | enhanced | enhanced(итог ИсходВорот) | — | продолжить { слово_человека строка, автор строка, источник строка }, остановить | попытка_усиленного |

- Предел запросов: 1

| свидетель | witness | machine шаг_агента(вход ЗапросАгента, итог ОтветАгента); разбор: разобрать_ответ_свидетеля -> []ОтветСвидетеля | профиль_стороны("witness") | — | попытка_свидетеля |
| автор | author | machine шаг_агента(вход ЗапросАгента, итог ОтветАгента); разбор: разобрать_ответ_автора -> ИтогПравки | профиль_стороны("author") | — | попытка_автора |

| усиленный | enhanced | enhanced(итог ИсходВорот) | — | продолжить { слово_человека строка, автор строка, источник строка }, остановить совещание | попытка_усиленного |

## 1а. Язык файла и ключевые слова

Язык Алулы двуязычный: файл `*.alula.md` пишется либо по-русски, либо по-английски. Русская форма — основная; все примеры спецификации записаны в ней. Английская форма — те же конструкции с английскими ключевыми словами; английская спецификация и английский образец машины — отдельные работы, на этот раздел они не влияют.

**Ключевые слова** — слова, которые определяет спецификация: заголовки разделов и шапки, строки-ключи, заголовки столбцов таблиц, виды состояний, слова событий и «куда», слова выражений, действия, функции каталога, литералы `истина`/`ложь`/`пусто`, виды сторон-слов, значения `пишет` и `читает`. Они пишутся **целиком на одном языке — языке файла**. Смешивать нельзя: файл с русскими заголовками и английским действием `journal(…)` — ошибка.

**Языков два, объявляется строкой шапки:** `- language: ru` или `- language: en`. Строка необязательна, по умолчанию `ru`. Правила разбора:

- проверка не гадает и не переключается молча: язык берётся только из строки `language` либо по умолчанию;
- файл с английской шапкой (`# Machine:`, `# Functions:`, `# Fragment:`) без `- language: en` — ошибка проверки («язык шапки английский, а language не объявлен»); так же для русской шапки при `- language: en`;
- ключевое слово не из языка файла — ошибка проверки с номером строки первого постороннего слова.

**Свободно, на любом языке и вперемешку** (это не ключевые слова; вперемешку — по словам, а не внутри слова): имена, которые придумывает автор — данные, состояния, функции, типы, поля, сигналы сторон, параметры фрагментов и их значения; проза-комментарии вне таблиц (4.1); значения-строки внутри данных и коды событий журнала (латиницей по конвенции, правило 34(б)); имена внешних функций (как записаны в реестре хозяина); идентификаторы сторон (`agent`, `human` и т. п.). Ключи шапки (`machine`, `machine_version`, `format`, `functions_version`, `fragment`, `language`) латинские в обоих языках; слова классов внешней функции — `изменчивая` и `действующая` (английские `volatile`, `acting`) — берутся из таблицы слов по языку файла (вид `enum_value`, раздел 7); у чистой внешней функции слова класса в файле нет (латинское `pure` — слово класса в реестре хозяина, а не в файле машины).

**JSON.** Дерево `machine/2` (раздел 6) от языка файла не зависит: ключевые слова обоих языков отвечают одним ключам и значениям, имена входят в дерево JSON-именами (ниже), значения-строки (тексты отказов, сообщения, текстовые литералы) — как их написал автор. Поэтому файлы двух языков с одними JSON-именами и значениями-строками дают одно дерево с точностью до внутренних имён (ниже). Сверка образцов ([tools/check-alula-samples.py](../tools/check-alula-samples.py)) сравнивает JSON-имена объявлений (у русского образца — автоматические и из `## Имена`) и не сравнивает значения-строки.

**JSON-имя** — одно правило и одно место. JSON-имя — имя в дереве `machine/2`, в журнале, в `все_данные` и на проводе. Оно есть у имени, которое объявляет автор и которое выходит из машины: состояние (поле `state` журнала, параметр `fork`, `строка(Состояние)`), данное (`все_данные`, `machine_data`), поле входа, тип, поле записи и формы, форма перечисления с полями, элемент перечисления (провод, `все_данные`), сигнал стороны и его поле (провод, сценарий), внешняя функция (JSON-имя — имя реестра хозяина), имя настройки вратаря (ключ настройки проекта). JSON-имя — строка раздела `## Имена` (ниже), а у имени без строки оно **строится автоматически**:

1. латинское имя (`[A-Za-z_][A-Za-z0-9_]*`) — само имя;
2. иначе, если словарь (ниже) называет всё имя, — английское имя словаря (`число_повторов` → `retry_count`, `ПОВТОР` → `Retry`, `Токены` → `TokenUsage`);
3. иначе — транслитерация имени по таблице ниже с правилом регистра (`оставить правку` → `ostavit_pravku`); каждое слово транслитерируется отдельно, латинское слово остаётся (`запрос_Agent` → `ZaprosAgent` у имени-типа).

**Раздел `## Имена`** — **единственный способ** задать JSON-имя, отличное от автоматического. Таблица `| имя | JSON-имя |` (английская — `| name | json_name |`): в первом столбце — имя, объявленное в этом файле (на любом языке, в том числе латинское), во втором — латинское JSON-имя `[A-Za-z_][A-Za-z0-9_]*`. Строка задаёт JSON-имя каждому объявлению с этим именем в файле; если одно имя объявлено в нескольких местах и JSON-имя нужно не всем, первый столбец — **уточнённое имя**: путь объявленных имён через точку от пространства верхнего уровня — `Тип.поле`, `Тип.Форма`, `Тип.Форма.поле`, `Тип.Элемент`, `сторона.сигнал`, `сторона.сигнал.поле`; строка с уточнённым именем сильнее строки с простым. Имя без строки получает автоматическое JSON-имя. В таблице — **только** имена, чьё автоматическое имя неверно. Ошибки проверки (раздел 10): строка, которая ничего не меняет (её JSON-имя равно имени, которое объявление получает без неё), — «лишняя строка»; строка для имени или пути, которого среди объявлений этого файла, выходящих из машины, нет (внутреннее имя, читаемое имя, опечатка), — «имя не объявлено»; имя, повторённое в первом столбце; нелатинское JSON-имя; совпадение JSON-имён в одном пространстве (ниже). Автоматическое имя, которое не вышло латинским (знак вне таблицы транслитерации), — тоже ошибка: такому имени нужна строка. **Скобок после имён в объявлениях нет** (`### ОТКРЫТИЕ — операция`, `| расход | ?РасходТранспорта | …`, `тип Утверждение { … }`): способ записи один; скобки `имя (X)` версий 2.9–2.15 — ошибка проверки. Раздел пишут файл машины и файл функций — после `## Типы`, файл фрагмента — после `## Данные` (у него нет `## Типы`); каждый файл — для своих объявлений: JSON-имена подключённого файла определяет он сам. Нет строк — раздела нет. В `## Имена` не пишутся путь поля `имя[*].поле` (он составлен из объявленных имён); ключевые и читаемые имена, в том числе данные контракта и фрагмента «Пауза» (`остановка`, `к_отправке`, `открытые_запросы`, `предыдущее`, `запрос_вызова`) и привязка `причина`, — их JSON-имя — слово `en` таблицы слов; **внутренние имена**, которые из машины не выходят, — константы, параметры (их внешнее имя — `проект.<ключ>`), функции и их параметры, имена сторон (их внешнее имя — `идентификатор`), привязки событий и `пусть`, параметры лямбд, переменная `для` — входят в дерево как написаны. Других способов задать JSON-имя нет.

Пример (образец «Совещания»; `Вопрос` — форма и у `ИтогПравки`, и у `КонтекстРоли`, поэтому имя уточнено; `расход` — образец «Шага агента»: строка без уточнения задаёт имя данному и полю пяти форм).

```
## Имена

| имя | JSON-имя |
| Утверждение | Claim |
| ИтогПравки.Вопрос | Asked |
| КонтекстРоли.Вопрос | QuestionContext |
| КонтекстРоли.Свидетель.находки | lens_findings |
| оставить правку | keep_edit |
| расход | transport_usage |
```

**Пространства различимости**. JSON-имена внутри одного пространства различны; совпадение — ошибка проверки, а одно JSON-имя в разных пространствах допустимо. Пространства: (1) состояния машины — вместе с состояниями подключённых фрагментов после подстановки (имена фрагмента входят в пространство состояний машины); (2) данные машины (вместе с данными фрагментов); (3) поля входа; (4) типы верхнего уровня — записи и перечисления (с полями и без) вместе; (5) поля одной записи или одной формы; (6) формы одного перечисления с полями; (7) элементы одного перечисления; (8) сигналы одной стороны и, отдельно, поля одного сигнала; общие события машины (сигналы машины) — отдельное пространство; (9) внешние функции файла машины; (10) параметры, константы и имена настроек вратаря; функции — каждое имя в своём пространстве. (11) **Пространство вызовов**: функции каталога (раздел 12), функции автора и внешние функции; имя функции или внешней функции (как написано, английское имя по 1а, у внешней функции — и JSON-имя) не совпадает со словом функции каталога ни в одном языке и с `range`, а имена в нём различны: функция автора не совпадает с внешней функцией — иначе ошибка проверки; исключение — стандартная внешняя функция `новый_ид`/`new_id` (7а): она стоит и в виде `catalog` таблицы слов (раздел 12), поэтому функция или внешняя функция с этим именем со словами каталога не сверяются; данные, поля и прочие имена в него не входят (3.1). Коды журнала (`журнал("код")`) и номера общих событий в эти пространства не входят.

**Смешанные имена**. Слово имени — часть между `_` и пробелами — пишется буквами одной письменности: только кириллица или только латиница; цифры допустимы в любом слове (`В3`, `v2`). Слово, где смешаны кириллица и латиница (`ЗапросAgent`, `ХодV2`), — ошибка проверки: у такого слова нет однозначной границы для транслитерации и регистра. Смешивать можно только между словами, через `_` или пробел (`запрос_Agent`, `ход_v2`): каждое слово транслитерируется отдельно, латинское слово остаётся как есть (шаг 3).

**Словарь для имён** — словарь английских имён методики [state-machine-glossary.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-glossary.md) (версия 11). Нормативна для имён только его часть «русское имя → английское имя»: строки таблиц разделов 2.1–2.9, 2.11, 2.12 и 2.16 (первый столбец — русское имя, второй — английское, оба в обратных кавычках) и записи `` `русское` → `английское` `` раздела 2.10. Поиск — по всему имени, точным совпадением строки (с регистром, подчёркиваниями и пробелами). **Осторожно:** поиск идёт по всему имени независимо от вида имени, поэтому автоматическое имя латинское, но может оказаться не тем, что задумано (тип `Утверждение` даёт `Approval`, состояние `ИТОГ` — `Totals`, поле `ошибка` — `failure_error`); у машины с английским близнецом расхождение находит сверка образцов, в остальных случаях автор проверяет имя сам и при необходимости пишет строку `## Имена`. Не входят: строковые литералы (2.14), контекстные исключения (2.15), соглашения, заметки и история; имя, которому эти таблицы дают два разных английских имени (одно — `расход`: `usage` и `transport_usage`), записи не имеет: его JSON-имя строится транслитерацией, а нужное пишется в `## Имена`.

**Хеш словаря**. Нормативная часть словаря закреплена хешем, а не номером версии. Текст для хеша: пары нормативной части в порядке файла (строки таблиц разделов 2.1–2.9, 2.11, 2.12, 2.16 — по первым двум столбцам; записи раздела 2.10 — по порядку в строке), каждая — строка `русское → английское` (русское имя, пробел, знак `→`, пробел, английское имя, без обратных кавычек), строки соединены LF (`\n`), после последней LF нет, кодировка UTF-8; хеш — первые 12 знаков SHA-256 этого текста, строчными. Формат 2.25 закрепляет **хеш словаря `35c571ccda17`** версии 13 (у 2.16–2.23 был `60383c370415` для словаря версии 11: в версии 13 три функции по роли заменили `разобрать_ответ_агента`). Проверка ([tools/check-alula-keywords.py](../tools/check-alula-keywords.py)) пересчитывает хеш из файла словаря; другой хеш — ошибка «словарь изменён без смены формата»: новая или изменённая пара меняет автоматические имена, и одна и та же машина дала бы другое дерево. Версия формата и хеш меняются только вместе; правка вне нормативной части (литералы 2.14, исключения 2.15, столбцы «Где», «Источник», «Заметка», соглашения, история) хеш не меняет и нового формата не требует. Номер версии в шапке словаря — для людей. Переводчику «Алула → JSON» нужна копия нормативной части с тем же хешем.

**Транслитерация**: буква кириллицы (строчная или заглавная) заменяется латиницей по таблице; латинские буквы, цифры, `_` и пробел остаются, регистр — по правилу ниже; слово, где смешаны кириллица и латиница, — ошибка (выше).

| Буква | Латиница | Буква | Латиница | Буква | Латиница |
|---|---|---|---|---|---|
| а | a | б | b | в | v |
| г | g | д | d | е | e |
| ё | e | ж | zh | з | z |
| и | i | й | y | к | k |
| л | l | м | m | н | n |
| о | o | п | p | р | r |
| с | s | т | t | у | u |
| ф | f | х | kh | ц | ts |
| ч | ch | ш | sh | щ | shch |
| ъ | — (опускается) | ы | y | ь | — (опускается) |
| э | e | ю | yu | я | ya |

**Регистр** транслитерации (шаг 3). Слова имени разделены `_` или пробелом; `_` и пробелы в начале, в конце и подряд пустых слов не дают и в имя не переходят (`_ход__агента` → `khod_agenta`). **Имена-типы** — состояние, тип, форма перечисления с полями, элемент перечисления — пишутся слитно, каждое слово с заглавной буквы (`PascalCase`): в слове, написанном без строчных букв (`ХОД`, `В3`), все буквы, кроме первой, сначала становятся строчными; заглавная буква кириллицы даёт латиницу с заглавной первой буквой (`Ж` → `Zh`, `Щ` → `Shch`); первая буква каждого слова — заглавная: `ХОД_АГЕНТА` → `KhodAgenta`, `ВидВызывающего` → `VidVyzyvayushchego`, `НетОтветаВСрок` → `NetOtvetaVSrok`. **Имена-значения** — данное, поле входа, поле записи и формы, сигнал стороны и его поле, внешняя функция, имя настройки вратаря — пишутся строчными, слова через `_` (`snake_case`): `оставить правку` → `ostavit_pravku`, `находки_В3` → `nakhodki_v3` (если бы словаря не было). Правило взято из образцов и соглашения 1 словаря: типы и формы — `PascalCase`, поля, данные и функции — `snake_case`.

**Таблица слов — единый нормативный источник:** [alula-keywords.tsv](alula-keywords.tsv). Строки `kind`, `ru`, `en` (табуляция), первая строка — заголовок; вид слова (`kind`) из закрытого перечня:

| `kind` | Слова |
|---|---|
| `header` | слова шапки: `Машина`, `Функции`, `Фрагмент` и ключи шапки |
| `section` | заголовки разделов `##` (включая `Обязывает`, `Общие события` файла фрагмента) |
| `column` | заголовки столбцов таблиц |
| `kind_state` | виды состояний: обращение, операция, развилка, конец |
| `key` | строки-ключи (`Сторона`, `Запрос`, `Читает`, `Правит`, `проверка`, `набор`, `Кроме` и др.), слова строки подключения (`функции`, `версия`, `хеш`), префикс `проект` |
| `kind_party` | виды сторон и слова их записи (`разбор`, `итог`, `вход`, `human или agent по настройке`) |
| `kind_param` | виды параметров фрагмента (раздел 9): `сигнал`, `строка`, `[]машина`, `поведение`, `примечание`; `строка` — и в `type` (слово может стоять в разных видах, в одном виде — один раз) |
| `event` | слова событий (`ответ`, `сбой`, `сразу`, `сигнал`), `причина`, `иначе` |
| `destination` | слова «куда»: `предыдущее`, `возврат_подготовки`, `то же`, суффикс `запуск заново` |
| `decl` | слова объявлений: `тип`, `перечисление` (слово вида после имени типа), `функция`, `внешняя` (в `внешняя функция`, раздел 7) |
| `type` | слова типов и встроенные типы (раздел 2) |
| `expr` | слова выражений, литералы, конструкторы `Ответ`, `Отказ` |
| `operator` | операторы и знаки ASCII: в обоих языках одно написание, `ru` и `en` совпадают, кроме знака принадлежности: русское `в`, английское `in` |
| `action` | слова действий и их аргументов (в том числе `для`) |
| `readable` | читаемые имена исполнителя, данные контракта и привязка `причина` |
| `enum_value` | значения `пишет` и `читает`, `да` столбца «не убывает», значения параметров `поведение`, значения `Сигнал`, слова классов внешних функций (`изменчивая`, `действующая`; `pure` — слово класса реестра хозяина) |
| `catalog` | функции каталога (раздел 12) |

Слово, подходящее под два вида, записано двумя строками (`иначе` — в `event`, `expr`, `action`; `конец` — в `kind_state` и `catalog`). В пределах вида слова `ru` не повторяются и слова `en` не повторяются: слово, одинаковое в английской форме для двух русских слов, относится к разным видам. Разбор читает слово по `kind` позиции и языку файла. Проверка таблицы и образца — [tools/check-alula-keywords.py](../tools/check-alula-keywords.py) (раздел 10).

**Операторы и знаки — только ASCII**. Знаки пишутся одинаково в обоих языках (вид `operator` таблицы слов: `ru` и `en` совпадают), кроме знака принадлежности: русское слово `в`, английское `in`; других написаний нет:

| Знак | Где |
|---|---|
| `>=` | сравнение; граница типа `число>=n` (английское `int>=n`) |
| `<=` | сравнение; `да, <= выр` столбца «не убывает» |
| `!=` | сравнение |
| `->` | тип результата `-> Тип`: заголовок функции, `разбор: внешняя функция -> Тип` стороны `machine`, сигнатуры каталога и функциональный тип параметра-лямбды `функция(T) -> R` в них (раздел 12) |
| `=>` | тело функции из одного выражения `-> Тип => выр` (тело-блок `-> Тип { … }` — без `=>`), ветка `выбор`, лямбда |
| `...` | спред `{ ...выр, поле: выр }` |
| `..` | диапазон `a..b` — полуоткрытый `[a, b)`; `..` после числа или имени — знак диапазона, а не часть дробного литерала: `1..п` — `1`, `..`, `п` |
| `..=` | включающий диапазон `a..=b` — `a..(b + 1)`; пишется слитно; самое длинное совпадение — `...`, затем `..=`, затем `..` |
| `в` (английское `in`) | `сбой(причина в […])`, `остановка в […]` («когда» концов, `Кроме`); множество — литерал списка `[…]`; `in` в русском файле — ошибка |
| `??`, `_` | значение по умолчанию; ненужный параметр лямбды |

Многоточие `…` в описании грамматики (3.1) и в тексте спецификации — метаобозначение пропуска, а не знак языка.

**Английская запись типов и знаков.** `число`→`int`, `число>=n`→`int>=n`, `вещественное`→`f64`, `строка`→`str`, `булево`→`bool` (слова Новы), `словарь[K, V]`→`map[K, V]` (в JSON словарь — `{K: V}`; синонимов у типов нет, `HashMap[K, V]` не принимается), `полный словарь[K, V]`→`full map[K, V]`, `ид`→`id`; `?T`, `[]T`, кортеж `(T1, T2)`, `—` и `№` в обоих языках те же (операторы — выше); значение «ничего» — `none` (литерал `пусто`), тип «ничего» в JSON — `nothing`; функции каталога `строка(x)`, `вещественное(x)`, `число(x)` — `text(x)`, `float(x)`, `int(x)` (раздел 12; их слова не меняются); в дереве типы называются словами `int`, `text`, `float`, `bool` (раздел 6). Например, `выбор … { альт | альт если выр => выр, иначе => выр }` — `match … { alt | alt if expr => expr, else => expr }`, `для x из xs { … }` — `for x in xs { … }`, `ответ: Форма { … }` — `response: Form { … }`, `засчитан { находки []Находка }` — `counted { findings []Finding }`, `Вар { поле, поле: имя } =>` — `Var { field, field: name } =>`, `сбой(причина в […])` — `failure(reason in […])`, `xs.фильтр(x => выр)` — `xs.filter(x => expr)`, `функция f(x число) -> число { … }` — `fn f(x int) -> int { … }`; литерал словаря `[к: з]` и `a..=b` в обоих языках те же.

## 1б. Канонический вид (рекомендуемый для генераторов)

Генератор «дерево → файл» (обратное преобразование JSON `machine/2` → Алула) обязан одному: написанный им текст переводится обратно в дерево, равное исходному, — круг «md → JSON → md → JSON» даёт равное дерево. Правила этого раздела — **рекомендуемый** канонический вид такого текста: с ним результат предсказуем, и два генератора пишут один текст; генератор, который пишет иначе, требование не нарушает, если дерево равно. При обратном преобразовании теряются абзацы-комментарии, оформление (выравнивание, переносы строк внутри объявлений) и имена, которых в дереве нет (в дереве лежит одно JSON-имя, автоматическое или из `## Имена`, 1а); смысл не теряется. Файл, написанный человеком иначе (порядок строк-ключей, проза, переносы), остаётся допустимым — разбор его принимает.

- **(а) Шапка.** `# Машина: <Имя>` (английская — `# Machine: <Name>`), где `<Имя>` — латинское имя машины (`machine` дерева); пустая строка; список из четырёх элементов в этом порядке: `- machine: <имя>`, `- machine_version: <строка>`, `- format: <версия формата>`, `- language: <ru|en>`; строка `language` пишется всегда, умолчание не используется. `machine_version` — `version` дерева; `format` — версия формата, в которой записан исходник (ключ `alula_version` корня дерева, раздел 6; нет его — версия формата генератора).
- **(б) Разделы.** Одиннадцать разделов раздела 1 по порядку — `## Типы`, `## Константы`, `## Параметры`, `## Вход`, `## Данные`, `## Стороны`, `## Функции`, `## Подключения`, `## Состояния`, `## Концы`, `## Внешние функции` — пишутся всегда и по одному разу; пустой раздел — единственная строка `—` под заголовком; необязательный раздел `## Имена` (1а) стоит после `## Типы` и пишется, только если в нём есть строки; между разделами — одна пустая строка. Строки-ключи разделов — элементами списка: `- Инвариант: <выражение>` (по одному на инвариант) — после таблицы `## Вход`; `- Предел запросов: <выражение>` (если в дереве задан `request_limit`) — после таблицы `## Стороны`; `- Результат: <Тип>` — перед таблицей `## Концы`.
- **(в) Состояния.** Первая строка `## Состояния` — `Начальное состояние: ИМЯ` (английская — `Initial state: NAME`), не элементом списка, затем пустая строка; состояния — в порядке `states` дерева. Строки-ключи состояния — элементами списка, подряд, в порядке: `Сторона`, `Срок тишины`, `Правит`, `Возвратов формы`, `Запрос`, `При приёме`, `Читает`, `При входе`, `Кроме` (английские — `Party`, `Idle term`, `Edits`, `Form returns`, `Request`, `On accept`, `Reads`, `On entry`, `Except`); ключ, которого у состояния нет или чьё значение пустое (`—`, `нет`), не пишется; ключ с настоящим значением по умолчанию (`Срок тишины: 0`, `Возвратов формы: 0`) генератор может написать. Элемент с таблицей (`Запрос:` обращения, `При приёме:`) стоит перед своей таблицей, между таблицей и следующим блоком — пустая строка; тело «При входе» из нескольких действий — вложенный список, по действию в элементе (4.1).
- **(г) Таблицы.** Заголовок и строки — один пробел с каждой стороны от `|`, без выравнивания ширины столбцов; строка-разделитель — `|---|` по числу столбцов; пустая ячейка — `—`; `|` внутри ячейки — `\|`. В таблице `Запрос` выражение, равное имени поля, пишется `—`. Действия в ячейке — в порядке дерева через `; `; блоки — в фигурных скобках с пробелом внутри: ветки условного действия `если выр то { а; б } иначе { в }`, условного выражения `если выр то { выр } иначе { выр }`, тело `для x из xs { а; б }`, блок действий `{ пусть л = выр; а }`; образец события — `ответ: Вар { поле, поле: имя }`, сигнал с полями — `сигнал(с { поле })`; объявление сигнала с полями в столбце «сигналы» — `с { поле тип, поле тип }`, сигнал без полей — именем. Слова заголовков столбцов — по таблице слов языка файла.
- **(д) Объявления.** Типы, функции и внешние функции пишутся в блоках кода под `## Типы`, `## Функции` и `## Внешние функции`, в порядке дерева, **одно объявление на строку**: `тип Имя перечисление А | Б`, со значениями — заголовок `тип Имя перечисление` и строки `| Эл = "значение"`, `тип Имя { поле тип, поле тип }`, `внешняя функция имя(параметр тип) [класс] [-> Тип]` (без тела), `функция имя(параметр тип) -> Тип =>` и тело функции на следующей строке с отступом в два пробела (одной строкой); тело-блок: `{` в конце заголовка без `=>` (`функция имя(параметр тип) -> Тип {`), привязки `пусть имя = выр;` и последнее выражение — по строке с отступом в два пробела, `}` — отдельной строкой. Перечисление (как D406 Новы): однострочно — `тип Имя перечисление А | Б`, только если все формы — голые имена (без значений и полей) и строка не длиннее 100 знаков; иначе многострочно — строка заголовка `тип Имя перечисление`, затем по форме на строке с отступом в два пробела: `  | Эл`, `  | Эл = "значение"`, `  | Вар { поле тип, поле тип }`; пустых строк и комментариев между формами генератор не пишет (разбор их допускает, раздел 2). Альтернатива `выбор` по форме с полями — `Вар { поле, поле: имя } =>`. В блоке `## Типы` пустые строки между объявлениями не обязательны и генератором не пишутся (разбор их допускает; образцы разделяют пустой строкой группы объявлений); между функциями — одна пустая строка.
- **(е) Операторы.** Только ASCII в обоих языках: `->` перед типом результата; `=>` перед телом функции из одного выражения (тело-блок — без `=>`), в ветках `выбор` и в лямбдах; `>=`, `<=`, `!=`, `==` в сравнениях; `...` в спреде; `..` в диапазоне `a..b`, `..=` во включающем диапазоне `a..=b`; ветки `выбор` — через `, ` на одной строке, в многострочном `выбор` — переводом строки: генератор пишет `выбор` одной строкой, если он умещается — строка, в которой стоит `выбор`, от начала до конца не длиннее 100 знаков и ни у одной ветки нет блока `=> { … }`; иначе — многострочно: `{` в конце строки заголовка, каждая ветка своей строкой с отступом на два пробела больше строки заголовка, без запятой в конце, `}` своей строкой на отступе строки заголовка; в ячейке таблицы `выбор` всегда однострочный; литерал словаря `[к: з, к: з]`, пустой словарь — `[]`; `в` (английское `in`) с литералом списка в `сбой(причина в […])`, «когда» и `Кроме`; функция списка из каталога — методом списка `xs.фильтр(x => выр)`; `число>=n` (`int>=n`); `да, <= выр` (`yes, <= expr`). Знаки — таблица слов, вид `operator` (1а).
- **(ж) Имена.** Генератор пишет каждое имя так, как оно лежит в дереве: у имени с JSON-именем в дереве лежит только оно; внутренние имена лежат как написаны; поэтому раздела `## Имена` (1а) такой генератор не пишет — `### Retry — развилка`, `| retry_count | число>=0 | …`; генератор, который пишет другие имена (например, сохранённые русские имена автора), пишет `## Имена` для каждого имени, чьё автоматическое имя не равно JSON-имени дерева, и только для них; то же имя состояния стоит в `Начальное состояние` и в столбце «Куда». Виды — слова `обращение`, `операция`, `развилка`, `конец` (английские — `appeal`, `operation`, `fork`, `end`).
- **(з) Язык файла.** Генератор выбирает язык параметром (`ru` или `en`); все ключевые слова берутся из [alula-keywords.tsv](alula-keywords.tsv) по этому языку (1а), смешения нет; имена, придуманные автором (данные, типы, поля, функции), и значения перечислений переносятся из дерева как есть.
- **(и) Значения-строки и коды журнала** переносятся как есть, без перевода и нормализации; строковый литерал — в двойных кавычках, внутри экранируются `"` (`\"`), `\` (`\\`), `$` перед `{` (`\$`), перевод строки, табуляция, возврат каретки и нулевой знак (`\n`, `\t`, `\r`, `\0`), прочие управляющие знаки — `\u{HEX}` (закрытый список). Число — десятичной записью: целое без `_`, дробное — записью `строка(x)` (3.3; `1e-7`, `1.5e20`); комментарии `//` генератор не пишет. Вызов `склеить(…)`, все аргументы которого — непустые текстовые литералы и вызовы `строка(x)` и два литерала не стоят подряд, генератор рекомендуется писать вставкой (`склеить("ход ", строка(н))` — `"ход ${н}"`), другой вызов `склеить` — вызовом; `строка(x)` — вызовом; требование одно — равное дерево.
- **(к) Проза.** Комментарии и проза не генерируются. Допустимо одним абзацем под шапкой (после списка шапки) записать `title` дерева, если он есть; больше ничего.
- **(л) Файл** кончается ровно одним переводом строки (без пустых строк в конце), кодировка UTF-8 без BOM, переводы строк LF.
- **(м) Подключения.** Фрагмент: дерево несёт его уже подставленным (раздел 9) и несёт узел подключения с параметрами (раздел 6); генератор пишет строку подключения фрагмента со всеми параметрами, одной строкой, параметры — в порядке таблицы `## Параметры` фрагмента (`Пауза(сигнал_остановки: остановить, код_остановки: "pause_halt", вложенные: [], отмена_запросов: прекратить_ход_транспорта, вход_заново: ничего, право_записи: "…")`), а состояния, данные и общие события фрагмента как собственные не пишет: повтор был бы «объявлено дважды», а без строки подключения потерялись бы параметры вида `поведение` (`отмена_запросов`, `вход_заново`) — подстановкой в текст они не выражаются, их эффект лежит на `отменить_открытые` и `Куда: предыдущее`. Файл функций: дерево несёт и ссылку (`includes`), и копию его типов, констант и функций (раздел 6); генератор пишет либо строку подключения (копии тогда не пишет), либо копии (тогда строки подключения нет) — иначе имена объявлены дважды (раздел 8); выбор — параметр генератора, по умолчанию строка подключения.

Образцы [spec/samples/agent-step.alula.md](samples/agent-step.alula.md) и [spec/samples/agent-step.en.alula.md](samples/agent-step.en.alula.md) написаны человеком и в рекомендуемый вид не приведены: они несут прозу (к), строку подключения фрагмента с переносами (м), переносы внутри объявлений и многострочные тела функций (д); русский образец, кроме того, — русские имена, чьи JSON-имена строятся автоматически, с разделом `## Имена` там, где автоматическое имя неверно (ж), и не имеет строки `language` (а). Остальное (шапка, порядок разделов и строк-ключей, таблицы, операторы) в образцах соответствует каноническому виду. Круг «md → JSON → md → JSON» проверяет продукт-потребитель; скрипты методики канонический вид не проверяют (см. [журнал изменений](alula-changelog.md), «Открытое»).

**Регистр**: встроенные типы-слова и типы с аргументами пишутся строчными (`число`, `строка`, `ид`, `словарь`), встроенные и объявленные автором именованные типы — с заглавной (`Состояние`, `Сигнал`, `ЗапросАгента`); виды параметров фрагмента (раздел 9) — не типы, а отдельная группа слов; `сигнал` (вид — сигнал стороны) и `Сигнал` (тип — сигнал машины) — разные слова.

**Набор литералов или перечисление**. Набор литералов — когда набор небольшой, локальный для одной машины, значения не нужны журналу как значения перечисления и не пересекают границу машины (`ход`, `остановка` у «Шага агента» — так в источнике). Перечисление со значениями (`тип Имя перечисление` и строки `| Эл = "значение"`) — когда набор общий для нескольких машин или фрагментов, пересекает границу вызова (вход, ответ, код сбоя — `КодСбоя`), нужны значения для журнала и `строка(x)` либо у элементов есть поля (тогда это перечисление с полями). **Значения набора** — любой текст, в том числе с кириллицей и пробелом (`"наблюдалось" | "не наблюдалось" | "вывод"` — слова артефакта роли): правило 34(б) латиницу в текстовых литералах закрытых наборов допускает, но не требует; значения пишутся как в источнике (слова кода автомата — латиницей, слова артефакта — как в артефакте). Ограничение `[a-z][a-z0-9_]*` действует только для значений перечисления.

**Тип `ид`**. Текст формата UUID: 8-4-4-4-12 шестнадцатеричных знаков через дефисы, строчные (`0192f3a0-7c1e-7b2a-9d4e-5a6b7c8d9e0f`). Проверка — при загрузке данных и при разборе входа: нарушение входа — отказ `input_rejected`, `reason=type`, `field` — имя поля (раздел 1); нарушение данных — ошибка загрузки по правилам формата. Версия UUID формат не фиксирует; для идентификаторов сессий, запросов хозяина и прогонов предпочтительна версия 7 (по времени, сортируемая). `ид` присваивается данному и параметру типа `строка` (тип при этом забывается, как у набора литералов); обратное — только литерал формата UUID. `==` — структурное, `строка(x)` даёт сам текст. Значение выдаёт стандартная внешняя функция `новый_ид` (раздел 7, 7а). **Не меняется:** идентификатор запроса `<сторона>-<попытка>` (правило 15, [протокол вызова](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-call-protocol.md)) и конверт трассировки (`трасса`, `номер_шага`, правило 31) остаются как в спецификации — `ид` служит данным машин (идентификаторы сессий, прогонов и т. п.), а не конверту.

**Значения перечисления**. Значения могут быть заданы не для всех элементов; значение — `[a-z][a-z0-9_]*`. Элемент без значения показывается в `строка(x)` и в `все_данные` JSON-именем (1а): в файле имя элемента — на языке файла, в дереве, в `machine_data` и `все_данные` — JSON-имя; сверка `machine_data` идёт по JSON-имени (для `КодСбоя` — по значению, как у движка).

**Нотация объявлений — как в Нове** (решение владельца, 2026-10-19): объявление — `имя тип` через пробел (поле записи и формы, параметр функции и функции каталога, параметр сигнатуры стороны и поле сигнала, параметр реестра); результат — после `->`, тело функции — после `=>` или блоком `{ … }`. Двоеточие стоит только в литерале записи `Тип { поле: выр }`, в именованном аргументе журнальных форм `имя: выр` (3.1), в паре литерала словаря `[к: з]` и в привязке поля образца `поле: имя` (4.3). Знак `=` в объявлении стоит только у значения элемента перечисления `Эл = "значение"`, после имени типа его нет. **Скобки**: поля записи, формы и сигнала стороны — в фигурных скобках (`тип Имя { поле T }`, `Вар { поле T }`, `засчитан { находки []Находка }`), так же образец события и альтернатива `выбор` (`Вар { поле, поле: имя }`); параметры функции, функции каталога, сигнатуры стороны и реестра — в круглых (`функция имя(п T)`, `agent(итог Тип)`): круглые скобки после имени — функция, фигурные — поля записи или формы. Таблицы с отдельным столбцом «тип» (`## Вход`, `## Параметры`, `## Данные`) не меняются. **Объявления только в блоке кода**: `тип` (в том числе перечисление `тип Имя перечисление …`), `функция` и `внешняя функция` пишутся внутри блока кода (ограждения ```) под `## Типы`, `## Функции` и `## Внешние функции`; строка объявления вне блока кода — комментарий (абзац) и предупреждение проверки: markdown исказил бы `|`, `{}`, `->`.

**Правило стиля: имя поля не совпадает с названием его типа** (рекомендация, не ошибка проверки). Правило касается полей записей и форм и данных машины (таблица «Данные»). Поле называет роль значения в записи, тип — вид значения: `токены Токены`, `сверка Сверка` читаются как повтор и не говорят, зачем поле; лучше `ответ строка`, `расход_токенов Токены`. Совпадение — равенство имени поля и имени его типа без учёта регистра, после снятия `?` и `[]` (`сверка ?Сверка` — совпадение). Имена полей образцов («Шаг агента», «Совещание») не меняются: это имена дерева и кода продукта-потребителя, переименование сломало бы их. Предупреждение проверки — позже (см. [журнал изменений](alula-changelog.md), «Открытое»).

**Записи типов и Нова** (сверено со спецификацией языка и кодом автоматов): как в Нове — `[]T`, кортеж `(T1, T2)` (в позиции типа), `словарь[K, V]` (в Нове — `HashMap[K, V]`; литерал `[к: з]` как в Нове), запись `тип Имя { поле T }`, перечисление `тип Имя перечисление А | Б`, со значениями и полями у форм — многострочно с `|` (как `type Имя enum …` Новы, D406; в Нове значение — целое `Эл = 0`); перевод имён — `число`, `строка`, `вещественное`, `булево` (`int`, `str`, `f64`, `bool`). **Расширения формата**, которых в Нове нет: `?T` (в Нове `Option[T]`), `число>=n`, набор литералов `"a" | "b"`, `ид`, `полный словарь[K, V]`; остальные расхождения — в перечне «Открытое» [журнала изменений](alula-changelog.md).

Пример (пилот «Шаг агента»; значения `КодСбоя` — из `fail_code_word` движка).

```
тип КодСбоя перечисление
  | НетРезультата = "no_result"
  | ОтказМодели = "model_refused"
  | СоединениеОборвалось = "connection_lost"
  | ФормаНеИсправлена = "form_not_fixed"
  | НетОтветаВСрок = "timeout"
  | ОстановленоЧеловеком = "stopped_by_human"
  | ПотолокЗаходов = "ceiling_reached"
  | ОтмененоРодителем = "cancelled"
  | ПредельТокенов = "max_tokens"
  | ПредельЗапросовХода = "max_turn_requests"

тип ИтогХода перечисление
  | Закончен { текст ?строка, артефакт ?строка, расход РасходТранспорта }
  | Обрезан { расход РасходТранспорта }
  | ПределЗапросов { расход РасходТранспорта }
  | МодельОтказалась { расход РасходТранспорта }

```

**Данные.** Таблица `| имя | тип | начальное | не убывает | пишет |`.

- `имя` — данное или **путь поля** внутри словаря: `имя[*].поле` (`*` — любой ключ; у вложенного `имя[*].поле.поле`). Строка с путём несёт только `не убывает` и `пишет` и действует на каждое значение словаря; `тип` — тип поля, `начальное` — `—` (значение задаёт строка самого данного).
- `начальное` — выражение или `вход.<поле>`.
- `не убывает` — `—`, `да` или `да, <= выр`; выражение может быть любым выражением над константами, параметрами и входом (`наибольшее(1, предел)`); границу проверяет исполнитель после перехода (у пути — при записи; нарушение — ошибка машины). Если граница в первоисточнике неверна для части значений, она не пишется.
- `пишет` — кто меняет данное: `действия` (всё, что записано в таблицах машины: действия строк, блок «При приёме», действующие функции, вызванные из таблиц; по умолчанию; прежнее слово `строки` — ошибка проверки с подсказкой «с 2.23 — `действия`», переходного периода нет), `механика` (записи исполнителя вне текста машины: счётчики попыток, перенос из `к_отправке`, `открытые_запросы`, правила 14, 15, 21), `действия и механика` (оба; исключение правила 29 называется явно), `фрагмент` (данные подключённого фрагмента), `действия и фрагмент` (действия машины и действия фрагмента: у данного `остановка`). `пишет` задаётся на данное целиком; у пути — своё значение: запись в поле с `пишет: механика` из строки перехода — ошибка проверки таблицы.
- **Данные контракта** вносятся в таблицу и входят в `все_данные`: `открытые_запросы` (`[]строка`, начальное `[]`, `пишет: механика`) вносит фрагмент «Пауза» — его читают `передать` и `отменить_открытые` (раздел 9); у машины без фрагмента, которая читает его сама, вносит машина; объявление в двух местах — конфликт имён (правило 36), ошибка проверки; `к_отправке` (`[]строка`) — `действия и механика`: действия строк пишут его (ЗАМОК, ОТКАЗ), механика переносит стороны в `открытые_запросы` (правило 21); счётчик попыток стороны — данное из столбца `счётчик` «Сторон» (раздел 1).
- **Состав `все_данные`**: **каждое** данное, названное в таблицах `## Данные` машины и подключённых фрагментов, и данные контракта (предыдущий пункт); путь поля — внутри своего данного. Признак один и проверяется по таблицам: названо в таблице — входит; исключений среди названных нет. Поэтому входят и данные, которые источник относит к внешним объектам и заданию (у «Совещания» `предложение`, `копия`, `отпечаток_копии`, `ответы_свидетеля`, `находки_линзы`, `свод`, `архив`, `вопрос_автора`, `порядок_линз`), и копия входа (`запрос_агента` у «Шага агента»): первоисточник даёт у ОШИБКИ «все переменные и хранилища», правило 11 спецификации — «все данные машины». Не входит только то, чего в таблицах нет: данные исполнителя и конверт (`состояние`, `трасса`, `номер_шага`, `счётчик_событий`, `причина_шага`, `принятые_запросы`, журнал) и хранилища правила 31 (`слова_человека`, `тексты_сбоев`; слово человека и текст сбоя в журнал целиком не пишутся). Кодирование — раздел 5.

Пример (пилоты; границы и `пишет` — как в пилотах, кроме `линзы`: путь поля вместо `действия и механика`).

| имя | тип | начальное | не убывает | пишет |
| запрос_агента | ЗапросАгента | ЗапросАгента { вид: вход.вид, профиль: вход.профиль, сессия: вход.сессия, вид_диалога: вход.вид_диалога, контекст: вход.контекст, пределы: вход.пределы, трасса: вход.трасса, номер_шага: вход.номер_шага } | — | действия |
| ход | "first" \| "retry" \| "continue" \| "fix" \| "permission" | "first" | — | действия |
| число_повторов | число>=0 | 0 | да, <= ЧИСЛО_ПОВТОРОВ | действия |
| число_ходов | число>=0 | 0 | да | действия |
| ход_до_повтора | ?("first" \| "retry" \| "continue" \| "fix" \| "permission") | пусто | — | действия |
| остановка | "" \| "no_result" \| "max_tokens" \| "pause_halt" \| "cancel_request" | "" | — | действия и фрагмент |
| попытка_агента | число>=0 | 0 | да | механика |
| номер_захода | число>=1 | 1 | да | действия |
| линзы | словарь[строка, Линза] | вход.порядок_линз.словарь(л => л, л => Линза { идентификатор: л, потери_подряд: 0, пробы: 0, попытка: 0 }) | — | действия |
| линзы[*].попытка | число>=0 | — | да | механика |
| ответы_свидетеля | словарь[число>=0, []ОтветСвидетеля] | [] | — | действия |

(Типы `ход`, `ход_до_повтора`, `остановка` — наборы литералов. Первые семь строк — «Шаг агента», остальные — «Совещание»; `запрос_агента` собирается конструктором из полей входа (раздел 1); `открытые_запросы` вносит фрагмент «Пауза», в таблицу машины его строка не пишется. В `остановка` показана часть набора; полный набор пилота — двенадцать значений. Границы `<=` у `число_ходов` нет: при пределе ходов меньше 1 код даёт 1. `номер_захода` — `число>=1`: в коде `Cycle.new()` и `MachineData.new()` дают 1, меняется только `+= 1` (инвариант «не уменьшается»); `номер_захода - 1` — `число`, 3.2. Строка `линзы` меняет `потери_подряд` и `пробы`, `попытка` — только механика: запись `линзы[к] = { ...л, поле: выр }`, не называющая `попытка`, — копирование, а не запись в него.)

## 3. Выражения

Слова выражений (`если`, `то`, `иначе`, `и`, `или`, `не`, `пусть`, `выбор`, `истина`, `ложь`, `пусто`, `недостижимо`) и читаемые имена — русская форма; английская форма — по [таблице слов](alula-keywords.tsv), виды `expr` и `readable` (1а).

### 3.1 Грамматика

```
выр := литерал | истина | ложь | пусто | недостижимо | имя | ( выр ) | выр.поле | выр.N | выр[выр]
     | Тип { поле: выр, … } | Тип.Форма { поле: выр, … } | Тип.Форма     запись, форма с полями, форма без полей
     | { ...выр, поле: выр, … }                        копия записи с заменой полей
     | (выр, выр, …)                                  кортеж (от двух полей)
     | [выр, …] | [выр: выр, …]                       список; словарь (ключ — выражение); [] — пустой список или словарь по ожидаемому типу
     | не выр | -выр | выр (+|-|*|/|%) выр | выр (==|!=|<|<=|>|>=) выр
     | выр (и|или) выр | выр ?? выр
     | выр..выр                                       диапазон: полуоткрытый [a, b)
     | выр..=выр                                      включающий диапазон [a, b]: a..(b + 1)
     | если выр то { выр } иначе { выр }
     | { [пусть имя = выр;]… выр }                       блок-выражение: привязки и последнее выражение (значение блока)
     | выбор выр { альт [| альт]… [если выр] => выр, … , иначе => выр }     исчерпывающий; на одной строке ветки — через `,`, многострочно — каждая ветка своей строкой без `,`
     | имя(выр, …)                                    функция каталога, функция автора (чистая) или внешняя функция хозяина (раздел 7: чистая — везде, изменчивая и действующая — по классу); именованных аргументов нет (ниже)
     | событие_журнала("код", имя: выр, …)             значение-событие журнала; именованные аргументы — только в журнальных формах (ниже)
     | выр.функция(имя => выр) | выр.свёртка(выр, (имя, имя) => выр) | выр.словарь(имя => выр, имя => выр)     функция списка из каталога — метод списка
     | имя(выр, …, ключ: выр, …)                      внешняя функция с именованным хвостом `...имя: Тип`: позиционные аргументы, затем пары `ключ: значение` (ниже)
альт := Тип.Значение | Значение | Форма | Форма { поле, поле: имя, … } | Тип.Форма { поле, поле: имя, … } | литерал     Значение — голое имя элемента, ищется среди объявленных перечислений
```

- **Приоритет и ассоциативность** (высший первым; с версии 2.24 приведены к Нове, D49): скобки `( )`, постфикс `.` `[]` и вызов; унарный `-` и `не` (сильный префикс, как `!` Новы); `* / %` (левоассоциативны); `+ -` (левоассоциативны); `??` (правоассоциативен: `a ?? b ?? c` — `a ?? (b ?? c)`; выше сравнений, ниже `+ -`); `< <= > >=`; `== !=`; `и` (левоассоциативен); `или` (левоассоциативен); `..` и `..=` — самые слабые: `a..b + 1` — `a..(b + 1)`, `0..н ?? 0` — `0..(н ?? 0)`, `a..b == c` — `a..(b == c)` (поэтому сравнение с диапазоном пишется в скобках); `..` и `..=` не цепляются: `a..b..c`, `a..=b..c` — ошибка. Сравнения и равенства не цепляются (ниже). `выбор` захватывает всё справа; ветки `если` и блок-выражение — блоки, их граница — закрывающая `}`.
- **Ошибки проверки с просьбой поставить скобки.** Любое сочетание двух операторов сравнения или равенства без скобок: `a < b < c`, `a == b != c`, `a == b < c` (по приоритету это `a == (b < c)`, но в Алуле скобки обязательны); пишется `a < b и b < c` или `(a < b) == c`. `не` над сравнением без скобок: `не a == b` — ошибка (`не` связывает сильнее сравнения, то есть `(не a) == b`); пишется `(не a) == b` или `не (a == b)`.
- **Рекомендация о читаемости** (не ошибка): смесь `??` со сравнением, `и` или `или` разбирается по приоритетам (`a ?? b == c` — `(a ?? b) == c`, `a и b ?? c` — `a и (b ?? c)`), но пишется со скобками.
- **Литералы:** целое `12`, дробное `0.0`, текст `"…"` (со вставками `"…${выр}…"`, ниже); `истина`, `ложь`; `пусто` — отсутствие значения `?T`. **Числа** (D44 Новы, `decimal-int` и `float`): целое — `[0-9] (_? [0-9])*` (`12`, `1_000`: знак `_` — только между двумя цифрами); дробное — целое, `.` и целое (`0.5`, `1_000.25`) с необязательным порядком или целое с порядком; порядок — `e` или `E`, необязательный знак `+`/`-` и целое (`1.5e-3`, `1e-7`, `2E5`, `1.5e+3`); шестнадцатеричные, двоичные, восьмеричные литералы и суффиксы типа не вводятся (как в Нове отвергнуты суффиксы). **Порядок разбора числа** (как лексер Новы `novac/src/lex/lex.nv`): цифры целой части с `_` между цифрами; точка входит в число, только если сразу за ней цифра — поэтому `1..п` — `1`, `..`, `п`, `0..3` — `0`, `..`, `3`, `1_000..2_000` — `1_000`, `..`, `2_000`, а `1.` без цифры после точки и `1..` — не дробное; затем порядок, если за `e`/`E` (и знаком) стоит цифра — `1e3` и `1.5e3` — одно дробное число; к числу не примыкает буква, цифра или `_` имени: `1__0`, `1_`, `1_e5`, `1.5_`, `1e`, `1e+`, `0x1F` — ошибка; `_1` — имя, а не число. **Escape** в текстовом литерале (закрытый список, как D467 §2 Новы): `\"` — кавычка, `\\` — обратная косая черта, `\$` — знак `$` (`\${` — это `\$` и `{`: вставки нет), `\n`, `\t`, `\r` — перевод строки, табуляция, возврат каретки, `\0` — нулевой знак, `\u{HEX}` — знак Юникода по одной–шести шестнадцатеричным цифрам (суррогаты `D800`…`DFFF` и значения больше `10FFFF` — ошибка); любой другой знак после `\` — ошибка проверки; `\xNN` Новы не взят (его покрывает `\u{…}`), продолжения строки `\` + перевод строки нет — литерал стоит в одной строке; в ячейке таблицы `\|` — экранирование ячейки, разбор снимает его до разбора литерала. Слово `нет` литералом не служит (правило 30: «нет» спецификации — `пусто` у `?T`). `недостижимо` — выражение любого типа: дефект программы, вычисление останавливает исполнитель, как `обязательно(пусто)` (3.3); стоит в ветке `выбор` для формы, которая по контракту не приходит.
- **Имена.** Имя — данные, константа, параметр, функция, привязка. Состояние читает любое имя из своих чтений (`Читает`; у обращения — таблица `Запрос`), каким бы ни было его `читает`. Привязка поля события, `пусть` и параметр лямбды видны только в своей области; привязка поля события с именем данного машины не совпадает (4.3). Вызываемое и значение лежат в разных пространствах: функция автора занимает пространство вызовов вместе с функциями каталога и внешними функциями (1а, пространство 11), а данные, константы, параметры и привязки — пространство значений; поэтому привязанное поле `строка` и вызов `строка(x)` не мешают друг другу, а функция автора не совпадает ни с функцией каталога, ни с внешней функцией. **Служебные слова**, именем привязки, данного или поля не бывают: `в`, `из`, `то`, `иначе`, `и`, `или`, `не`, `пусть`, `выбор`, `если`, `для`, `истина`, `ложь`, `пусто`, `недостижимо`.
- **Привязка поля двоеточием**. Объявление поля сигнала или формы пишется по нотации Новы через пробел (`находки []Находка`, раздел 2); привязка в образце строки перехода — `поле: имя`, двоеточие читается «поле → имя» (`сигнал(засчитан { находки: новые })`, `ответ: Закончен { текст, артефакт, расход: полученный }`, альтернатива `Закончен { текст, расход: р } => …`); если имя совпадает с полем, пишется одно имя.
- **Лямбда** — одноместная (двухместная только у `свёртка`); параметр, который не нужен, пишется `_`; лямбды стоят только в аргументе функции списка. Запись — `имя => выр`, у двухместной параметры в скобках: `(н, _) => н * 2`; выражением тела может быть блок-выражение: `x => { пусть у = x * 2; у + 1 }` — как у ветки `выбор` и в отличие от тела функции, где `=> {` — ошибка (решение методики для 2.21, подтверждено владельцем (чат методики, 2026-10-22: «по рекомендации»)); знак `=>` тот же, что у ветки `выбор` и тела функции из одного выражения (как в Нове), а `->` стоит только перед типом результата. Запись Новы `|н, _| н * 2` не взята: GitHub делит строку таблицы по каждому знаку `|`, даже внутри обратных кавычек, и лямбда в ячейке (`начальное` данных, действия) требовала бы `\|`; кроме того, `|` уже разделяет значения набора литералов и альтернативы `выбор`.
- **Читаемые имена исполнителя** (не вычисления, правило 11): `вход`; `событие.идентификатор` (у любого события); `событие.момент` (у любого события: штамп события, целое — миллисекунды от 1970-01-01 UTC, когда событие пришло; исполнитель ставит его один раз, при повторе шага (правила 12–13) он тот же; у удержанного ответа — штамп шага, который его проигрывает; поле сигнала или формы с именем `момент` или с JSON-именем `at` (например, русское `время`, если словарь даёт ему `at`) — ошибка проверки: имя занято); `событие.<поле>` (поле данных события строки или цепочки, правило 13); `сторона` (у набора — идентификатор стороны события; в «профиле» и «Запросе» набора — текущая сторона); `причина` — код сбоя события `сбой(причина)` (4.3; виден строке и цепочке); `состояние` (раздел 9; тип `Состояние`); `запись_перехода` (тип `СобытиеЖурнала`; в «При входе» и «ответе» концов; определена, когда машина вошла в ОШИБКУ, а в ОШИБКУ входят двумя путями: по `ошибка_машины` — запись этого действия и по ошибке машины исполнителя (3.3) — запись `machine_error`; оба пути дают запись); `все_данные` (запись данных машины; состав — раздел 2; в действии `журнал(все_данные)` то же имя — сокращение события `machine_data`, раздел 5). `предыдущее` и `запрос_вызова` — не имена исполнителя, а данные фрагмента «Пауза» (раздел 9). JSON-имя читаемого имени — слово `en` таблицы слов, вид `readable` (`сторона` — `party`, `причина` — `reason`, `событие.момент` — `event.at`; 1а). Имена `трасса` и `номер_шага` (конверт, правило 31) доступны **только** в выражениях «Запроса» стороны вида `machine` — это конверт вызова вложенной машины (правило 35, пункт 1); в условиях и действиях конверт не читается.
- **Именованные аргументы** допустимы в двух местах. (1) В журнальных формах `журнал("код", имя: выр, …)`, `событие_журнала("код", имя: выр, …)` и `ошибка_машины("код", имя: выр, …)` (параметры события журнала, раздел 5): пары `имя: значение` идут после позиционных аргументов, имя пары — имя параметра шаблона события, повтор имени в одном вызове — ошибка проверки. (2) В вызове внешней функции с именованным хвостом (следующий пункт). В остальных вызовах — функциях каталога, функциях автора, внешних функциях без хвоста — именованный аргумент является ошибкой проверки, сообщение называет функцию и имя аргумента.
- **Именованный хвост внешней функции.** Последний параметр внешней функции может быть записан `...имя: Тип` (английская запись — `...name: Type`): именованный хвост, который принимает пары `ключ: значение` (объявление — раздел 7: `внешняя функция записать_статус(код число, ...поля: строка)`). Вызов `f(a, b, ключ: значение, …)`: позиционные аргументы по числу позиционных параметров, затем пары `ключ: выр` через запятую. Тип хвоста в языке — `словарь[строка, Тип]`; порядок записи ключей сохраняется (раздел 2), повтор имени ключа в одном вызове — ошибка проверки. Хозяину хвост приходит отдельным последним параметром — списком пар `[](name, value)` в порядке записи. Хвост бывает только у внешних функций, у функций автора и каталога его нет. Вызов без пар допустим: хвост пуст (пустой словарь), хозяину приходит пустой список. В дереве параметр-хвост — запись `{name, type, tail: true}` в `params` (`type` — тип значений хвоста), у вызова — поле `named: [{name, value}]` в порядке записи; в записи реестра хозяина параметр-хвост помечается так же (`tail`). Свои записи, а не вызовы функций: подключение фрагмента `Пауза(параметр: значение, …)` (раздел 9), литерал записи `Тип { поле: выр }` и `отменить_открытые(кроме: вложенные)` (раздел 5).
- **Функции списка с лямбдой**. Восемь функций каталога (`фильтр`, `отобразить`, `любой`, `все`, `количество`, `первый_где`, `свёртка`, `словарь`, раздел 12) вызываются методом своего первого аргумента — списка: `xs.фильтр(x => выр)`, `xs.свёртка(начальное, (н, x) => выр)`, `xs.словарь(x => ключ, x => значение)`; цепочка — `xs.фильтр(…).количество(…)`. Остальные функции каталога, функции автора и внешние функции зовутся вызовом `имя(…)`. Имя после точки без `(` — поле записи (`итог.пробы`), имя функции списка после точки с `(` — вызов метода; поле записи или формы с именем функции списка — предупреждение проверки, а не ошибка: такое имя есть у полей машин пакетов (`count`), а вызов метода `x.количество(…)` от поля `x.количество` отличают скобки. Прежний вызов этой функции обычным вызовом со списком первым аргументом (`фильтр(xs, x => выр)`) — ошибка. Дерево — прежний обычный вызов функции списка, получатель — первый аргумент (раздел 6).
- **Диапазон**. `a..b` — список целых `[a, b)`: полуоткрытый, пуст при `b <= a` (как прежний `диапазон(a, b)` и `a..b` Новы; включающий — `a..=b`, ниже); операнды — `число`. **Лексика:** `..` после числа или имени — всегда знак диапазона, никогда не часть дробного литерала: `1..п` читается `1`, `..`, `п`, а `0.5..2` — `0.5`, `..`, `2` (тип — ошибка: операнды не `число`); `...` — спред (самое длинное совпадение). Метод на диапазоне пишется в скобках: `(1..п).свёртка(…)` (`.` связывает сильнее `..`). В дереве — вызов `range` (раздел 6).
- **Включающий диапазон**. `a..=b` — сахар для `a..(b + 1)`, как `a..=b` Новы (конец `b + 1`): список целых от `a` до `b` включительно, пуст при `b < a`; операнды — `число`; приоритет и правила — как у `..` (самый низкий, `a..=b + 1` — `a..=(b + 1)`, не цепляется, метод — в скобках: `(1..=п).свёртка(…)`). **Лексика:** самое длинное совпадение — `...` (спред), затем `..=`, затем `..`; `..=` пишется слитно: `a.. =b` (`..`, затем `=`) и `a..==b` — ошибка. В дереве — вызов `range` с аргументами `a` и `b + 1` (раздел 6), тот же, что у `a..b + 1`.
- **Литерал словаря**. `[ключ: значение, …]`, как `[k: v]` Новы (`[ВидДействия.Чтение: "ask", ВидДействия.Запись: "deny"]`, `["a": 1]`): после `[` разбирается первое выражение; следующий знак `:` — литерал словаря, дальше пары `выр: выр` через запятую; `,` или `]` — литерал списка; разделитель пары — первое `:` вне вложенных `()`, `[]`, `{}` (`[событие_журнала("x", имя: "1")]` — список: `:` именованного аргумента стоит внутри скобок). `[]` — пустой список или пустой словарь по **ожидаемому типу**; источники ожидаемого типа: тип данного (столбец «тип»), константы, параметра; тип поля — в литерале записи и формы, в копии записи и в ячейке «выражение» `Запроса` (тип поля входа вызываемой машины, иначе данного того же имени); тип результата функции из её заголовка (тело — `[]`); тип параметра функции с объявленной сигнатурой — функции автора (аргумент вызова); тип левой части присваивания; тип другого операнда `==`, `!=`, `+` (`к_отправке != []`, `открытые_запросы == []`); у правого операнда `??` — тип места, а без него тип левого операнда без `?` (`м[к] ?? []`); значение ветки `если`/`выбор` и последнее выражение блока — тип, ожидаемый по месту; начальное значение `свёртка` — тип результата вызова; вид параметра подключения фрагмента (`вложенные: []` — пустой список машин, раздел 9). Тип вызова `xs.фильтр(…)`, `убрать(xs, x)` и `без_ключа(m, k)` — тип первого аргумента: по нему известен тип другого операнда (`xs.фильтр(x => x > 0) == []`). Параметр функции каталога по сигнатуре раздела 12 источником ожидаемого типа не служит; где ожидаемого типа нет (например, `[] == []`), `[]` — ошибка проверки типов. Ключи и значения — выражения, вычисляются слева направо (3.3); повтор константного ключа в литерале — ошибка проверки (разбор), ключи, ставшие равными только при вычислении, — ошибка машины `duplicate_key` (3.3); у полного словаря литерал называет все ключи (раздел 2). Литерала словаря в фигурных скобках нет: `{выр: выр}` и `{}` — ошибка.
- **Множество после `в`** (английское `in`) — литерал списка: `причина в [КодСбоя.А, КодСбоя.Б]`, `остановка в [""]`; стоит только в `сбой(причина в […])`, «когда» концов и `Кроме` (4.3, 4.7); элементы — значения закрытого типа (элементы перечисления, литералы без вставок); `in {…}` — ошибка.
- **Вставки в текстовых литералах**. `"…${выр}…"` — как в Нове (`"${файл}:${номер}"`, `"ход ${номер} из ${предел}"`; английская форма та же). (а) В `${ … }` — любое выражение типа, для которого определён `строка(x)` (число, вещественное, строка, набор литералов, `ид`, перечисление, `Состояние` и `?A` от них, раздел 12); `булево` и составные типы — ошибка проверки; значение вставляется как `строка(x)` (3.3). (б) Литерал со вставкой — значение типа `строка` (3.2), а не литерал набора литералов: в наборе `"a" | "b"` (раздел 2) и в `в […]` стоят только литералы без вставок. (в) Знак `${` в тексте пишется `\${` (экранирование знаком `\`, как у `"` и `\`, 1б); одиночный `$` экранировать не нужно; пустая вставка `${}` и незакрытая — ошибка; внутри вставки допустимы литералы, в том числе со своими вставками, глубина не ограничена (`"${если есть(x) то { "есть ${обязательно(x)}" } иначе { "нет" }}"`); в ячейке таблицы знак `|` внутри вставки, как везде в ячейке, пишется `\|` — выражение с `|` лучше вынести в `пусть`. (г) Схема дерева не меняется: разбор разворачивает литерал со вставками в вызов функции каталога `склеить` (раздел 12; английское `concat`) по одному правилу: части литерала — текстовые фрагменты и вставки по порядку, пустые фрагменты опускаются; литерал без вставок — сам литерал; одна часть-вставка (`"${x}"`) — `строка(x)`; иначе — вызов `склеить(…)` с частями по порядку, не меньше двух аргументов, вставка — `строка(x)`: `"${файл}:${номер}"` — `склеить(строка(файл), ":", строка(номер))`, `"a${x}"` — `склеить("a", строка(x))` (раздел 6); генератор пишет вставкой только вызов `склеить` канонического вида (1б, рекомендация). Знак `+` у текста остаётся (3.2).
- **Альтернатива формы с полями**. Альтернатива `выбор` по форме с полями — образец, как в ячейке события (4.3) и в Нове: `выбор итог { Закончен { текст, расход: р } если есть(текст) => …, Обрезан { расход } | Отменён { расход } => …, иначе => … }`; поля привязываются как имена (`поле: имя` — с переименованием, одно имя — то же поле), привязки видны в страже и в ветке; форма без полей — именем без скобок. Имя формы ищется в типе выражения после `выбор` (как `ответ: Форма` — в типе `итог` стороны); квалифицированная запись `Тип.Форма { поле, поле: имя }` допустима, как `ответ: Тип.Вар { … }` (4.3), и `Тип` в ней — тип выражения `выбор`, иначе ошибка проверки типов (`выбор итог { ИтогХода.Закончен { текст } => текст, иначе => "" }`); `Имя { … }` в альтернативе — всегда образец, а не литерал: альтернатива стоит до `=>`, а значение формы с полями в выражении пишется только с именем типа `Тип.Вар { поле: выр }`, поэтому `Имя { … }` без точки в выражении — литерал записи типа `Имя`. У альтернатив через `|` у каждой свои скобки. Прежняя запись `Форма(поле, поле: имя) =>` — ошибка; круглые скобки после имени — только вызов функции.
- **Ветки `выбор`** (по D452 Новы: армы `match` на одной строке разделяет `,`, в многострочной форме — только перевод строки): на одной строке ветки разделяет `,` — `выбор вид { Удаление | Перенос => истина, иначе => ложь }`; после последней ветки запятой нет. Многострочный `выбор` (в блоке кода) ветки разделяет переводом строки: `{` стоит в конце строки заголовка, каждая ветка — своей строкой, без `,` и `;` в конце, `}` — своей строкой; ветка `=> { … }` может занимать несколько строк (переводы строк внутри блока ветки ветки не делят), ветка `иначе => …` — так же. Ветки — альтернативы, а не последовательность, поэтому `;` между ними — ошибка; `,` в конце строки ветки многострочного `выбор` — ошибка (D452 снял запятую в многострочной форме, включая хвостовую); две ветки на одной строке многострочного `выбор` и ветка на строке `{` или `}` — ошибка (смешанной формы нет). Ячейка таблицы — одна строка, поэтому `выбор` в ячейке всегда однострочный. `;` внутри блока ветки (`=> { пусть x = выр; x }`) — разделитель блока и остаётся.
- **Голые имена** (как правило 1 D478 Новы). Имя элемента перечисления или формы без полей пишется без имени типа: в альтернативе `выбор`, в элементе `в […]`, в ключе литерала словаря и полного словаря и индексе `выр[ключ]`, на стороне `==`, `!=` и в других местах выражения. Голое имя ищется среди перечислений, объявленных в машине, в подключённых файлах функций и во фрагментах; ожидаемый тип места для поиска не нужен; тип голого имени — тип, который его объявляет, общей сверки типов операндов формат 2.25 не вводит (см. [журнал изменений](alula-changelog.md), «Открытое»). Ошибка проверки (нужна квалификация `Тип.Эл`): имя объявлено в двух типах; имя совпало с данным, константой, параметром или привязкой. Квалифицированная форма `Тип.Эл` допустима всегда. Выбор между суммами по ожидаемому типу (D478 Новы) не взят: переводчик не выводит тип каждого места. Имена состояний — литералы встроенного перечисления `Состояние` — так писались и прежде (`состояние != ПАУЗА`, раздел 9). Форма с полями в выражении — только `Тип.Вар { поле: выр }`: `Имя { … }` без точки — литерал записи типа `Имя` (ниже). Пример (тот же смысл, что у квалифицированной записи): `выбор вид { Удаление | Перенос | Исполнение => истина, иначе => ложь }`, `сбой(причина в [СоединениеОборвалось, НетОтветаВСрок, НетРезультата])`, `проверка == Верна`, `ПОЛИТИКА_РАЗРЕШЕНИЙ[Чтение]` (ключ типа `ВидДействия`); если `Верна` объявлена и у `Проверка`, и у другого перечисления машины, пишется `проверка == Проверка.Верна`.
- **Из подсчёта методики не вводятся:** `contains`, срезы, постфиксный `?`, сортировка, циклы и рекурсия вне `для`.

**Позиция блока**. Знак блока один — `{ … }`; что в нём и есть ли значение, задаёт позиция:

| Позиция | Где | Содержимое блока | Значение |
|---|---|---|---|
| действие | строка «Действия», «При приёме», «При входе» операции и конца (4.5, 4.7), ветка условного действия, тело `для`, блок `{ действия }`; не «При входе» развилки (там только привязки `пусть`, 4.6) | действия через `;`, в том числе `пусть имя = выр` (видна до `}`) | нет |
| выражение | ветка условного выражения, тело-блок функции (после типа результата, без `=>`), правая часть присваивания и `пусть`, аргумент, ячейка выражения | ноль или несколько `пусть имя = выр;`, последним — одно выражение | последнее выражение |

Блок-выражение отличается от литералов с фигурными скобками так: литерал записи и формы стоит после имени типа (`Тип { … }`), образец альтернативы `выбор` — после имени формы, до `=>`; копия записи начинается с `...`; иначе `{` открывает блок. Литерала словаря в фигурных скобках нет — словарь пишется `[к: з]`, поэтому просмотр вперёд до `:` не нужен; `{}` — ошибка: пустого блока нет, пустой словарь — `[]`. После типа результата в заголовке функции `{` всегда открывает тело-блок, а сразу после `=>` блока не бывает.

Пример выражений (пилот «Шаг агента», функции).

```
функция требует_повышенного_внимания(вид ВидДействия) -> булево =>
  выбор вид {
    ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима => истина
    иначе => ложь
  }

функция пауза_повтора(п число>=0) -> число =>
  (1..п).свёртка(ПАУЗА_ПОВТОРА, (н, _) => н * 2)
```

### 3.2 Типы выражений

| Правило | Запись |
|---|---|
| Возведение `T` в `?T` | в присвоении полю `?T`, в поле конструктора записи, в аргументе функции с параметром `?T`, в ветке `если`/`выбор`, справа от `??` |
| `если`, `выбор` | ветки `T` и `?T` (или `пусто`) дают `?T`; ветки одного типа — этот тип |
| `??` | `?T ?? T` — `T`; `?T ?? ?T` — `?T`: правый операнд любого из двух типов, результат `T` только при правом `T` |
| `+` | число, вещественное (смешивать нельзя), строка (склейка), список одного типа (склейка: сначала левый) |
| `==`, `!=` | структурные для записей, кортежей, списков, словарей, перечислений, в том числе с полями (форма без полей — `x == Тип.Вар` или голое `x == Вар`; форма с полями — `x == Тип.Вар { поле: выр }`), наборов литералов, `?T`; `T` с `?T` — через возведение (`пусто` не равно значению) |
| `<`, `<=`, `>`, `>=` | число, вещественное |
| `выр[ключ]` | словарь: `?V`, отсутствующий ключ — `пусто` (не ошибка); у полного словаря — `V`. Список: `?T`, индекс вне границ — `пусто` |
| Набор литералов | значение выражения — **набор значений**: литерал — одно; `+` — попарные склейки; `если`/`выбор` — объединение веток; `обязательно(x)` — набор `x` без `пусто`; `обязательно_непустое(x)` — набор `x` без `""`; `строка(x)` для перечисления или его подмножества — их значения; присвоение и сравнение с данным типа «набор литералов» проверяют вхождение набора. Склеиваемое поле с «пустым» началом объявляется по источнику: источник даёт «нет» — `?("a" \| "b")` без `""`, пусто и `обязательно`; источник даёт `""` — `"" \| "a" \| "b"`, начальное `""` и `обязательно_непустое`. Одно значение другим не заменяется: в снимке данных `""` и `none` различны |
| набор литералов → `строка` | значение набора присваивается данному и передаётся параметру типа `строка`, набор при этом забывается; обратное — по вхождению набора |
| `ид` → `строка` | присваивается данному и параметру типа `строка`, тип `ид` при этом забывается; обратное — только литерал формата UUID (раздел 2) |
| Литерал со вставками `"…${x}…"` | `строка`, не набор литералов: значение вставки не закрыто, поэтому присвоение данному типа «набор литералов» — ошибка проверки; `x` — тип, для которого определён `строка(x)` |
| `число>=n` | присвоение значения, нарушающего границу, — ошибка машины; статически проверяется только для литералов и констант; `число>=n` совместимо с `число` в обе стороны. Результат `+`, `-`, `*` над `число>=n` — `число` (без границы): `номер_захода - 1` — `число`, передача его параметру `число>=0` проверяется при вызове |
| `недостижимо` | тип любой: совместимо с `T` и `?T`; в `выбор` не влияет на тип результата |

Пример (пилоты «Шаг агента» и «Совещание»; `сбойное_обращение` объявлено `"" | "Witness" | "Lenses" | "AuthorFix" | "AuthorQuestion"` (набор литералов), начальное `""`, как в источнике: набор после `обязательно_непустое` — без пустого значения).

```
остановка = строка(причина)                                     // причина в [СоединениеОборвалось, НетОтветаВСрок, НетРезультата]: набор "connection_lost" | "timeout" | "no_result"
остановка = обязательно_непустое(сбойное_обращение) + "_halt_meeting"      // набор: четыре значения «..._halt_meeting», все входят в набор остановка
текст_отказа = "ход ${число_ходов} из ${предел_ходов}"         // вставки: тип строка, не набор; дерево — склеить("ход ", строка(число_ходов), " из ", строка(предел_ходов))
```

### 3.3 Вычисление

- Вычисление строгое, слева направо: аргументы функции, поля записи, элементы списка и словаря — в порядке записи; ветви `выбор` — сверху вниз, охрана `если` — после совпадения альтернативы; привязка `пусть` в блоке — сначала значение, потом остаток блока. **Ленивы** только `если`, `и`, `или`, `??`: невыбранная ветка и правая часть, которая не нужна, не вычисляются.
- **Вызов изменчивой функции внутри `если`/`выбор`**: выбранная ветка вычисляет вызов, невыбранная — нет (ленивость выше); чтение вызова входит в чтения состояния безусловно, по списку `читает` функции. Вызовы в аргументах вычисляются в порядке записи.
- **Язык не тотален.** Два рода частичных операций.
  - **Дефект программы**: `обязательно(x)` при пустом `x`, `обязательно_непустое("")` и `недостижимо` — процесс останавливает исполнитель (не таблица); перехода в ОШИБКА нет, состояние машины не откатывается; ответ вызова — конец с `NoResult`; журнал дефекта — на усмотрение исполнителя (так ведёт себя `required` автоматов).
  - **Ошибка машины:** переполнение `число`, деление на ноль, выход за `число>=n`, `число(x)` вне диапазона, повтор ключа в литерале словаря с вычисляемыми ключами и в `xs.словарь(…)`, отсутствующий ключ в `имя[ключ].поле = выр`, индекс вне границ при записи в список. Исполнитель пишет событие журнала `machine_error` с параметром `reason` — словом из закрытого перечня `overflow`, `division_by_zero`, `bound_violation`, `conversion_range`, `duplicate_key`, `missing_key`, `list_index` (журнал, подраздел «События формата таблиц») — и входит в ОШИБКУ; это событие — `запись_перехода` (3.1).
  - Индекс словаря и списка при чтении частичной операцией не является.
- `если` не вкладывается в ветку другого `если` (три и более исхода — `выбор` с охранами или развилка).
- `строка(x)`: целое — десятичная запись; дробное — кратчайшая десятичная запись, обратимая в то же дробное; целое значение пишется с `.0` (`1.0`, `0.0`); без порядка `e`, если `1e-4 <= |x| < 1e16`, иначе порядок вида `1e-7`, `1.5e20` (строчная `e`, без `+` и без ведущих нулей порядка); примеры: `0.0`, `2.0`, `0.42`, `0.0001`, `1e-7`, `1.5e20` — каждая запись и литерал дробного (3.1), поэтому генератор пишет значение обратно ею; NaN и бесконечность — ошибка машины; перечисление — значение элемента (у элемента без значения — JSON-имя); `Состояние` — JSON-имя; текст — он сам; `пусто` любого из этих типов — `none`. Для `булево` и составных типов `строка` не определена.

## 4. Состояния

### 4.1 Общее

Заголовок `### ИМЯ — вид`: вид — `обращение`, `операция`, `развилка`, `конец`; **JSON-имя состояния** (1а) — латинское, для журнала и конверта (поле `state`, параметр `fork`, `строка(Состояние)`): автоматическое (`ПОВТОР` → `Retry` по словарю; у латинского — само имя, `### Retry — развилка`) или, где оно неверно, строка `## Имена` (`| ОТКРЫТИЕ | Opening |`, `| Pass | Gate3 |`); скобок в заголовке нет. Примеры ниже записаны с русским именем в заголовке. Номер `№` строки = метка `// ИМЯ #n` в первоисточнике. Выбирается **первая** подходящая строка. Начальное состояние — первая строка раздела `## Состояния`: `Начальное состояние: ИМЯ`; проверка 34(г) требует, чтобы оно называло состояние раздела. **Чтения состояния** (правило 11): у обращения — таблица `Запрос:` (4.2), у операции, развилки и конца — строка-ключ `Читает:` с именами данных, которые читают «При входе», условия и действия состояния, через запятую; состояние, которое ничего не читает, строки `Читает:` не пишет, обращение без полей запроса — строки `Запрос:`; чтения изменчивой функции (раздел 7) входят в чтения состояния по его списку `читает`; `Читает` ОШИБКИ — `все_данные` (все данные машины без данных исполнителя; имена читаются как данные).

**Строки-ключи состояния** — `Сторона`, `Срок тишины`, `Правит`, `Возвратов формы`, `Запрос`, `Читает`, `При входе`, `При приёме`, `Кроме`, а в разделах `## Стороны` и `## Концы` — `Предел запросов` и `Результат` — **элементы маркированного списка**: `- Сторона: агент`, `- Срок тишины: СРОК_БЕЗДЕЙСТВИЯ`, `- Читает: число_повторов, ход`. Маркер `- ` необязателен при разборе (совместимость с версией 2.5), обязателен в записи; причина: markdown склеивает идущие подряд строки в один абзац, и предпросмотр показывает «Сторона: агент Срок тишины: СРОК_БЕЗДЕЙСТВИЯ Запрос:» одной строкой. **Пустые значения не пишутся**: ключ с пустым значением (`—`, `нет`: полей запроса нет, читать нечего, срока нет, работы при входе нет) пропускается, и пропуск значит умолчание; `- Срок тишины: —`, `- При входе: —`, `- Вход: нет` не пишутся. Ключ с настоящим значением по умолчанию (`- Срок тишины: 0`, `- Возвратов формы: 0`) может остаться написанным: так он показывает, что значение выбрано, а не забыто. Остальные правила записи:

- таблица (поле запроса | выражение | читает у `Запрос`; событие | действия у `При приёме`; строки состояния) стоит **на уровне блока**, не внутри элемента списка: между последним элементом списка и таблицей, как и между двумя таблицами, — пустая строка; сам элемент (`- Запрос:`, `- При приёме:`) остаётся последним в списке перед своей таблицей;
- значение в одну строку — в самом элементе (`- При входе: пусть момент = событие.момент`); тело «При входе» из нескольких действий — вложенный список, по действию в элементе (`  - пусть сейчас = событие.момент;`), знак `;` в конце элемента сохраняется, разбор склеивает элементы в тот же список действий через `;`;
- заголовок состояния `### ИМЯ — вид` и строка `Начальное состояние: ИМЯ` (одна на раздел) списком не записываются.

**Проза**. Абзац — одна или несколько строк текста между пустыми строками (пустая строка нужна и до, и после) вне таблиц, вне блоков кода и вне строк-ключей — комментарий для читателя: переводчики и проверки его пропускают, знаки «`» и «« »» внутри него допустимы. Строка текста, прижатая вплотную к таблице, заголовку или элементу списка без пустой строки, абзацем не является (markdown склеивает её с соседним блоком): проверка форматирования предупреждает, разбор читает её как лишнюю строку соседнего блока. Прозой не считаются заголовки `#`, `##`, `###`, таблицы и элементы списков строк-ключей (`- Ключ: …`). Чтобы опечатка в ключе не стала молчаливым комментарием, проверка форматирования (раздел 10) предупреждает о строке-абзаце, которая начинается со слова из перечня ключей (`Сторона`, `Срок тишины`, `Запрос`, `Читает`, `Правит`, `Возвратов формы`, `При входе`, `При приёме`, `Результат`, `Кроме`, `Предел запросов`) без маркера `- ` или с опечаткой в нём.

**«Куда»:** имя состояния; `предыдущее`; `возврат_подготовки` (правило 24); `то же` (остаться в состоянии; допустимо в строках обращения и в общих событиях; без перезапуска выполняются только действия строки — повторного входа нет, запрос не шлётся; с перезапуском — `то же, запуск заново` — состояние входится заново: открытый запрос обращения отменяется и посылается новый; пример: `| 3 | сигнал(повторить) | — | журнал("retry_requested") | то же, запуск заново |`); суффикс `, запуск заново` (правило 18); `—` у строки с `ошибка_машины`.

**Умолчание развилки и `иначе`**. Строка `иначе` по правилу 27 записывается последней, с действием `ошибка_машины("fork_no_match", fork: "<JSON_имя>")` (значение `fork` — текстовый литерал) и `Куда` `—`; её метка — следующий номер после последней строки условий. Строка `иначе` **обязательна**, если исчерпание условий не доказано типом; развилка без `иначе` и без доказанного исчерпания — ошибка проверки. **Исчерпание доказано типом**, когда условие каждой строки, кроме `иначе`, — сравнение одного и того же имени `x` (данное, привязка `пусть`, `событие.<поле>`) закрытого типа с одним его значением: `x == Тип.Эл` у перечисления `Тип` (или голое `x == Эл`), `x == Тип.Вар` у перечисления, все формы которого без полей, `x == "метка"` у набора литералов (`"a" | "b"`, раздел 2) — и строки называют все значения типа (как у `выбор`, раздел 2). Тогда `иначе` необязательна: развилка без неё не может остаться без подходящей строки; написанная `иначе` недостижима — **предупреждение** проверки, а не ошибка (обычно это `иначе` с `ошибка_машины`, оставшаяся по привычке). Исчерпания не доказывают: условие над текстом — имя типа `строка` (`продолжение == "…"` с метками-строками: сколько бы меток ни было, тип их не закрывает; закрыть набор — объявить тип набором литералов или перечислением), над двумя полями (пара перечислений: произведение типов не доказывается, `иначе` — ловушка непредусмотренного сочетания), над `?T` (`пусто` не назван), условие с `и`, `не`, `!=`, `<`; у таких развилок `иначе` остаётся.

### 4.2 Обращение

```
### ИМЯ — обращение
- Сторона: <имя из «Стороны»>[; набор: <выражение-список идентификаторов>]
- Срок тишины: <выражение типа ?число>=0>   необязательно; пустое (`—`) не пишется, не написан — срока нет
- Правит: <данное>; проверка: <изменчивая функция>   необязательно (правило 14)
- Возвратов формы: <число>=0>                необязательно, по умолчанию 0 (`0` можно написать)
- Запрос:                                    необязательно: нет полей запроса — строки нет

| поле запроса | выражение | читает |       выражение `—` — то же имя; читает: сторона | исполнитель

- При приёме:                                  необязательно

| событие | действия |
| <событие> | <действия> |

| № | Событие | Условие | Действия | Куда |
```

- **Запрос.** `читает: сторона` — поле запроса стороне; `исполнитель` — имя, которое читают строки состояния, а в запрос оно не идёт: запись **объявляет зависимость** состояния (оно использует это данное в своих условиях и действиях; правило 11 «шаг читает только свой Вход»), а не действие, которое что-то выполняет; проверка до запуска сверяет строки состояния с объявленными именами, а при исполнении исполнитель берёт текущее значение данного, как в любом выражении (выражение — то же имя, `—`). **Выражение по умолчанию**: `—` в ячейке «выражение» значит «то же имя» — выражение поля равно имени поля (`| номер_захода | — | исполнитель |` — то же, что `| номер_захода | номер_захода | исполнитель |`); это не «нет значения», а знак `—` — потому что пустая ячейка теряется при правке и в просмотрщиках. Имя поля при `—` обязано быть именем, которое выражения «Запроса» читают (данное, константа, параметр, `вход`, `сторона` у набора, у стороны `machine` — `трасса`, `номер_шага`), иначе ошибка проверки, как у любого выражения. Явное выражение, равное имени поля, допустимо, но не рекомендуется: проверка предупреждает, канонический вид пишет `—` (1б). Столбец «выражение» остаётся и при `—` во всех строках: шапки таблиц не убираются (без шапки markdown таблицу не показывает). Строки состояния, «При приёме», «Срок тишины» читают **любое** имя из `Запрос`, с каким бы значением `читает` оно ни стояло. Поле запроса `профиль` в «Запросе» не пишется: его даёт столбец `профиль` «Сторон». Выражения читают данные машины, константы, параметры, `вход`, `сторона` (набор) и — у стороны `machine` — `трасса`, `номер_шага`; допустим вызов изменчивой внешней функции (вычисляется при входе, до отправки, в порядке строк). Поля запроса стороны `machine` — ровно поля её типа `вход`, кроме `профиль` (его даёт столбец «Сторон»). Поле запроса может называться как данное при ином выражении (`предыдущее` — `обязательно(предыдущее)` у ПАУЗЫ): строки, условия и «При приёме» читают **данное**, а не поле, поле видно только стороне, и такое поле — только `читает: сторона`; выражение такого поля — любое выражение «Запроса», в том числе с вызовом внешней функции и `если` (у ИЗМЕНЁН «Совещания» поле `предложение` — `если предложение_прочитано() то { предложение } иначе { пусто }`), строки его не читают. Условия, «При приёме» и «Действия» читают только имена из `Запрос`, `событие.…`, привязки, константы и параметры (правило 11).
- **`читает` по умолчанию**. Если источник не говорит, кто читает поле (в его таблице «Вход» состояния нет столбца «Кто читает»), пишется `сторона`: поле уходит в запрос, как в источнике; `исполнитель` — только для имён, которые источник называет не идущими в запрос.
- **Обращение без полей запроса**. Если стороне не нужны поля запроса (ворота «повторить / остановить» без данных), строка `Запрос:` и таблица не пишутся: запрос несёт только то, что даёт исполнитель (конверт, `профиль` из столбца «Сторон»); строки, «При приёме» и «Срок тишины» такого состояния данных машины не читают — только `событие.…`, привязки, константы и параметры. У стороны `machine` запрос без полей допустим, только если у типа `вход` нет полей (раздел 1).
- **Обращение со свободным вводом** (правило 19). `Сторона` — сторона вида `human` без счётчика (раздел 1): ворот и запроса нет, исполнитель ничего не отправляет и не показывает, машина ждёт слова. Поэтому у такого обращения нет `Запрос`, `набор`, `Срок тишины`, `Правит`, `Возвратов формы`, строк `ответ` и `сбой` (проверка раздела 10); строки — по сигналам стороны (`сигнал(сообщение { содержание, автор, источник })`); слово принимается по имени сигнала в текущем состоянии, слово, для которого строки нет, отбрасывается (правило 17); «стоп человека» — общее событие (правило 23).
- **Срок тишины.** Строка не написана (пустое значение `—` не пишется), `пусто` или `0` — срока нет ( у человека срока нет — открытые ворота, правило 19; у вратаря срок в состоянии не пишется: срок вратаря-агента — параметр вратаря, правило 19; у вызова машины срока нет, правило 35, пункт 5). Выражение читает те же имена, что выражения «Запроса» (данные, константы, параметры, `вход`, `сторона` у набора), без вызова изменчивых внешних функций (чистые функции и функции каталога допустимы); эти имена названы в `Запрос` состояния. Вычисляется при входе, после «Запроса», до отправки запроса.
- **Правит** (правило 14). `Правит: <данное>; проверка: <внешняя функция>` — ответ стороны правит объект, который отражает данное (`предложение`), и результат нельзя принять, если объект изменился с начала попытки. `проверка` — изменчивая внешняя функция без параметров с результатом `булево`; исполнитель вызывает её при приёме ответа, после проверки открытости запроса и формы и до `разбор` и «При приёме». `истина` — результат не принимается (в `принятые_запросы` не пишется, «При приёме» не выполняется, события нет), запрос отменяется и уходит заново: новая попытка, `Запрос` вычисляется заново; запись об этом в журнал — механика исполнителя. «Началом попытки» и сравнением владеет исполнитель, функция читает его служебную запись и объект (`читает` в реестре хозяина). Данное из `Правит` обязано записываться в «При приёме» этого состояния (проверка таблицы).
- **Набор** (правило 21): `Сторона: линза; набор: порядок_линз` — по запросу на каждый идентификатор; `сторона` в «Запросе» — идентификатор, для которого строится запрос; `Предел запросов` — раздел «Стороны». `к_отправке` — данное `действия и механика`, `открытые_запросы` — `механика` (раздел 2), счётчик попыток стороны — столбец `счётчик` «Сторон» (раздел 1).
- **Возвратов формы** — сколько раз исполнитель возвращает стороне ответ не по форме или не по сверке, которую делает `разбор` (например, выдержек; правило 18). У видов, кроме `machine`, — в том же запросе. У стороны `machine` — новым запросом той же стороны с новым идентификатором и замечанием: тот же идентификатор вернул бы готовый ответ (правила 14, 35, пункт 4). Сверку (например, выдержек) делает внешняя функция `разбор` при приёме, сам возврат — механика исполнителя. Возвраты исчерпаны — запрос закрывается событием `сбой` с кодом `ФормаНеИсправлена` (сбой разбора, раздел 1).
- **Условие** в строке события — только у общих событий и сигналов фрагмента (правила 23, 35); у строк обращения `—`. Событие, чьё условие ложно, отбрасывается (правило 17, запись в журнал — механика). Условие `иначе` допустимо у сигнала: последняя строка того же события, берётся, если условия предыдущих строк этого события не истинны; у остальных событий `иначе` нет.

Пример (пилот «Совещание», ЛИНЗЫ). Выражение, равное имени поля, — `—`; ключ находок — кортеж; имена `трасса`, `номер_шага` (не изменчивые функции `трасса_вызова`, `номер_шага_вызова`); строки `профиль` нет; показаны не все строки «Запроса».

```
### ЛИНЗЫ — обращение
- Сторона: линза; набор: порядок_линз
- Срок тишины: 0
- Запрос:

| поле запроса | выражение | читает |
| вид | ВидВызывающего.Линза | сторона |
| сессия | сторона | сторона |
| контекст | контекст_роли(КонтекстРоли.Линза { предложение: предложение, ответы_свидетеля: ответы_свидетеля[номер_захода] }) | сторона |

### 4.3 События обращения

Таблица строк `| № | Событие | Условие | Действия | Куда |`. Виды событий:

| Событие | Смысл |
|---|---|
| `ответ`, `ответ(имя)` | значение ответа (результат стороны или результат её `разбор`, раздел 1); `имя` привязывает его целиком |
| `ответ: Форма { поле, поле: имя, … }`, `ответ: Форма`, `ответ: Тип.Форма { … }` | значение ответа — форма типа `итог` стороны (у `machine` с `разбор` — результата разбора); поля привязываются как имена (`поле: имя` — с переименованием); форма без полей — без скобок |
| `сбой`, `сбой(причина)`, `сбой(причина в […])` | отказ или «нет ответа» (правило 16); закрытое подмножество кодов — **список состояния**: объединение наборов его строк `сбой` (строка без набора — все `КодСбоя`). Код вне списка исполнитель приводит к `КодСбоя.НетРезультата` (правило 16), событие несёт уже его; если и `НетРезультата` вне списка — `недостижимо` (набор объявлен полным для состояния) |
| `сигнал(<сигнал>)`, `сигнал(<сигнал> { поле, поле: имя, … })` | **сигнал стороны** обращения (`human`, `enhanced`, вратарь): сигнал — из столбца «сигналы» стороны, поля и их типы — оттуда же; либо **сигнал машины** вне контракта (стоп, отмена, сигналы от родителя) — только в общих событиях и ПАУЗЕ фрагмента (раздел 9); у строки сигнала машины допустимо условие `иначе` (4.2) |
| `сразу` | у операции: переход без события после работы при входе (правило 26) |

- **Образец и вызов**. Ячейка события несёт либо образец, либо функцию события формата:

| Форма | Запись | Пример |
|---|---|---|
| образец формы с полями (ответ стороны) | `ответ: Вар { поле, поле: имя }`, `ответ: Тип.Вар { … }` | `ответ: Закончен { текст, артефакт, расход: полученный }` |
| образец сигнала с полями | `сигнал(с { поле, поле: имя })` | `сигнал(засчитан { находки: новые })` |
| объявление сигнала с полями (столбец «сигналы» «Сторон», не ячейка события) | `с { поле тип, … }` | `засчитан { находки []Находка }` |
| альтернатива `выбор` по форме с полями (участок кода, не ячейка события; 3.1) | `Вар { поле, поле: имя } => выр`, `Тип.Вар { … } => выр` | `Закончен { текст, расход: р } => текст` |
| форма или сигнал без полей | имя без скобок | `ответ: ВременнаяОшибка`, `сигнал(разрешить)` |
| функция события формата | вызов `имя(…)` | `ответ`, `ответ(имя)`, `сбой`, `сбой(причина)`, `сбой(причина в […])`, `сигнал(…)` |

  Образец события с фигурными скобками стоит в ячейке события (столбец «Событие» строк перехода и общих событий, столбец «событие» таблицы «При приёме»), а образец формы с полями — ещё и в альтернативе `выбор` (до `=>`, 3.1); с блоком они не пересекаются: в ячейке события блока нет, поэтому `Имя {` в ней — всегда образец, а в `выбор` образец стоит после имени формы до `=>`, после `=>` — значение ветки (выражение, в том числе блок-выражение). Прежняя запись образца в круглых скобках (`ответ: Закончен(…)`, `сигнал(засчитан(…))`) — ошибка. Объявление сигнала с полями в столбце «сигналы» «Сторон» (`засчитан { находки []Находка }`) и альтернатива `выбор` по форме с полями (`Закончен { текст } => …`, 3.1) с 2.20 пишутся теми же фигурными скобками, прежние `засчитан(находки []Находка)` и `Закончен(текст) =>` — ошибка; фигурные скобки альтернативы стоят в участке кода, но до `=>` и после имени формы, поэтому с блоком не путаются (3.1, «Позиция блока»). Круглые скобки после имени — только функции: функции событий формата (последняя строка таблицы), функции каталога, функции автора, внешние функции и конструкторы ответа `Ответ(…)`, `Отказ(…)` (4.7).
- **Привязки.** Любое поле события доступно и как `событие.<поле>`; привязка нужна для краткости. Имя привязки, совпавшее с именем данных машины без переименования, — ошибка проверки (затенения нет). Привязывать можно часть полей. **Частичный образец без `..`**: в Нове частичный образец записи требует явного `..` (D486 §3), а в Алуле образец события (`ответ: Закончен { текст }`) и альтернатива `выбор` (`Закончен { текст } =>`) привязывают часть полей без `..`. Причина: непривязанные поля события читаются как `событие.<поле>`, привязка нужна только для краткости, и знак `..` в ячейке таблицы ничего бы не добавил; решение методики, принятое владельцем (чат методики, 2026-10-22: «по рекомендации»).
- **Поле, названное как данное**. Поле сигнала или формы может называться как данное машины (сигнал `подтвердил { подтверждение строка }` при данном `подтверждение`): затеняет не объявление поля, а привязка; такое поле привязывается с переименованием (`сигнал(подтвердил { подтверждение: слово_подтверждения })`) или читается как `событие.подтверждение`. Данные машины здесь — вместе с данными подключённых фрагментов, и проверка идёт после подстановки фрагмента: привязки строк фрагмента «Пауза» (`слово_человека`, `автор`, `источник`, `идентификатор_запроса`; в английском файле — имена английского файла фрагмента) не совпадают ни с одним данным машины, поэтому данное машины так не называют (словарь версии 10: `источник_запуска` → `launch_source`, а не `source`).
- **Набор.** События набора несут `сторона`; цепочка развилок за строкой события читает её как `событие.сторона` (правило 13).
- **Сигналы стороны**. Сигналы состояния — сигналы его строк. Сигнал стороны принимается строкой обращения, чья `Сторона` его объявила; сигнал человека несёт идентификатор открытых ворот, а с идентификатором не открытых ворот отбрасывается (правила 17, 19); при воротах нескольких сторон в одном состоянии сигнал принадлежит стороне, названной в идентификаторе, а сигнал, которого она не объявила, или сигнал от другой стороны отбрасывается («слово чужой стороны», правило 19); сигнал человека на ворота, принятые ответом вратаря-агента, до перехода по этому ответу заменяет его (окно 2, правило 19); слово свободного ввода (сторона `human` без счётчика, 4.2; правило 19) идентификатора ворот не несёт и принимается строкой текущего состояния по имени сигнала, без записи ворот; сигнал, которого сторона не объявила, — ошибка проверки строки. Объявленный сигнал стороны, для которого у текущего состояния строки нет, строкой состояния не принимается; он отбрасывается, а ворота остаются открытыми (правила 14, 17, 19). Каждый сигнал стороны используется хотя бы в одной строке машины (или фрагмента); сигнал события строки обращения входит в список сигналов его стороны. Поле сигнала объявляется в столбце «сигналы» в фигурных скобках через пробел (`засчитан { находки []Находка }`), а в строке привязывается `поле: имя` (3.1).
- «При приёме» — действия ДО перехода (правило 14), раздел 4.4.

Пример (пилоты). Сигналы с данными — запись `сигнал(засчитан { находки: новые })`; поля, совпавшие с данными, переименованы; к В3 приложена выдержка таблицы «Стороны»: сигналы `не засчитан` и `засчитан { находки []Находка }` объявлены в столбце «сигналы» вратаря, стороны обращения (поля — в фигурных скобках).

```
### ХОД_АГЕНТА — обращение       // строки 1, 3, 6, 8, 9 пилота «Шаг агента»
| № | Событие | Условие | Действия | Куда |
| 1 | ответ: Закончен { текст, артефакт, расход: полученный } | — | расход = сложить_расход(расход, полученный); текст_ответа = текст; артефакт_ответа = артефакт | ПРОВЕРКА_ОТВЕТА |
| 3 | ответ: ПределЗапросов { расход: полученный } | — | расход = сложить_расход(расход, полученный); остановка = "max_turn_requests"; журнал("turn_requests_exhausted") | УЧЁТ |
| 6 | ответ: ВременнаяОшибка | — | — | ПОВТОР |
| 8 | ответ: НужноРазрешение { запрос_разрешения: запрос } | — | запрос_разрешения = запрос | ПОЛИТИКА |
| 9 | сбой(причина в [КодСбоя.СоединениеОборвалось, КодСбоя.НетОтветаВСрок, КодСбоя.НетРезультата]) | — | остановка = строка(причина); журнал("turn_failed", reason: строка(причина)) | УЧЁТ |

| имя | идентификатор | вид | профиль | сигналы | счётчик |
| вратарь | gatekeeper | human или agent по настройке исполнитель_повышенного_внимания(итог ИсходВорот) | — | не засчитан, засчитан { находки []Находка } | попытка_вратаря |

### В3 — обращение                      // строки 1, 2 пилота «Совещание»
- Сторона: вратарь

| 1 | сигнал(не засчитан) | — | журнал("pass_probes_not_probes", pass: строка(номер_захода)); номер_захода += 1 | ЗАХОД |
| 2 | сигнал(засчитан { находки: новые }) | — | номер_захода += 1; находки_В3 = новые | ИТОГ |
```

### 4.4 При приёме

Блок обращения `При приёме:` — таблица `| событие | действия |`. Событие — `ответ`, `ответ(имя)`, `ответ: Форма { … }` или `сбой`; доступны привязки события и `сторона`; значение ответа — результат `разбор` стороны (раздел 1). Исполнитель выполняет блок при приёме ответа, до перехода, одной фиксацией с записью в `принятые_запросы` (правило 14); привязки блока (`пусть`) сохраняются вместе с принятым событием и видны его строке и цепочке. Порядок приёма: открытость запроса и форма, «Правит» (4.2), `разбор`, блок.

В блоке допустимы: присваивания данным, `+=`, `поле[ключ] = выр`, `поле[ключ].поле = выр` (5), `для`, `если`, `пусть имя = выр` (в том числе с вызовом изменчивой внешней функции в любой позиции выражения, 3.1). Недопустимы: `журнал`, `ошибка_машины`, вызов действующей функции, переход; вызовы действующих функций после приёма (например, отметка времени и проверка кеша) пишутся в действиях строки. Данные, которые пишет блок, — `пишет: действия` (2).

Пример (пилот «Совещание», ЛИНЗЫ). Значение `итог` — результат `разбор` стороны `линза` (`ИтогЛинзы`, раздел 1); запись в линзу — копия записи с заменой полей через `обязательно(линзы[сторона])`: в коде `@lenses(lens_id)` при отсутствии линзы — `unreachable` (линзы созданы при старте), то есть дефект программы, `обязательно(пусто)` (3.3); краткая запись `линзы[сторона].поле = выр` дала бы ошибку машины `missing_key` (3.3), расходясь с кодом.

```
- При приёме:

| событие | действия |
| ответ(итог) | { пусть л = обязательно(линзы[сторона]); линзы[сторона] = { ...л, потери_подряд: 0, пробы: итог.пробы } }; ответившие += 1; находки_линзы[(сторона, номер_захода)] = итог.находки |
| сбой | { пусть л = обязательно(линзы[сторона]); линзы[сторона] = { ...л, потери_подряд: л.потери_подряд + 1, пробы: 0 } } |
```

Пример (пилот «Совещание», ПРАВКА): свойство «Правит», разбор в перечисление с полями `ИтогПравки`, запись при приёме и строки по форме. Запись при приёме — по форме, а не `выбор` по обоим: при `Закончена` `вопрос_автора` не читается и не пишется, как в коде. Тип `ИтогПравки` определён в примере: поля форм — как в таблице первоисточника («закончена»: `предложение`; «вопрос»: `предложение`, `вопрос`); в коде `Done(str)` и `Asked(Asking)` с полями `proposal`, `question` — запись `Asking` развёрнута в поля формы.

```
тип ИтогПравки перечисление
  | Закончена { предложение строка }
  | Вопрос { предложение строка, вопрос строка }
```

```
### ПРАВКА — обращение
- Сторона: автор
- Срок тишины: 0
- Правит: предложение; проверка: предложение_менялось_с_начала_попытки
- Возвратов формы: 0
- Запрос:

| поле запроса | выражение | читает |
| контекст | контекст_роли(КонтекстРоли.Правка { предложение: предложение, находки_В3: находки_В3, указание_автору: если указание_автору == "" то { пусто } иначе { указание_автору } }) | сторона |

- При приёме:

| событие | действия |
| ответ: Закончена { предложение: правка } | предложение = правка |
| ответ: Вопрос { предложение: правка, вопрос: текст_вопроса } | предложение = правка; вопрос_автора = текст_вопроса |

| № | Событие | Условие | Действия | Куда |
| 1 | ответ: Закончена | — | указание_автору = "" | ЗАХОД |
| 2 | ответ: Вопрос | — | указание_автору = "" | В7 |
```
(Показаны не все строки «Запроса» и строки сбоя. Чтения внешних функций `проверка` и `разбор` входят в `Запрос` по их спискам `читает`, раздел 7.)

### 4.5 Операция

```
### ИМЯ — операция
- Читает: <имена>                         необязательно
- При входе: <пусть-привязки и вызовы>

| № | Событие | Условие | Действия | Куда |
| 1 | сразу | — | <изменения данных, журнал> | ... |
```

«При входе» — работа с внешним миром (правило 10): `пусть имя = <выражение>` (в том числе с вызовом изменчивой или действующей внешней функции), вызовы действующих функций без результата — действие `имя(арг);`. Привязка видна дальше в «При входе» и во всех строках состояния; вычисляется один раз за вход. Запись действующей функции (её `пишет`) видна следующим за ним привязкам «При входе» и строкам: порядок записи — порядок исполнения. Изменения данных и журнал — в строке `сразу` (правило 29). Событие у операции одно — `сразу`.

Пример (пилот «Шаг агента», СТАРТ и УЧЁТ; «Совещание», ЗАМОК, ВОЗВРАТ, ФИЛЬТР, СВОД). Запись данных — в строке, не в «При входе»; вместо `сразу(данные)` — привязка; в ВОЗВРАТЕ условное действие — в строке; в ЗАМКЕ `копия` — текст предложения, `отпечаток_копии` — отпечаток; в ФИЛЬТРЕ запись в линзу — копия через `обязательно(…)`, как при приёме ЛИНЗ (4.4), а `линзы_без_критических` — внешняя функция без тела в источнике (раздел 7), `Читает` включает его чтения; в СВОДЕ `Читает` включает чтения `собрать_свод` из реестра.

```
### СТАРТ — операция
- При входе: пусть момент = событие.момент

| 1 | сразу | — | начато = момент; число_ходов = 1 | ХОД_АГЕНТА |

### УЧЁТ — операция
- Читает: запрос_агента, остановка, расход, начато
- При входе:
  - пусть сейчас = событие.момент;
  - пусть собранное = собрать_использование(запрос_агента, остановка, расход, начато, сейчас)

| 1 | сразу | — | использование = собранное; журнал(событие_расхода(собранное)) | ИТОГ_ШАГА |

### ЗАМОК — операция
- Читает: предложение, порядок_линз
- При входе: пусть отпечаток = отпечаток_предложения(); закрыть_для_записи("proposal")

| 1 | сразу | — | копия = предложение; отпечаток_копии = отпечаток; к_отправке = порядок_линз; ответившие = 0 | ЛИНЗЫ |

### ВОЗВРАТ — операция
- Читает: копия

| 1 | сразу | — | если есть(копия) то { предложение = обязательно(копия) } иначе { журнал("copy_restore_no_copy") } | АННУЛ |

### ФИЛЬТР — операция
- Читает: номер_захода, порядок_линз, находки_линзы, ответы_свидетеля, линзы
- При входе:
  - убрать_несостоятельные(номер_захода);
  - пусть без_критических = линзы_без_критических()

| 1 | сразу | — | для л из без_критических { линзы[л] = { ...обязательно(линзы[л]), пробы: 0 } } | СВОД |

### СВОД — операция
- Читает: номер_захода, порядок_линз, находки_линзы, линзы
- При входе: пусть итог = собрать_свод(номер_захода)

| 1 | сразу | — | если есть(итог) то { свод[номер_захода] = обязательно(итог) } | РАЗБОР |
```

(`событие_расхода` и `собрать_использование` — функции, пример в разделе 8. JSON-имя СВОДА в файле машины — `Summary`: строка `| СВОД | Summary |` раздела `## Имена`, 1а.)

### 4.6 Развилка

```
### ИМЯ — развилка
- Читает: <имена>                         необязательно
- При входе: пусть имя = <выражение, в том числе с вызовом изменчивой функции в любой позиции>      необязательно

| № | Условие | Действия | Куда |
```

Развилка ничего не делает и не ждёт (правило 9): «При входе» — только `пусть`-привязки (выражение; вызов изменчивой функции допустим в любой позиции выражения, в том числе в ветке `если`, 3.3), каждая вычисляется один раз за вход; действия строки меняют данные только в её переходе. Условия не вызывают изменчивые внешние функции: результат изменчивой функции читается по привязке `пусть` «При входе»; чистая внешняя функция (раздел 7) и функция автора зовутся в условии вызовом `имя(арг)`, функции каталога — тоже; действующая функция в условии не стоит нигде (раздел 7).

Пример (пилот «Шаг агента»). Строка `иначе` записана (обязательна: исчерпание не доказано типом, условия — над числом и над парой полей, 4.1); латинское имя ПРОВЕРКИ_ОТВЕТА — `ReplyValidation`, как в словаре; чтения `reply_validation` названы в реестре (раздел 7) и входят в `Читает`.

```
### ПОВТОР — развилка
- Читает: число_повторов, ход

| 1 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход != "retry" | число_повторов += 1; ход_до_повтора = ход; ход = "retry"; журнал("agent_transient_error", retry: строка(число_повторов)) | БЮДЖЕТ |
| 2 | число_повторов < ЧИСЛО_ПОВТОРОВ и ход == "retry" | число_повторов += 1; журнал("agent_transient_error", retry: строка(число_повторов)) | БЮДЖЕТ |
| 3 | число_повторов >= ЧИСЛО_ПОВТОРОВ | остановка = "no_result"; журнал("agent_transient_error_exhausted", retries: строка(ЧИСЛО_ПОВТОРОВ)) | УЧЁТ |
| 4 | иначе | ошибка_машины("fork_no_match", fork: "Retry") | — |

### ПРОВЕРКА_ОТВЕТА — развилка
- Читает: число_возвратов, текст_ответа, артефакт_ответа, запрос_агента
- При входе: пусть проверка = reply_validation()

| 1 | проверка == ПроверкаОтвета.Верна | — | УЧЁТ |
| 2 | проверка == ПроверкаОтвета.Пуста | остановка = "no_result"; журнал("agent_no_result") | УЧЁТ |
| 3 | проверка == ПроверкаОтвета.Нарушена и число_возвратов < ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | число_возвратов += 1; ход = "fix"; журнал("reply_form_violated") | БЮДЖЕТ |
| 4 | проверка == ПроверкаОтвета.Нарушена и число_возвратов >= ЧИСЛО_ВОЗВРАТОВ_ФОРМЫ | остановка = "form_not_fixed"; журнал("reply_form_not_fixed") | УЧЁТ |
| 5 | иначе | ошибка_машины("fork_no_match", fork: "ReplyValidation") | — |
```

(У ПРОВЕРКИ_ОТВЕТА строки 3 и 4 читают и перечисление `проверка`, и число `число_возвратов`: исчерпание по типу не доказано, `иначе` нужна. Будь условия только `проверка == ПроверкаОтвета.Верна`, `… .Пуста`, `… .Нарушена` — по строке на элемент, — `иначе` была бы необязательна, а написанная — предупреждением.)

Пример вложенного вызова изменчивой функции (пилот «Совещание», СВЕРКА): отпечаток читается, только если предложение прочитано; `отпечаток_предложения` при нечитаемом предложении — `недостижимо`, поэтому вызов стоит в ветке `если`, а `Читает` СВЕРКИ включает чтения обеих внешних функций.

```
### СВЕРКА — развилка
- Читает: отпечаток_копии
- При входе:
  - пусть прочитано = предложение_прочитано();
  - пусть отпечаток = если прочитано то { отпечаток_предложения() } иначе { пусто }

| 1 | прочитано и отпечаток == отпечаток_копии | — | ФИЛЬТР |
| 2 | прочитано и отпечаток != отпечаток_копии | — | ИЗМЕНЁН |
| 3 | не прочитано | — | ИЗМЕНЁН |
| 4 | иначе | ошибка_машины("fork_no_match", fork: "Comparison") | — |
```

Пример развилки цепочки набора (пилот «Совещание», ОТКАЗ): `событие.сторона` — из события ЛИНЗЫ #2. Показаны строки 1 и 2; строки 3 и `иначе` (4) — в образце. JSON-имя ОТКАЗА в файле машины — `Refusal` (строка `| ОТКАЗ | Refusal |` раздела `## Имена`; у образца «Совещания» состояние называется по словарю иначе, `LensRefusal`).

```
### ОТКАЗ — развилка
- Читает: линзы, к_отправке, номер_захода

| 1 | обязательно(линзы[событие.сторона]).потери_подряд == 1 | журнал("lens_dropped", party: событие.сторона, pass: строка(номер_захода)) | ВСЕ_ЗАКРЫТЫ |
| 2 | обязательно(линзы[событие.сторона]).потери_подряд == 2 | сбойное_обращение = "Lenses"; к_отправке = [событие.сторона] + к_отправке | СБОЙ |
```

- Кроме: <значение в […]>                необязательно
```

«При входе» конца — работа с внешним миром и журнал: `пусть`-привязки, вызовы внешних функций (изменчивой и действующей), `журнал`, условные `если`, `для` с телом из `журнал(…)` и `если`; данные конец не меняет (правило 29). Действующая функция в «При входе» конца должна быть безвредно повторяема хозяином: конец входится повторно (правило 22). `Кроме:` — значения набора, с которыми в этот конец не входят: исчерпанность «Концов» проверяется по набору без них; вход с таким значением — `недостижимо`.

**Таблица «Концы»** (правило 35, пункт 2, «конец → ответ»): сначала элемент списка `- Результат: <тип ответа машины>`, затем (через пустую строку) таблица

```
| конец | № | когда | ответ |
```

- `когда` — условие входа: `истина`, `остановка == "…"`, `остановка в […]`; строки одного конца взаимоисключающи и покрывают набор, по которому ветвятся (кроме `Кроме`); не покрытое значение — ошибка проверки таблицы.
- `ответ` — `Ответ(<значение типа результата>)` или `Отказ(<код КодСбоя>, <текст>)`: это функции ответа формата с позиционными аргументами, а не формы с полями, поэтому круглые скобки у них остаются; конверт ответа (запрос, сторона, трасса, шаг) собирает исполнитель; код отказа берётся из конструктора, отдельного столбца нет.
- В «ответе» доступны данные, `запись_перехода` (поля `код`, `параметры`; значение есть всегда: в ОШИБКУ входят по `ошибка_машины` или по ошибке машины исполнителя, и оба пути пишут запись, 3.3) и функции каталога; текст записи целиком — `текст_записи(запись_перехода)`.

Пример (пилот «Шаг агента»). В коде `Time.now()` читается внутри ветки, здесь время берётся из штампа события `событие.момент` (чтение штампа следов не оставляет). `Читает` ОШИБКИ — `все_данные`: `использование`, `запрос_агента` и прочие имена в её «При входе» читаются из `все_данные` как данные.

## 5. Действия

Слова действий (`журнал`, `ошибка_машины`, `передать`, `отменить_открытые`, `для`) — русская форма; английская форма — по [таблице слов](alula-keywords.tsv), вид `action` (1а).

Список через `;` в порядке записи (правило 29); **каждое действие видит результаты предыдущих** (после `число_повторов += 1` журнал читает новое значение). Действующая внешняя функция (вызов `имя(арг)` функции класса `действующая`) исполняется сразу, когда шаг доходит до вызова, до записи шага; её аргументы вычисляются в точке записи. **Отступление от правила 13 (очередь исходящих).** Правило 13 ставит необратимые внешние действия последним этапом фиксации, после записи шага; формат этого пока не делает: повторяемость действующей функции при повторе шага — требование к хозяину, а исполнение после записи шага (очередь) не реализовано до появления реального хозяина или первого двойного вызова. Это отступление, а не норма.

| Действие | Смысл | Где |
|---|---|---|
| `поле = выр`; `поле += выр` | присваивание; прибавление (число, вещественное, строка, список) | строки, «При приёме» |
| `поле[ключ] = выр` | словарь: вставка или замена; список: существующий индекс, иначе ошибка машины | строки, «При приёме» |
| `поле[ключ].поле = выр` | краткая запись `поле[ключ] = { ...поле[ключ], поле: выр }`; ключа нет — ошибка машины, запись не создаётся; поле с `пишет: механика` — ошибка проверки. Где источник называет отсутствие ключа дефектом программы (`unreachable`, `required`), пишется `поле[ключ] = { ...обязательно(поле[ключ]), поле: выр }` (4.4) | строки, «При приёме» |
| `поле = без_ключа(поле, ключ)`; `поле = убрать(поле, элемент)` | удаление ключа и элементов | строки, «При приёме» |
| `журнал("код", имя: выр, …)`; `журнал("код")` | событие журнала: `код` — строковый литерал латиницей `snake_case` из таблицы шаблонов, значения параметров — `строка`; прежняя запись `журнал(код)` без кавычек — ошибка с подсказкой, переходного периода нет | строки, «При входе» конца, тело `для` в «При входе» конца |
| `журнал(значение)` | событие, собранное `событие_журнала("код", …)`, или `запись_перехода`; здесь без кавычек стоит значение-событие, а не код | строки, «При входе» конца |
| `журнал(все_данные)` | сокращение `журнал("machine_data", data: <запись данных>)`: событие `machine_data` с **одним** параметром `data`; кодирование — ниже; состав — раздел 2. Имя `все_данные` в выражении — значение-запись (3.1) | «При входе» ОШИБКИ |
| `пусть имя = выр` | привязка до конца «При входе» и на все строки состояния; также с вызовом внешней функции, `пусть имя = имя(арг)` | «При входе», «При приёме» |
| `{ действия }` | блок действий: действия по порядку; `пусть имя = выр` внутри видна до закрывающей `}`; блок не пустой | строки, «При приёме», «При входе» операции и конца (4.5, 4.7), ветки условного действия, тело `для`; не «При входе» развилки (там только привязки, 4.6) |
| `если выр то { действия } [иначе { действия }]` | условное; условие — выражение без вызова изменчивых и действующих внешних функций (чистые функции и функции каталога допустимы) | строки, «При приёме», «При входе» конца |
| `для имя из выр { действия }` | конечный список или диапазон `a..b`, `a..=b`; тело — присваивания, `+=` и краткая запись (в строках, «При приёме»); `журнал(…)` и `если` (в «При входе» конца); **граница тела**: тело — блок `для x из xs { а; б }`, действие после `}` в тело не входит | строки, «При приёме», «При входе» конца |
| `имя(арг, …);` | вызов действующей внешней функции как действие (`close_agent_turn();`); у функции без результата — только так: вызов не стоит в выражении и справа от `пусть`; допустимость по классам — раздел 7; исполняется сразу, до записи шага (отступление от правила 13, выше) | по классу |
| `ошибка_машины("код", имя: выр, …)` | журнал `код` (строковый литерал) и конец ОШИБКА; «Куда» — `—`; единственный вход в ОШИБКУ по воле таблицы (второй — ошибка машины исполнителя, 3.3); после обоих определено `запись_перехода` | строки, общие события |
| `передать(вложенные, сигнал)` | сигнал `Сигнал` машинам `вложенные` (параметр фрагмента, раздел 9) из `открытые_запросы` на момент действия (адресаты берутся в точке записи, до `отменить_открытые` той же строки), отправка — после фиксации; журнал `signal_passed` на каждого | только фрагмент |
| `отменить_открытые[(кроме: вложенные)]` | отменить открытые запросы без принятого ответа (правило 18): с `кроме: вложенные` — кроме запросов к названным вложенным, без аргумента — все, включая вложенные; эффект — по параметру `отмена_запросов` (раздел 9); возврат сторон отменённых запросов набора в `к_отправке` — правило 18, при любом значении параметра; отключает его только `без_возврата_в_к_отправке`, и только в ОБЩ 1, 2; изменение `открытые_запросы` и `к_отправке` — механика контракта (правило 29), «запись ⊆ `пишет`» его не считает записью строки | только фрагмент |

**Условное действие**. Ветки условного действия пишутся в фигурных скобках, как блок в Нове: `если есть(копия) то { предложение = обязательно(копия) } иначе { журнал("copy_restore_no_copy") }`; в ветке — одно действие или список через `;`; `иначе { … }` необязательна. Слово `то` обязательно: условие — выражение, а выражение может кончаться именем типа (`если x == Тип.Вар`), и запись `если x == Тип { … }` читалась бы как сравнение с литералом записи или формы `Тип { … }`; `то` ставит границу условия. Ветка не пустая: блок `{ }` без содержимого — ошибка проверки; ненужную ветку `иначе` условного действия не пишут (у условного выражения `иначе` обязательна). Условное **выражение** пишет ветки тоже блоками, по одному выражению в блоке: `если выр то { выр } иначе { выр }`, `иначе` обязательна (3.1); там `то` нужен по той же причине.

**Формы `пусть`**:

| Форма | Что это | Где | Область видимости |
|---|---|---|---|
| `пусть имя = выр` | действие-привязка | «При входе» операции, развилки и конца, «При приёме» (вне блока) | до конца «При входе» и на все строки состояния; в «При приёме» — с принятым событием, его строке и цепочке (2, «Время жизни данных») |
| `пусть имя = выр` внутри `{ … }` | действие-привязка в блоке | любой блок действий: строки, «При приёме», «При входе» конца, ветки условного действия, тело `для` | до закрывающей `}` блока |
| `пусть имя = выр;` внутри блока-выражения `{ …; выр }` | привязка в блоке-выражении | любая позиция выражения: тело-блок функции, ветки условного выражения, ячейки выражений | до закрывающей `}` блока |

Слова `в` у `пусть` нет: локальная привязка в действиях — блок `{ пусть имя = выр; действия }`, в выражении — блок-выражение `{ пусть имя = выр; выр }`.

**Коды журнала продукта**. Код в `журнал("код", …)` и `ошибка_машины("код", …)` — строковый литерал; он берётся из таблицы шаблонов [журнала](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-journal.md) (раздел 2 и подраздел «События формата таблиц») — это коды методики. Продукт, которому нужны свои события (запись механики исполнителя: правка ответа при «Правит», возврат формы, повтор запроса, заказ сигнала — например `answer_edited`, `form_returned`, `request_repeated`, `signal_ordered`), объявляет их **таблицей шаблонов продукта** той же формы (`Машина | Код события | Русский шаблон | Параметры`) рядом с таблицей методики; где она лежит, называет реестр хозяина (как файлы функций, раздел 8). Правила: код продукта — латинский `snake_case` по правилам кода журнала; он не повторяет код методики (совпадение — ошибка проверки, даже при том же шаблоне); код, который пишет сам формат или механика контракта (`signal_passed` у `передать`, `input_rejected`, `machine_error`, `machine_data`, коды фрагмента «Пауза»), продукт своим кодом не заменяет: своё событие (например, `signal_ordered` при заказе сигнала до фиксации) пишется рядом с кодом методики, а не вместо него. Проверка (раздел 10) сверяет код и параметры строки с объединением двух таблиц; код вне объединения — ошибка. Скрипт методики [check-tables.py](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/check-tables.py) читает только таблицу методики; таблицу продукта читает проверка продукта. В таблицу методики коды продукта не вносятся.

**Кодирование `журнал(все_данные)`** (проверено реализацией). Событие `machine_data` с **одним** параметром `data`. Значение параметра — пары `имя=значение` (имя — JSON-имя данного, 1а), разделитель — `; ` (точка с запятой и пробел); порядок — порядок строк таблицы «Данные» машины (сначала данные подключённых фрагментов в порядке подключений, затем данные машины); пути полей внутри словаря (`имя[*].поле`) в состав не входят — они часть значения словаря. Значение пары:

| Значение | Запись |
|---|---|
| целое | десятичная запись |
| дробное | `строка(x)` (кратчайшая обратимая запись, целое с `.0`; 3.3) |
| текст, набор литералов, `ид` | как есть, без кавычек; пустой текст — пусто после `=` (`stop=`) |
| `булево` | `yes`, `no` |
| необязательное `пусто` | `none` |
| перечисление | значение элемента (латинский текст кода); у элемента без значения — его JSON-имя |
| `Состояние` | JSON-имя состояния |
| список | JSON-массив `[…]`; пустой — `[]` |
| словарь | JSON-объект `{…}`; пустой — `{}`; у словаря с нетекстовыми ключами — массив пар `[[ключ,значение],…]` в порядке записи ключей (раздел 2) |
| запись | JSON-объект; ключи — JSON-имена полей, порядок — порядок полей типа |
| перечисление с полями | форма с полями — `{"Вар":{поля}}`; без полей — строка `"Вар"` (JSON-имена) |
| кортеж | массив; позиции по порядку |

Составные значения кодируются JSON без потерь: без пробелов (разделители `,` и `:`), UTF-8, не-ASCII знаки не экранируются, экранирование текста — по RFC 8259 (`\"`, `\\`, `\b`, `\f`, `\n`, `\r`, `\t`, прочие управляющие знаки — `\u00xx` строчными); внутри составного текст — JSON-строка, `пусто` — `null`, `булево` — `true`, `false`, дробное — число по `строка(x)`, перечисление и `Состояние` — строка по строкам таблицы. Кодирование и разбор туда и обратно без потерь: кириллица и 4-байтные буквы сохраняются, целое и дробное различаются (`1` и `1.0`). Целое (`число`, i64) в JSON — число: значения больше 2^53 по модулю читатели JSON, хранящие числа как f64, могут прочитать неточно.

Примеры (`data=` — имя параметра события): `data=count=0; label=abc; began=1000; log=[]; table={}; stop=` и `data=total=99; label=; log=[]; counts={}; items={}; p_attempt=0`; словарь `линзы словарь[строка, Линза]` (JSON-имя `lenses`; поля `Линза` с JSON-именами `id`, `lost`, `probes`, `attempt`) — `lenses={"л1":{"id":"л1","lost":0,"probes":0,"attempt":2}}`; `turn_before_retry=none` — пустое необязательное `ход_до_повтора` (JSON-имя `turn_before_retry`).

## 6. Дерево JSON

**Имя файла дерева**. Дерево, скомпилированное из `<имя>.alula.md`, лежит рядом в `<имя>.alula.json` (`agent_step.alula.md` ↔ `agent_step.alula.json`). JSON — исполняемая форма самого языка, а не другой формат: рукописное дерево — тоже Алула в JSON-виде; ключ `format: "machine/2"` внутри дерева не меняется. Прежнее имя `*.machine.json` не употребляется, загрузка его не принимает. Правила, по которым дерево пишется обратно в файл Алулы, — раздел 1б.

**Версия языка в дереве**. Корень дерева несёт ключ `alula_version` — версию формата, в которой дерево скомпилировано (строка; у этой версии — `"2.25"`); ключ необязателен: нет его — дерево той версии, которую читает программа. Программа читает ровно одну версию формата: дерево с другой `alula_version` — ошибка, сообщение называет версию (переходного периода нет). Ключ `format` (`"machine/2"`) — формат дерева, от версии языка он не зависит; ключа `table_format` нет.

Дерево JSON и его схема — вне этого файла: схемы дерева (`machine/2`) и сценариев (`test/0`) лежат в репозитории языка, [nv-lang/nova-alula, папка `src/machine/schema/`](https://github.com/nv-lang/nova-alula/tree/main/src/machine/schema); версию схемы ведёт пакет `alula`, ключи в ней английские; схема — первоисточник структуры дерева, этот файл — правил записи и соответствия слов ключам. Дерево одинаково для русского и английского файла: слова обоих языков отвечают одному ключу и одному значению (таблица слов, 1а); вид стороны «человек или агент по настройке» называется в дереве `gatekeeper` (раздел 1). Здесь перечислены конструкции версий 2, 2.1, 2.2 и 2.5 (у версий 2.8–2.23 новых узлов нет: дерево от языка файла не зависит, 1а; `—` в ячейке «выражение» таблицы «Запрос» даёт в дереве выражение-имя поля, как прежняя запись; у версии 2.7 один новый ключ — `words`, в версии 2.13 он называется `values`, ниже; у версий 2.3, 2.4 и 2.6 новых узлов машины нет: результат по роли (до 2.24) — запись реестра хозяина; у версии 2.5 новые узлы — набор литералов и тип `id`), которым нужны узлы (у части из них в версии 1 узлов не было): `in` у `сбой`, «когда» и «Кроме» у концов, «При входе» развилки, операции и конца, альтернативы `|` в `выбор`, наборы литералов `"a" | "b"` (в JSON-схеме — перечень строк `enum`: слово схемы, не узел типа дерева), тип `id` (строка формата UUID: `^[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}$`), `число>=n`, `?`, кортеж, полный словарь, `не убывает, <= выр`, `пишет` (пять значений), путь поля `имя[*].поле` в «Данных» и краткая запись `имя[ключ].поле = выр`, `недостижимо`, скобки группировки, вызов с именованными аргументами, идентификатор стороны, `разбор` стороны `machine`, `Правит` с `проверка`, `Начальное состояние`, `для` с `журнал` в конце, подключение с параметрами, `сигнал(…)` с полями (сигнал стороны и сигнал машины), привязка поля с переименованием, «При приёме», `пусть` в «При входе», условное действие, `событие_журнала`, `журнал(значение)`, набор сторон, сторона `machine`, `## Вход` машины с инвариантами, значения перечислений; перечисление `тип Имя перечисление …` — всегда узел типа в массиве `variants`, у форм поля есть или нет: отдельного узла `enum` в дереве нет; значения элементов — пары ключа `values` на этом узле (ниже), генератор пишет `= "значение"` у форм со значением в `values` и поля у форм с полями; Заранее объявленная функция (`новый_ид`, 7а) в `primitives` не входит: она принадлежит языку, а не объявлена в файле; её вызовы — те же узлы вызова по имени. Именованный хвост `...имя: Тип` записан в `params` записью `{name, type, tail: true}`. **Значения перечислений**. У перечисления со значениями (раздел 2) узел типа в массиве `variants` несёт ключ `values` (до версии 2.13 — `words`) — список пар «JSON-имя элемента → значение» в порядке объявления (`[["NoResult", "no_result"], …]`); ключ есть только у узла типа, у элементов которого есть значения. Кодирование `все_данные` (раздел 5) и `строка(x)` берут значение из `values`; у элемента без значения — его JSON-имя. **Имена в дереве** — JSON-имена (1а): автоматические или из `## Имена`, дерево не зависит от того, как имя получено; раздел `## Имена` своего узла в дереве не имеет. **Счётчик стороны**: у стороны ключ счётчика может отсутствовать — так дерево несёт сторону вида `human` со свободным вводом (`—` в столбце `счётчик`, раздел 1); как это выражено в схеме, решает продукт. таблица `Запрос` обращения — ключ `inputs`, строка `Читает` — ключ `reads`. Подключение файла функций — `includes: [{ "name", "version", "hash" }]` и копия его типов, констант и функций в дереве машины: интерпретатору хватает одного дерева.

## 7. Внешние функции и допустимость классов

**Внешняя функция** — функция хозяина (исполнителя), которую зовёт машина: чтение мира (часы, файлы, хранилище, объекты), разбор текста ответа, внешнее действие. Файл машины **объявляет** каждую внешнюю функцию, которую зовёт, строкой раздела `## Внешние функции` — без тела:

```
внешняя функция имя(арг тип, …) [<класс>] [-> тип]
```

Английская запись — `external fn name(arg type, …) [<class>] [-> type]`. В реестре и ниже внешние функции зовут также примитивами: «примитив» и «внешняя функция» — одно и то же. **Внутренние функции автора** (с телом на языке, раздел 8) всегда чистые, класса у них нет.

- **Класс** — слово после списка параметров: `изменчивая` (английское `volatile`) или `действующая` (`acting`); у чистой функции слова нет. Три класса: **чистая** (читает только свои аргументы, мира не читает и не меняет), **изменчивая** (результат зависит от мира), **действующая** (меняет мир).
- **Результат** `-> тип` может отсутствовать; для действующей функции без результата это единственная запись.
- **Тела нет**: объявление — одна строка в блоке кода под заголовком `## Внешние функции`; пустой раздел — единственная строка `—`. Объявление вне блока кода — комментарий (абзац) и предупреждение проверки (1а).
- Последний параметр может быть **именованным хвостом** `...имя: Тип` (3.1).
- **Имя.** Внешняя функция занимает пространство вызовов (1а, пространство 11); её JSON-имя — имя в реестре хозяина: у нелатинского имени оно строится автоматически (1а; `профиль_стороны` → `party_profile` по словарю), а если имя реестра другое — задаётся строкой `## Имена`.
- **Вызов** внешней функции — обычный `имя(арг)` в любом допустимом месте; позицию вызова определяет класс по объявлению (таблица ниже). Вызов действующей функции без результата — действие строки `имя(арг);` (раздел 5). Отдельной формы вызова нет: прежняя запись `вызвать(имя, …)` — ошибка проверки («прежняя запись `вызвать(имя, …)` — ошибка; пишется `имя(…)`; переходного периода нет»).
- **Заранее объявленная** функция `новый_ид()` в файле не пишется (7а); время машина читает как `событие.момент` (читаемые имена исполнителя, правило 11).
- В **файле функций** (раздел 8) внешние функции запрещены.

Чистые функции над данными можно писать не здесь, а в «Функциях» (раздел 8); внешними остаются разбор текста, чтение объектов, время, закрытие хода, эффекты и функции без тела в источнике (ниже).

| Класс (слово в объявлении) | Что делает | Вызов `имя(арг)` допустим |
|---|---|---|
| чистая (слова нет) | читает только свои аргументы, мира не читает и не меняет; данные машины ей передаются аргументами | везде, где допустимо выражение, в том числе в условиях |
| `изменчивая` | результат зависит от мира — часы, файлы, хранилище, объекты; мир не меняет (прежний `reading`) | в «Запрос» обращения, в `профиль`, в «При входе» операции, развилки и конца (в `пусть`), в «При приёме» (в любой позиции выражения, 3.1) и в действиях строк; как `разбор` стороны `machine` и `проверка` свойства «Правит» (4.2); не в условиях строк; `новый_ид` — только в `пусть` «При входе» операции (ниже) |
| `действующая` | меняет мир — данные машины, объекты, буфер, внешнее действие (прежние `writing` и `irreversible`) | в «При входе» операции и конца (в том числе `пусть имя = имя(арг)`) и в действиях строк; не в условиях, не в «Запрос», не в `профиль`, не в «При входе» развилки, не в «При приёме»; у действующей функции без результата вызов не стоит в выражении и справа от `пусть` — он действие строки `имя(арг);`; в «При входе» конца она должна быть безвредно повторяема хозяином (конец входится повторно, правило 22) |

**Сверка с реестром хозяина при загрузке.** Хозяин держит реестр своих внешних функций: запись реестра — `имя`, `параметры` с типами, `результат`, `класс`, `читает`, `пишет`, примечание. При загрузке машины каждая объявленная в файле внешняя функция сверяется с реестром: имя найдено (по JSON-имени объявления); число и типы параметров; тип результата; класс. Расхождение — ошибка проверки с именем функции и расхождением (пример текста: «функция записать_статус: параметр 2 в файле число, в реестре строка»); функции нет в реестре — ошибка; лишние функции в реестре допустимы (файл объявляет только те, что зовёт). Скрытые чтения и записи (`читает`, `пишет`) берутся из реестра, не из файла: в объявлении их нет.

- `читает:` — данные машины, объекты, служебные записи, которые читает функция скрыто (не через аргументы). Эти имена входят в чтения состояния (`Запрос`, `Читает`) в точке вызова (правило 11). У чистой функции графа `читает` пуста (`—`): она читает только аргументы. У изменчивой и действующей графа остаётся (в 2.24 так — узко: сужение `читает` до одного мира, с передачей данных машины аргументами, — кандидат, см. [журнал изменений](alula-changelog.md), «Открытое»).
- `пишет:` у действующей функции — данные машины, которые функция меняет на месте; проверка «записи ⊆ данные» его учитывает. У изменчивой функции — только служебные записи исполнителя (не данные машины, не объекты); запись называет, кто её читает (функция или механика хода), чтобы зависимость была видна (например, замечания проверки формы для хода «исправить»).

**Исполнение действующей функции и правило 13 (очередь исходящих).** Действующая функция исполняется сразу, когда шаг доходит до вызова, до записи шага; повторяемость при повторе шага (незавершённый шаг откатывается, правило 12) — требование к хозяину: исполнение после записи шага (очередь) не реализовано до появления реального хозяина или первого двойного вызова. Это отступление от правила 13, а не норма; исполнение необратимых вызовов последним этапом после записи нормой не является.

Пример (пилоты): раздел `## Внешние функции` файла машины. Класс стоит после списка параметров, до `-> тип`; у `close_agent_turn` и `убрать_несостоятельные` результата нет; `не_вошедшие_в` и `объединить_без_повторов` чистые (слова класса нет); три функции разбора — по одной на роль (ниже).

**`новый_ид`** (стандартная внешняя функция языка; латинское имя в реестре хозяина и в JSON — `new_id`, слово таблицы слов, вид `catalog`; хозяин реализует её через `Uuid.v7()` с эффектами времени и случайности — это деталь хозяина). Без параметров, результат `ид` (раздел 2), класс `изменчивая`, `читает` и `пишет` — `—`; результат недетерминирован: значение выдаёт исполнитель. Недетерминированность снимается так (СТАРТ, раздел 4.5): значение входит в привязку `пусть` и фиксируется в событии `сразу` шага; при повторе шага (правила 12–13) берётся из сохранённого события, а не выдаётся заново. Поэтому `новый_ид()` допустим **только** в `пусть` «При входе» операции с записью привязки в данные строкой `сразу`. Консервативное решение: в «Запрос» обращения не допустим даже при `читает: исполнитель` — «Запрос» вычисляется заново при повторном входе и новом запросе (4.2, правило 12), и значение сменилось бы; в развилке, конце, условиях, действиях, `профиль` — тоже нет (раздел 10).

Пример (иллюстрация; данное `ид_сессии` — `?ид`, начальное `пусто`; состояние не из пилота; его JSON-имя `Opening` — строка `| ОТКРЫТИЕ | Opening |` раздела `## Имена`, транслитерация дала бы `Otkrytie`).

```

- При входе: пусть новая = новый_ид()

| 1 | сразу | — | ид_сессии = новая | ХОД_АГЕНТА |
```

**Разбор по роли.** У каждой роли разбора ответа своя изменчивая внешняя функция: `разобрать_ответ_свидетеля` (результат `[]ОтветСвидетеля`), `разобрать_ответ_автора` (`ИтогПравки`), `разобрать_ответ_линзы` (`ИтогЛинзы`); сторона `machine` называет её в `разбор:` без аргументов (раздел 1). Проверка (раздел 10) сверяет первый параметр функции с типом `итог` стороны, а результат — с типом после `->` у `разбор`: типы различны — ошибка проверки. Скрытые чтения у каждой функции свои (у функции свидетеля — ещё предложение): в чтения состояния входят чтения функции разбора его стороны. Прежняя одна функция `разобрать_ответ_агента(ответ, роль)` с таблицей `по роли {…}` в реестре и текстовый литерал роли в `разбор:` — ошибка проверки («с 2.24 — отдельная функция на роль»), переходного периода нет.

Остальные внешние функции примеров (`профиль_стороны`, `контекст_роли`, `закрыть_для_записи`) объявляются так же; функции `сложить_расход`, `собрать_использование` в примерах не расписаны, их записи — в выписках пилотов. У `убрать_несостоятельные` скрытые чтения — `порядок_линз`, `находки_линзы`, `ответы_свидетеля`.

**Функция без тела в источнике** (решение методики 2026-10-19): функция, у которой в источнике нет тела (в коде автомата только сигнатура), записывается **внешней функцией хозяина** с классом и описанием по таблицам первоисточника; функцией на языке она станет, когда тело появится в источнике (тогда объявление переносится в `## Функции`). Правило одно для всех таких функций, чистых и нет; **класс — по сигнатуре источника**: свободная функция без `mut` и без `Objects` — чистая (вызов как `имя(арг)` везде); метод данных машины без `mut` или функция с `Objects` без `mut` — `изменчивая` (читает данные или объекты, ничего не меняет); с `mut` — `действующая` (пишет данные, объекты или буфер, совершает внешнее действие); прежнее различие `writing` и `irreversible` снято. Сюда входят все такие функции автоматов, которые зовут таблицы «Совещания»: чистые — `merge_unique` (`объединить_без_повторов`), `not_included_in` (`не_вошедшие_в`), `has_critical`, `desirable`, `desirable_and_significant`, `desirable_and_significant_repeated`, `critical_and_significant_not_repeated`; `изменчивая` — `has_reviewer_questions`, `reviewer_questions`, `all_lens_findings`, `lenses_without_critical`, `build_summary` (`собрать_свод`: записывает `свод[…]` строка СВОДА по результату, сама функция данных не меняет), `proposal_changed_since_attempt`; `действующая` — `remove_unsound` (`убрать_несостоятельные`: пишет `находки_линзы`) и `count_in_model_tally` (таблицы её не зовут). Журнал-функции без тела (`journal_findings`, `journal_decision`, `journal_machine_data`) формат записывает строками журнала (4.7). Пилотный подсчёт считает такие функции записанными как внешние функции. Тела в автоматы этим не вносятся.

### 7а. Стандартные внешние функции, контракт хозяина и коды языка

Язык называет только то, что любой хозяин и любой исполнитель обязаны дать; всё остальное хозяин регистрирует сам (раздел 7), а коды журнала берёт из таблиц своего владельца (журнал методики, журнал продукта).

**Стандартная внешняя функция** (заранее объявлена языком, в файле машины не пишется; класс `изменчивая`; без неё не записать идентификатор): `новый_ид()` (английское `new_id()`) — `() -> ид`, раздел 7 и каталог (раздел 12). Время — не функция: машина читает штамп события `событие.момент` (целое, миллисекунды от 1970-01-01 UTC); он приходит с событием и при повторе шага тот же, поэтому шаг воспроизводим, а сценарий задаёт время в самом событии. Остальные внешние функции — данные хозяина: методика даёт свои (54 в реестре пакета 0.3.2: шаг агента, совещание, запуск сессии, раннер задачи), продукт — свои.

**Контракт хозяина.** Хозяин подключает реализации внешних функций по одной: `bind_pure`, `bind_volatile`, `bind_acting` — по классу функции; при загрузке каждая объявленная внешняя функция привязана (непривязанная — ошибка загрузки). Класс внешней функции различается типом среды: чистой среда не передаётся, изменчивой передаётся среда без записи, действующей — с записью; это проверяет компилятор. Не доказано типами: что реализация не пишет вывод, файлы, часы и сеть мимо среды и не захватывает внешнее изменяемое состояние; это проверяется стражем импортов, --strict-effects (частично) и тест-хостом. Контракт относится к хозяину, а не к файлу машины: в файле его записать нельзя.

**Коды журнала языка** — коды, которые пишет сам формат, фрагмент «Пауза» и исполнитель с движком; хозяин их не переопределяет. (а) формат: `signal_passed`, `input_rejected`, `machine_error`, `machine_data`, `fork_no_match`; (б) фрагмент «Пауза»: `human_stop`, `pause_by_parent_stop`, `cancel_discarded_foreign_request`, `cancel_discarded_already_replied`, `request_cancelled`, `cancel_parse_no_match`, `human_continue`, `parent_continue`; (в) движок и исполнитель: `machine_started`, `event_accepted`, `reply_discarded`, `request_ordered`, `request_sent`, `request_repeated`, `request_closed`, `cancel_ordered`, `cancel_sent`, `cancel_without_request`, `snapshot_ordered`, `machine_finished`, `engine_resumed`, `signal_ordered`, `machine_defect`, `event_ignored`, `event_unknown`, `event_malformed`, `answer_held`, `answer_replayed`, `answer_edited`, `form_returned`. Параметры и шаблоны текста этих кодов — в таблице журнала языка пакета; коды методики и продукта в этот список не входят.

## 8. Функции, константы, параметры

**Функция** (объявление `функция`, английское `fn`) — чистая функция автора (внутренние функции автора, с телом на языке, всегда чистые и класса не имеют; внешние функции хозяина — раздел 7), тело — одно из двух (как в Нове): `функция имя(арг тип, …) -> тип => выр` — тело из одного выражения; `функция имя(арг тип, …) -> тип { пусть имя = выр; …; выр }` — тело-блок: ноль или несколько привязок `пусть имя = выр;` и последним одно выражение, его значение — значение функции. `=>` и `{ … }` не сочетаются: `=> {` после заголовка — ошибка проверки; после `=>` стоит одно выражение, в том числе многострочное (`если … то { … } иначе { … }`, `выбор … { … }`), а `{` после типа результата всегда открывает тело-блок, поэтому копия записи как всё тело пишется в скобках: `=> ({ ...р, поле: выр })`; пустое тело-блок — ошибка. Ветка `выбор` — исключение, как ветка `match` Новы: `альт => выр`, в том числе `альт => { пусть …; выр }` (3.1). «Функция» без уточнения в этой спецификации — функция автора; функции раздела 12 — функции каталога. Арность 0 допустима; рекурсии нет. Константа — именованное значение с типом. Параметр — значение по умолчанию и переопределение проектом (`проект.<ключ>`).

Пример (пилоты; `событие_расхода` вместо функции-события кода, ключ — кортеж; `слово_да_нет` — для значений параметров журнала, 4.7; `объединить_без_повторов` — внешняя функция хозяина: у неё в источнике нет тела, раздел 7).

```
функция сумма_целых(а ?число, б ?число) -> ?число =>
  если есть(а) и есть(б) то { (а ?? 0) + (б ?? 0) } иначе { а ?? б }

функция слово_да_нет(б булево) -> строка =>
  если б то { "yes" } иначе { "no" }

функция событие_расхода(u Использование) -> СобытиеЖурнала =>
  событие_журнала("agent_usage", session: u.сессия, result: u.результат, model: u.модель.идентификатор,
                  input: строка(u.токены.вход), output: строка(u.токены.выход), reasoning: строка(u.токены.рассуждение),
                  cache_read: строка(u.токены.кэш_чтение), cache_write: строка(u.токены.кэш_запись), cost: строка(u.стоимость))
```

**Файлы функций**. Функции, общие у нескольких машин, лежат в подключаемом файле и подключаются строкой раздела `## Подключения`:

```
функции: <имя> версия <N> хеш <hex12>
```

- **Реестр**. `<имя>` — имя файла функций по реестру подключаемых файлов (не путь). Реестр — часть реестра хозяина, того же, где записаны внешние функции (раздел 7) и машины (правило 35, [протокол вызова](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-call-protocol.md), раздел J, пункт 6): запись `имя → файл` (путь относительно реестра). Формат файла реестра задаёт хозяин; формат таблиц требует одного: по имени находится ровно один файл, иначе — ошибка проверки таблицы.
- **Шапка файла функций:** `# Функции: <имя>`, элементы списка `- functions_version: <N>` (целое), `- format: 2.25` и необязательно `- language: ru`/`en` (1а). `версия` строки подключения — точное совпадение с `functions_version`.
- **Разделы** — `## Типы`, `## Константы`, `## Функции` по порядку, **все три обязательны**; пустой раздел — строка `—`; необязательный `## Имена` (1а) — после `## Типы`, только если в нём есть строки. Только чистые функции, типы и константы; без `## Состояния`, без `## Внешние функции` (внешние функции в файле функций запрещены: ни объявлением, ни вызовом, в том числе стандартная `новый_ид`), без `## Подключения`: файл функций других файлов не подключает (циклов нет по построению).
- **Хеш** — первые 12 знаков SHA-256 содержимого файла в UTF-8 после нормализации: ведущий BOM отбрасывается (файл с BOM и без него дают один хеш); переводы строк — LF (CRLF и одиночный CR заменяются на LF); у каждой строки убраны пробелы и табуляции в конце; в конце файла ровно один LF (пустые строки в конце убраны, недостающий LF добавлен); 12 знаков хеша — шестнадцатеричные, строчными буквами. Нормализация однозначна: файл без завершающего LF и файл с ним дают один хеш.
- Имена из подключённого файла видны без префикса; совпадение с локальным именем или с именем другого подключённого файла — ошибка проверки таблицы; несовпадение версии или хеша — ошибка проверки таблицы, а не предупреждение.

Пример («Совещание»: арифметика цикла общая у совещания и проверки цикла). ## 9. Подключаемые фрагменты

Фрагмент (правило 36) — файл формата `fragment`: шапка `# Фрагмент: <Имя>`, элементы списка `- fragment: <латинское_имя>`, `- format: 2.25` (необязательно `- language: ru`/`en`, 1а) и разделы по порядку: `## Параметры`, `## Обязывает`, `## Данные`, необязательный `## Имена` (1а), `## Общие события`, `## Состояния`. В тексте параметр стоит как `<параметр>` и подставляется до проверки (правило 34).

**Параметры** — `имя`, `вид`, допустимые значения. Виды (не типы данных; группа `kind_param` таблицы слов): `сигнал` (сигнал стороны), `строка`, `[]машина` (список имён вложенных машин; это вид, типа `машина` нет), `поведение` (закрытый перечень слов фрагмента; смысл — описание исполнителя в тексте фрагмента), `примечание` (текст для читателя). Подключение называет все параметры; пропущенный — ошибка.

**Обязывает** — что фрагмент требует от машины: значения `остановка`, строки «Концов», концы ОСТАНОВЛЕНО и ОШИБКА, сторону `усиленный` вида `enhanced` в «Сторонах» с сигналами `продолжить { слово_человека строка, автор строка, источник строка }` и `<сигнал_остановки>` (к ней обращается ПАУЗА); значение `предыдущее` — всегда обращение: машина стоит только в обращениях и концах, а в концах и ПАУЗЕ ОБЩ 1 и 2 условием отброшены (правило 24).

**Имена фрагмента:** `состояние` (текущее состояние, тип `Состояние`), `предыдущее` (`?Состояние`), `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, даёт исполнитель), `событие.идентификатор`, `конец(состояние)` (каталог), `вложенные`. `состояние` — имя исполнителя (тип `Состояние`); `предыдущее` (`?Состояние`) и `запрос_вызова` (текст; идентификатор запроса, которым запущена машина, значение задаёт исполнитель при запуске) — **данные фрагмента** (таблица «Данные» ниже), а не имена исполнителя. Общие события читают данные фрагмента, `состояние` и `событие.…` без строки чтений; состояния фрагмента — только свои чтения (`Запрос`, `Читает`).

**Значения параметров вида `поведение`** — закрытые перечни слов; значение вне перечня — ошибка проверки. Эффект называется формально и применяется там, где указано; `право_записи` — примечание для читателя, исполнитель его не вычисляет.

| Параметр | Слово | Эффект | Где действует |
|---|---|---|---|
| `отмена_запросов` | `механика` | отмена открытых запросов без принятого ответа — только механика контракта (запросы к человеку закрываются); стороны отменённых запросов набора возвращаются в `к_отправке` (правило 18) | `отменить_открытые`: ОБЩ 1, 2 — кроме `вложенные`; ОБЩ 5 — все открытые, включая вложенные (им сигнал «отмена» ушёл строкой раньше), как код движка и текст фрагмента |
| `отмена_запросов` | `без_возврата_в_к_отправке` | как `механика`, но стороны отменённых запросов набора в `к_отправке` не возвращаются (текст фрагмента: «по паузе»); у «Совещания» запросы ЛИНЗ вложенные, ОБЩ 1, 2 их не отменяют, возвращать нечего | только ОБЩ 1, 2 (пауза); в ОБЩ 5 параметр не действует: стороны набора возвращаются в `к_отправке` по правилу 18, как `cancel_open_without_accepted(false)` движка |
| `отмена_запросов` | `прекратить_ход_транспорта` | как `механика`; кроме того, ход у транспорта агента прекращается; закрытие удержанного хода — не эффект параметра: его делает `close_agent_turn()` в концах машины | `отменить_открытые`: ОБЩ 1, 2, 5, как у `механика` |
| `вход_заново` | `ничего` | повторный вход в сохранённое состояние — только по правилу 12 (новый запрос, если по нему нет принятого) | `Куда: предыдущее` (ПАУЗА 1, 3) |
| `вход_заново` | `запросы_из_к_отправке` | после повторного входа в обращение набора уходят запросы сторонам, перечисленным в `к_отправке` | то же |

Подключение в машине (раздел `## Подключения`): `Пауза(сигнал_остановки: остановить, код_остановки: "pause_halt", вложенные: [], отмена_запросов: прекратить_ход_транспорта, вход_заново: ничего, право_записи: "файлы, которые правит агент; пауза их права не трогает")` — «Шаг агента»; «Совещание» — `сигнал_остановки: остановить совещание`, `код_остановки: "pause_halt_meeting"`, `вложенные: [шаг_агента]`, `отмена_запросов: без_возврата_в_к_отправке`, `вход_заново: запросы_из_к_отправке`. Состояния, события и данные фрагмента входят в машину и в её разделах не повторяются: в `## Подключения` стоит **только** строка подключения; в `## Состояния` заголовок состояния фрагмента (`### ПАУЗА — обращение`) писать запрещено — повтор состояния, которое принесло подключение, — ошибка проверки («объявлено дважды»). Справочного раздела с раскрытием фрагмента нет: что приносит фрагмент (параметры, обязательства, данные, события, состояния), описывает его файл (у «Паузы» — определение ниже); в разделе `## Состояния` машины при необходимости стоит абзац-ссылка (проза, 4.1).

Определение фрагмента «Пауза» в формате. Составлено по раскрытию фрагмента в пилоте «Совещание» и тексту [archive/state-machine-pause-states.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/archive/state-machine-pause-states.md); сам файл фрагмента на формате пилотом не проверялся, его сверка с текстом правил 23, 24, 35 — по строкам. Файла фрагмента на Алуле (`*.alula.md` с шапкой `# Фрагмент: Пауза`) нет: определение ниже — образец, подключение `Пауза(…)` скриптами методики не разрешается (см. [журнал изменений](alula-changelog.md), «Открытое»). Особенности определения: `сигнал_остановки` и `код_остановки` — параметры; события от родителя — `сигнал(…)`; значения `остановка` — `<код_остановки>`; `передать(вложенные, …)`; ОБЩ 6 — `ошибка_машины`; в «Запросе» ПАУЗЫ `обязательно(предыдущее)` (поле видно только стороне, строки ПАУЗЫ читают данное `предыдущее`, 4.2); ОБЩ 5 — `отменить_открытые` без исключения, как код и текст фрагмента; возврат сторон набора в `к_отправке` в ОБЩ 5 — правило 18, при любом значении `отмена_запросов`; `открытые_запросы` — данные фрагмента, `слова_человека` в таблицу не вносятся (раздел 2).

- Сигналы «продолжить» и «остановить» (и от родителя) вне ПАУЗЫ — лишние сигналы: исполнитель отбрасывает их с записью в журнал (правило 17).
- `Куда: предыдущее` ведёт повторным входом в сохранённое состояние (правило 12; параметр `вход_заново`); «предыдущее» при этом не пишется (правила 13, 24).
- JSON-имена фрагмента (1а): данные фрагмента (`предыдущее`, `запрос_вызова`, `открытые_запросы`) — читаемые имена таблицы слов; JSON-имена сигналов машины называет словарь версии 11 (раздел 2.16): `стоп человека` → `human_stop`, `стоп от родителя` → `parent_stop`, `отмена_запроса` → `cancel_request`, `продолжить от родителя` → `parent_continue`, `остановить от родителя` → `parent_halt`; поля сигналов — `слово_человека` → `human_word`, `автор` → `author`, `источник` → `source`, `идентификатор_запроса` → `id` (разделы 2.9, 2.12 словаря); их и параметры фрагмента строит по правилу 1а файл фрагмента, переопределения — его разделом `## Имена`; сигналы машины — отдельное пространство различимости (1а), состояния фрагмента входят в пространство состояний машины.
- Привязки строк фрагмента (`слово_человека`, `автор`, `источник`, `идентификатор_запроса`) — внутренние имена (1а): их английские имена задаст английский файл фрагмента, в таблице слов их нет. После подстановки они — привязки строк машины: данное машины с таким именем — ошибка проверки (4.3).
- Слова человека (`слова_человека`) — хранилище правила 31, его пишет механика контракта (правило 19); в таблицу «Данные» оно не вносится (раздел 2) и в `все_данные` не входит; в строках его нет. `открытые_запросы` вносит фрагмент (его читают `передать` и `отменить_открытые`); машина строку не повторяет (раздел 2).

## 10. Проверки таблицы

Таблица слов и язык: слова `ru` и `en` таблицы [alula-keywords.tsv](alula-keywords.tsv) уникальны в пределах вида; строка `language` ∈ {`ru`, `en`}; язык шапки совпадает с объявленным; ключевое слово не из языка файла — ошибка с номером строки первого постороннего слова (1а); скрипт [tools/check-alula-keywords.py](../tools/check-alula-keywords.py) проверяет таблицу (виды слов, в том числе `operator`), сверяет с ней образцы машин и проверяет в них знаки операторов (только ASCII), JSON-имена (автоматическое имя; раздел `## Имена` — лишняя строка, имя не объявлено, повтор, нелатинское JSON-имя; коллизия в пространстве; смешанное слово; скобки после имени) и хеш словаря; [tools/check-alula-samples.py](../tools/check-alula-samples.py) сверяет JSON-имена объявлений двух образцов «Шага агента».

Расширение [check-tables.py](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/check-tables.py): имена полей, типов и состояний; чтения выражений ⊆ чтений состояния (`Запрос`, `Читает`) по правилу 11 (по обоим значениям `читает`, по спискам `читает` внешних функций, у ОШИБКИ — `все_данные`), записи ⊆ данные (включая `пишет` действующих функций); границы `число>=n`, «не убывает» и `<=`; достижимость состояний; полнота развилок: строка `иначе` обязательна, если исчерпание не доказано типом (перечисление без полей у форм, набор литералов — все значения названы), а после доказанного исчерпания написанная `иначе` — предупреждение (4.1); исчерпанность «Концов» с учётом `Кроме`; значения `Куда`; события обращения ⊆ события машины; сигналы сторон: сигнал события строки обращения ∈ список сигналов стороны обращения, каждый сигнал стороны используется (сигнал без строки в текущем состоянии строкой не принимается и отбрасывается, правила 14, 17, 19); `сбой(причина в …)` ⊆ `КодСбоя`; класс внешней функции (по её объявлению) допустим в позиции вызова; наборы литералов (вхождение вычисленного набора, значение вне набора — ошибка, `выбор` по набору исчерпан, 3.2); литерал типа `ид` — формата UUID; `новый_ид()` только в `пусть` «При входе» операции, и привязка записывается строкой `сразу` (раздел 7); привязка поля события не совпадает с данными (вместе с данными фрагментов, после подстановки); у обращения без строки `Запрос` строки, «При приёме» и «Срок тишины» данных не читают; полный словарь; типы `T`/`?T`; журнал: код ↔ таблица шаблонов методики или таблица продукта, код продукта не повторяет код методики (раздел 5), имена параметров ↔ шаблон (`fork`), значения — `строка`; значения перечислений — `[a-z][a-z0-9_]*`; JSON-имена (1а): итоговое JSON-имя (строка `## Имена`, иначе автоматическое — словарь, транслитерация) латинское; строка `## Имена`, которая ничего не меняет, — ошибка «лишняя строка»; строка для имени, которого среди объявлений файла нет (внутреннее, читаемое, опечатка), — ошибка; имя повторено в `## Имена`; JSON-имя строки не латинское; скобки после имени в объявлении — ошибка (скобки убраны); JSON-имена одного пространства различны (пространства — 1а: состояния вместе с состояниями фрагментов; данные; поля входа; типы; поля одной записи или формы; формы одного перечисления с полями; элементы одного перечисления; сигналы одной стороны; поля одного сигнала; сигналы машины; внешние функции; параметры, константы и имена настроек), разные пространства друг другу не мешают, коды журнала в пространства не входят; слово имени, где смешаны кириллица и латиница, — ошибка; хеш нормативной части словаря равен хешу, который называет формат (`хеш словаря`, 1а), иначе ошибка «словарь изменён без смены формата»; эталонный скрипт [tools/check-alula-keywords.py](../tools/check-alula-keywords.py) сверяет пространства, которые видит в объявлениях (состояния вместе с состоянием фрагмента «Пауза», данные вместе с JSON-именами данных контракта и фрагмента — `previous`, `call_request_id`, `open_requests`, `stop_reason`, `to_send`, `human_words`, — поля входа, типы, поля, формы, элементы, сигналы и их поля, внешние функции, имена настроек), а константы и параметры (пространство 10) и сигналы машины фрагмента не сверяет — это проверка переводчика продукта; `открытые_запросы` объявлено один раз; `сбой` вне списка состояния приводится к `НетРезультата` (4.3); `обязательно_непустое`: аргумент — набор с `""`; коды журнала формата таблиц — в таблице шаблонов (подраздел «События формата таблиц» файла журнала).

- **Форматирование**: строка-ключ состояния (4.1) без маркера `- ` допустима при разборе (запись версии 2.5), но проверка форматирования предупреждает — это предупреждение, а не ошибка таблицы; так же предупреждает таблица, стоящая вплотную к элементу списка или к другой таблице (без пустой строки). Проза: строка-абзац, начинающаяся со слова из перечня ключей (4.1) без маркера `- ` или с опечаткой в нём (`-Сторона:`, `– Читает:`), — предупреждение, иначе опечатка осталась бы молчаливым комментарием. Остальная проза проверок не вызывает. Абзац: строка текста вплотную к таблице, заголовку или списку без пустой строки — предупреждение. Объявление (`тип`, `функция`) вне блока кода — предупреждение. Расширение файла проверяет только этот скрипт.

**Выпуск для интерпретатора**. `недостижимо` и `обязательно(пусто)` — дефект программы: процесс останавливает исполнитель (не таблица); состояние машины не откатывается; ответ вызова — конец с `NoResult`; журнал дефекта — на усмотрение исполнителя. Это не ошибка машины (3.3): в ОШИБКУ дефект не ведёт. Отказ вызова при неверном входе — отдельный случай: событие `input_rejected` (раздел 1).

## 11. Сценарии

Сценарий — события и ожидание: событие (`старт` с входом, `ответ`, `сбой`, `сигнал` стороны или машины с данными, срок) → состояние, структурный журнал (код и параметры, правило 31), подмножество данных, очередь. Сравнение — по этим четырём; прогонщик — в продукте; тот же сценарий прогоняется на автомате методики. Форма записи сценария здесь в целом не задаётся (формат прогонщика — в продукте); формат фиксирует три вещи. **Имя файла**: сценарий (`test/0`) называется `<имя>.alula.test.json`; формат сценария не меняется. **Данные события**: сигнал (стороны или машины) с одним полем данных несёт значение этого поля — текст (например, `продолжить` с полем `автор` — значение `"ivan"`, а не объект); с несколькими полями — объект `{поле: значение}`; без полей — только имя. **Параметры**: сценарий может нести `params` — таблицу «ключ → значение» с ключами `проект.<ключ>` (раздел 1, «передача значений извне»); не названный параметр остаётся со значением по умолчанию.

## 12. Каталог встроенных функций

Имена функций каталога — русская форма; английские имена (`has`, `require`, `require_non_empty`, `record_text`, `without_key`, `first_where`, `fold`, `new_id` и др.) — в [таблице слов](alula-keywords.tsv), вид `catalog` (1а).

Все функции каталога — класс `pure`: вызываются везде, где допустимо выражение; исключение — стандартная внешняя функция `новый_ид` (последняя строка). Функции списка с лямбдой (`фильтр` … `свёртка`) вызываются методом своего первого аргумента — списка: `xs.фильтр(x => выр)` (3.1); в сигнатуре первый параметр `xs []T` — получатель метода (у каждого параметра сигнатуры — имя); вызов функции списка обычным вызовом — ошибка. Параметр-лямбда записан в сигнатуре функциональным типом `имя функция(T) -> R` (английское `name fn(T) -> R`, как D20 Новы): это запись документации — в языке функционального типа нет, лямбда стоит только аргументом функции списка (3.1). Диапазон — операторы `a..b` и `a..=b`, функции `диапазон` нет. Остальные внешние функции объявлены в файле машины (раздел 7), в каталог не входят.
