# Машина: Шаг агента

- machine: agent_step
- machine_version: alula-2.22
- format: 2.22

Это **иллюстрация**: машина «Шаг агента» целиком, записанная в формате «Алула», версия формата 2.22 ([state-machine-alula-spec.md](state-machine-alula-spec.md); он единственное определение языка записи). Файл нужен, чтобы человек мог открыть и увидеть настоящую машину: типы, данные, стороны, функции, все 37 строк переходов, концы с таблицей «конец → ответ», подключённый фрагмент «Пауза»; что приносит фрагмент (параметры, общие события ОБЩ 1–6, состояние ПАУЗА с событиями ПАУЗА 1–4), описано в разделе 9 спецификации.

**Статус.** Эквивалентность этой записи автомату по журналу не проверялась: интерпретатор «Шага агента» не гонялся, сценарии не сравнивались. **Первоисточник — эта запись на Алуле; прежние таблицы лежат в архиве и не обновляются.** Прежняя запись — таблицы состояний [archive/state-machine-agent-step-states.md](archive/state-machine-agent-step-states.md) и код автомата [archive/state-machine-agent-step-automaton.md](archive/state-machine-agent-step-automaton.md). Фрагмент «Пауза» — [archive/state-machine-pause-states.md](archive/state-machine-pause-states.md), коды журнала — [state-machine-journal.md](state-machine-journal.md), имена — [state-machine-glossary.md](state-machine-glossary.md).

**Как устроена запись.** Разделы идут в порядке раздела 1 формата. Номер `№` строки состояния равен метке `ИМЯ #n` в таблицах и в коде автомата (метка умолчания развилки — следующий номер; строки `иначе` записаны явно и равны умолчанию). Строки-ключи состояний — элементы списка (`- Сторона: …`), таблицы стоят на уровне блока; абзацы прозы вне таблиц и блоков кода — комментарии для читателя, разбор их пропускает. Текстовые значения (`ход`, `остановка`, решения) — слова кода автомата (латиница). Имена, которые выходят из машины (состояния, данные, поля входа, типы, их поля, формы и элементы, сигналы сторон и их поля, имя настройки вратаря), получают латинское JSON-имя автоматически (спецификация, раздел 1а, «JSON-имя»: словарь методики, затем транслитерация): `число_повторов` → `retry_count`, `ПОВТОР` → `Retry`, `разрешить` → `allow`; раздел `## Имена` (после `## Типы`) задаёт JSON-имя только там, где автоматическое имя неверно, — 2 строки: `расход` (данное и поле пяти форм) и имя настройки вратаря `исполнитель_повышенного_внимания`; скобок после имён в языке нет (версия 2.16); JSON-имена — те же, что имена английского образца, поэтому дерево `machine/2` у двух образцов одно с точностью до внутренних имён (константы, параметры, функции, имена сторон, привязки; сверка — `check-alula-samples.py`); данное контракта `остановка` в `## Имена` не пишется: его JSON-имя — слово таблицы слов (`stop_reason`). В таблицах «Запрос» поле, чьё выражение — то же имя, несёт `—` в столбце «выражение» (`| ход | — | сторона |`). Строк переходов 37: СТАРТ 1, ХОД_АГЕНТА 9, ПОВТОР 4, ПРОДОЛЖЕНИЕ 3, ПРОВЕРКА_ОТВЕТА 5, ПОЛИТИКА 4, РАЗРЕШЕНИЕ 2, БЮДЖЕТ 5, УЧЁТ 1, ИТОГ_ШАГА 3; строки ПАУЗА 1–4 и ОБЩ 1–6 приходят из фрагмента. Строк «Концов» 13: КОНЕЦ 1, ОШИБКА 1, ОСТАНОВЛЕНО 11.

Типы конверта (запрос, ответ, отказ) не объявляются: их собирает исполнитель; машина пишет только `Ответ(значение)` и `Отказ(код, текст)` (раздел «Концы»). Источник называет «дробное» неотрицательным; формат границу у вещественного не выражает, поэтому поля `?вещественное` — без границы, как в коде. Значения `ВидДействия` и `КодСбоя` (тексты в кавычках) — тексты журнала и провода; у `ВидВызывающего` и `ПроверкаОтвета` значений в источнике нет, в записи данных они идут JSON-именем элемента.

## Имена

| имя | JSON-имя |
|---|---|
| расход | transport_usage |
| исполнитель_повышенного_внимания | elevated_attention_executor |

Строки — только там, где автоматическое JSON-имя неверно (спецификация, раздел 1а, «Раздел `## Имена`»): `расход` — данное и поле пяти форм `ИтогХода` (словарь даёт этому имени два английских, `usage` и `transport_usage`, поэтому автоматическое имя — транслитерация `raskhod`); `исполнитель_повышенного_внимания` — имя настройки вратаря (в словаре его нет). Остальные имена получают JSON-имя автоматически, в том числе сигналы `разрешить` → `allow`, `отказать` → `deny`, `продолжить` → `continue`, `остановить` → `halt` (словарь, раздел 2.16).

## Функции

```
функция сумма_целых(а ?число, б ?число) -> ?число =>
  если есть(а) и есть(б) то { (а ?? 0) + (б ?? 0) } иначе { а ?? б }

функция сумма_дробных(а ?вещественное, б ?вещественное) -> ?вещественное =>
  если есть(а) и есть(б) то { (а ?? 0.0) + (б ?? 0.0) } иначе { а ?? б }

функция сложить_токены(а Токены, б Токены) -> Токены =>
  Токены { вход: сумма_целых(а.вход, б.вход), выход: сумма_целых(а.выход, б.выход),
           рассуждение: сумма_целых(а.рассуждение, б.рассуждение),
           кэш_чтение: сумма_целых(а.кэш_чтение, б.кэш_чтение), кэш_запись: сумма_целых(а.кэш_запись, б.кэш_запись) }

функция сложить_расход(прежний ?РасходТранспорта, новый РасходТранспорта) -> РасходТранспорта =>
  если есть(прежний)
  то { пусть п = обязательно(прежний);
        РасходТранспорта { модель: новый.модель, токены: сложить_токены(п.токены, новый.токены),
                           стоимость: сумма_дробных(п.стоимость, новый.стоимость),
                           занято_контекста: новый.занято_контекста, начало_запроса: новый.начало_запроса } }
  иначе { новый }

функция израсходовано_токенов(р ?РасходТранспорта) -> число =>
  если есть(р)
  то { пусть п = обязательно(р); (п.токены.вход ?? 0) + (п.токены.выход ?? 0) + (п.токены.рассуждение ?? 0) }
  иначе { 0 }

функция израсходовано_стоимости(р ?РасходТранспорта) -> вещественное =>
  если есть(р) то { обязательно(р).стоимость ?? 0.0 } иначе { 0.0 }

функция предел_токенов_исчерпан(з ЗапросАгента, р ?РасходТранспорта) -> булево =>
  есть(з.пределы.бюджет_токенов) и израсходовано_токенов(р) >= (з.пределы.бюджет_токенов ?? 0)

функция предел_стоимости_исчерпан(з ЗапросАгента, р ?РасходТранспорта) -> булево =>
  есть(з.пределы.бюджет_стоимости) и израсходовано_стоимости(р) >= (з.пределы.бюджет_стоимости ?? 0.0)

функция предел_ходов_исчерпан(з ЗапросАгента, ходов число>=0) -> булево =>
  ходов >= (з.пределы.предел_ходов ?? ПРЕДЕЛ_ХОДОВ)

функция интерактивный(вид_вызова ВидВызывающего) -> булево =>
  вид_вызова == ВидВызывающего.СессияЦикла или вид_вызова == ВидВызывающего.ХодЧата

функция требует_повышенного_внимания(вид_действия ВидДействия) -> булево =>
  выбор вид_действия {
    ВидДействия.Удаление | ВидДействия.Перенос | ВидДействия.Исполнение | ВидДействия.Сеть | ВидДействия.СменаРежима => истина
    иначе => ложь
  }

функция решение_по_политике(вид_действия ВидДействия, вид_вызова ВидВызывающего) -> "allow" | "deny" | "ask" {
  пусть по_таблице = если требует_повышенного_внимания(вид_действия) то { "ask" } иначе { ПОЛИТИКА_РАЗРЕШЕНИЙ[вид_действия] };

функция пауза_повтора(п число>=0) -> число =>

  если есть(срок) то { (срок ?? 0) + добавка } иначе { 0 }
}

функция собрать_использование(з ЗапросАгента, ост строка, р ?РасходТранспорта, нач ?число, обн число) -> Использование {
  пусть результат_шага = если ост == "" то { "reply" } иначе { ост };

    токены: (если есть(р) то { обязательно(р).токены }

    стоимость: (если есть(р) то { обязательно(р).стоимость } иначе { пусто }),
    создано: нач ?? обн, обновлено: обн,
```

## Примитивы

| имя | параметры | результат | класс | читает | пишет |
|---|---|---|---|---|---|
| time_now | — | число | reading | — | — |
| reply_validation | — | ПроверкаОтвета | reading | текст_ответа, артефакт_ответа, запрос_агента; объекты: файлы сессии | служебная запись «замечания формы» (читает ход «fix») |
| close_agent_turn | — | — | irreversible | — | — |

`time_now` — миллисекунды эпохи. `reply_validation` измеряет исполнитель перед развилкой ПРОВЕРКА_ОТВЕТА: форма ответа верна, нарушена или ответ пуст; замечания формы остаются у исполнителя и в данные не входят. `close_agent_turn` — транспорту сообщается об отмене открытого хода, в том числе удержанного до решения о разрешении; выполняется последним этапом фиксации, повторяем без вреда.
