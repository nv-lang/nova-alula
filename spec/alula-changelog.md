# Журнал изменений спецификации Алулы

Назначение: здесь собраны история правок спецификации [spec/alula-spec.md](alula-spec.md) (что изменилось в каждой версии, номера правок `AL-NN` и прежних меток), открытые вопросы и кандидаты, трассировка к правилам методики. Журнал ведётся только на добавление; метки правок живут здесь; правила языка — в [spec/alula-spec.md](alula-spec.md), в журнал они не входят. Тексты ниже перенесены из спецификации версии 2.22 дословно (разделы 0, 14 и 13 с прежними номерами; ссылки «раздел N» ведут в спецификацию, если не сказано иное). Английская версия: [spec/alula-changelog.en.md](alula-changelog.en.md).

## 0. Что изменилось

Метки изменений: префикс AL- (Alula); до 2.17 метки писались как Я-NN, число то же (слово владельца, 2026-10-22: «AL- — ОК»).

**Против версии 2.23.** Метки версии 2.24 — **AL-123, AL-128…AL-132**: выпуск по решениям владельца методики, 2026-10-25 (чат методики) — внешняя функция объявляется в файле машины (раздел `## Внешние функции` вместо `## Примитивы`), вызов без `вызвать`, сверка с реестром хозяина при загрузке, именованный хвост параметров, контракт хозяина (`bind_pure`, `bind_volatile`, `bind_acting`), три функции разбора по роли, приоритеты операторов приведены к Нове, `непустое` → `обязательно_непустое`. Формат меняется 2.23 → 2.24; дерево `machine/2` меняет только список `primitives` (раздел 6), имя формата и хеш словаря `60383c370415` те же; хеш образца файла функций (раздел 8) пересчитывается при публикации версии 2.24 (`ebb7658048b2` и `a9af85407c2b` — значения версии 2.23); образцы машин переносит на 2.24 владелец пакета скриптом. Слова владельца методики, 2026-10-25 (чат методики): «ОК» (внешние функции в файле, сверка при загрузке), «bind_* по одной функции — обязательно» (AL-130), «по рекомендации» (остальные решения: хвост, три функции по роли, `обязательно_непустое`), «да» (AL-132: приоритеты по Нове).

| AL-130 | **контракт хозяина**: хозяин подключает реализации внешних функций по одной (`bind_pure`, `bind_volatile`, `bind_acting`), при загрузке каждая объявленная функция привязана; класс различается типом среды (чистой среда не передаётся, изменчивой — без записи, действующей — с записью, это проверяет компилятор); честная запись, что не доказано типами (вывод, файлы, часы и сеть мимо среды, захват внешнего изменяемого состояния — это покрывают страж импортов, `--strict-effects` частично и тест-хост); контракт относится к хозяину, а не к файлу машины; слова владельца методики, 2026-10-25 (чат методики): «bind_* по одной функции — обязательно» | 7а |

| AL-132 | **приоритеты операторов приведены к Нове (D49)** (до 2.24 порядок был иной: `??` ниже `и`/`или`, `не` слабее сравнений): унарный `-` и `не` — сильный префикс; затем `* / %`, `+ -`, `??` (правоассоциативен, выше сравнений), `< <= > >=`, `== !=`, `и`, `или`, `..` и `..=`; `и`, `или`, `+ -`, `* / %` левоассоциативны, сравнения и равенства не цепляются; ошибки проверки с просьбой поставить скобки: любое сочетание двух операторов сравнения или равенства без скобок (`a < b < c`, `a == b != c`, `a == b < c`), `не` над сравнением без скобок (`не a == b`); смесь `??` со сравнением, `и`, `или` допустима, записывать со скобками — рекомендация; слова владельца методики, 2026-10-25 (чат методики): «да» | 3.1, 10 |

**Против версии 2.22.** Метки версии 2.23 — **AL-115…AL-122**: выпуск по решениям владельца методики, 2026-10-25 (чат методики) — код журнала записывается строкой, у внешних функций три класса (`pure`, `изменчивая`, `действующая`), порядок обхода словаря равен порядку записи, `длина` без строки, именованные аргументы только у журнальных форм, запись об отступлении от правила 13 (очередь исходящих не реализована), столбец `пишет`: `строки` → `действия`. Формат меняется 2.22 → 2.23; дерево `machine/2` не меняется (раздел 6); хеш словаря `60383c370415` тот же (словарь методики версии 11); хеш образца файла функций (раздел 8) пересчитан при публикации версии 2.23 — `ebb7658048b2` (русский образец) и `a9af85407c2b` (английский): в образце изменилась только строка `format:`; образцы машин перенесены владельцем пакета скриптом. Слова владельца методики, 2026-10-25 (чат методики): «принимаю три класса: чистая, изменчивая, действующая» (AL-116) и «по рекомендации» (остальные решения; кандидаты, записанные в «Открытое» с метками AL-123…AL-127).

## 14. Открытое

- **Эквивалентность по журналу подтверждена частично.** Версия 2.2 реализована интерпретатором; равенство с автоматом по журналу подтверждено на 39 сценариях одной небольшой машины (машина чата); выразимость «Шага агента» и «Совещания» проверена пилотами, прогон их сценариев на автомате и на описании не делался; не реализованы вложенные машины, `Правит`, профиль стороны, `Предел запросов`, `Возвратов формы`, `передать`. Запись дробного (`0.0`, `2.0`, `0.42`, `1e-7`) формат определил, а код её не определяет: совпадение с исполнителем кода проверяется сценарием (ША11).
- **Расхождения источников пилота «Совещание»:** ИС2 — исправлено в источнике: АННУЛ переносит объекты захода в архив и очищает находки, ответы свидетеля и свод аннулированного захода (`без_ключа`), как первоисточник («АННУЛ», «При входе») и код (`Void`); прежний текст пункта («в данных остаются») устарел и заменён (AL-36); ИС6 — у функций `merge_unique`, `not_included_in`, `has_critical`, `desirable*`, `critical_and_significant_not_repeated`, `has_reviewer_questions`, `reviewer_questions`, `all_lens_findings`, `lenses_without_critical`, `build_summary`, `remove_unsound`, `proposal_changed_since_attempt` (полный перечень по классам — раздел 7) в коде только сигнатуры: по правилу раздела 7 они записываются примитивами хозяина с классом по сигнатуре и описанием по таблицам первоисточника, функциями на языке станут, когда тело появится в источнике (что считать «линзой» при отброшенной линзе, четыре признака несостоятельного мнения, источник не говорит); ИС8 — запретные идентификаторы линз: инвариант источника называет русские «свидетель», «автор», «вратарь», «человек», а код различает стороны латинскими `witness`, `author`, `gatekeeper`, `enhanced`; ИС9, ИС10 — журнал причины сбоя пишет `"${reason}"` вместо слова кода сбоя, текст отказа ОШИБКИ из `JournalEvent` не определён; ключи `проект.<ключ>` параметров в источниках не названы.
- **Определения, которые не код.** Тела изменчивых функций (`предложение_менялось_с_начала_попытки`, `контекст_роли`, `разобрать_ответ_агента`); четыре признака несостоятельного мнения в `убрать_несостоятельные`; K и P в `собрать_свод`; тексты ворот. Смысл `право_записи` — только текст.
- **Журнал.** Коды `input_rejected`, `machine_data`, `machine_error`, `unclosed_finding`, `meeting_decision`, `open_finding` определены форматом ([state-machine-journal.md](https://github.com/unitcraft/ai-dev-methodology/blob/main/state-machines/state-machine-journal.md)), но автоматы пока пишут часть этих событий примитивами без тела (`journal_machine_data`, `journal_findings`, `journal_decision`) и ошибки машины кодом не помечают: сверка кода с таблицей их не видит.
